# Family Calendar Bot 📅

Telegram бот для управления семейным календарем на базе Spring Boot 3.5.3 и PostgreSQL. Позволяет членам семьи планировать события, получать уведомления и просматривать расписание через удобный интерфейс Telegram.

## 🎯 Возможности

### Основные функции

- 📅 **Создание событий** - добавляйте события с датой, временем и описанием через интерактивный календарь
- 👀 **Просмотр расписания** - смотрите все предстоящие события семьи на 7 дней вперед
- ✏️ **Управление событиями** - редактируйте и удаляйте свои события
- 🔄 **Умное редактирование** - при изменении события бот обновляет существующее сообщение вместо отправки нового, сохраняя чат чистым
- 🔔 **Умные уведомления** - настраиваемые напоминания (утром, вечером, за час, за 10 минут или кастомное время)
- 👥 **Многопользовательский режим** - поддержка нескольких семей с изолированными календарями
- 🔐 **Безопасность** - авторизация по Telegram ID, доступ только для зарегистрированных пользователей
- 💬 **Информативные сообщения** - понятные уведомления для неавторизованных пользователей с инструкциями по получению доступа
- ⚡ **Webhook интеграция** - мгновенная обработка команд в реальном времени
- 🐳 **Docker Ready** - простое развертывание с помощью Docker Compose

### Расширенные функции

- 🔒 **Персональные события** - создавайте события, видимые только вам
- 👨‍👩‍👧‍👦 **Семейные события** - события, видимые всем членам семьи
- ⏰ **Временные интервалы** - указывайте время начала и окончания события
- 🔁 **Повторяющиеся события** - настройка ежедневных, еженедельных и ежемесячных повторений
- 📎 **Вложения** - прикрепляйте файлы, документы и изображения к событиям (до 20 МБ)
  - 🔄 **Умное редактирование сообщений** - при всех операциях с вложениями (просмотр списка, добавление, удаление) бот обновляет существующее сообщение вместо создания новых, сохраняя чат чистым и организованным
  - 💾 **Сохранение контекста** - система запоминает ID сообщения между операциями, обеспечивая плавный пользовательский опыт
  - 📝 **Автоматический fallback** - если редактирование невозможно (сообщение удалено пользователем или старше 48 часов), бот автоматически переключается на отправку нового сообщения
  - ✨ **Бесшовная навигация** - переход между списком вложений и карточкой события происходит через редактирование одного сообщения
- 💬 **Комментарии** - обсуждайте события с членами семьи
- ✅ **Чек-листы** - создавайте списки задач для событий
- 🗑️ **Корзина** - восстанавливайте удаленные события в течение 30 дней
- 🔍 **Поиск** - находите события по названию или описанию
- 🔎 **Фильтрация** - фильтруйте события по типу (все/семейные/персональные/предстоящие)
- 📊 **Статистика** - просматривайте статистику событий за месяц
- 📝 **История изменений** - отслеживайте все изменения событий
- ⏱️ **Автозавершение** - события автоматически завершаются после истечения времени
- 📅 **Интерактивный календарь** - визуальный выбор даты с индикаторами событий
- 🕐 **Выбор времени** - удобный выбор часов и минут через inline-кнопки
- ⚡ **Быстрое создание из текста** - создавайте события из текстовых сообщений в свободной форме
- 💡 **Контекстные подсказки** - умные предложения на основе названия события
- 📤 **Автоматическое прикрепление файлов** - отправляйте файлы в процессе создания события

## 🚀 Быстрый старт с Docker Compose

### Предварительные требования

- Docker 20.10+ и Docker Compose 2.0+
- Telegram бот токен (получите от [@BotFather](https://t.me/BotFather))
- Публичный HTTPS URL для webhook (можно использовать ngrok для разработки)

### Шаги запуска

1. **Клонируйте репозиторий**
   ```bash
   git clone <repository-url>
   cd family-calendar-bot
   ```

2. **Создайте файл .env из примера**
   ```bash
   cp .env.example .env
   ```

3. **Настройте переменные окружения в .env**
   ```env
   # База данных
   DB_PASSWORD=your_secure_password_here
   
   # Telegram Bot
   TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz
   TELEGRAM_BOT_USERNAME=YourFamilyCalendarBot
   
   # Webhook URL (должен быть доступен из интернета по HTTPS)
   TELEGRAM_BOT_WEBHOOK_URL=https://your-domain.com/webhook
   ```

4. **Запустите приложение**
   ```bash
   # Unix (Linux/macOS)
   scripts/unix/start.sh
   
   # Windows
   scripts\windows\start.bat
   
   # Или напрямую через Docker Compose
   docker-compose up -d
   ```

5. **Проверьте статус и логи**
   ```bash
   # Статус контейнеров
   docker-compose ps
   
   # Логи приложения (Unix)
   scripts/unix/logs.sh
   
   # Логи приложения (Windows)
   scripts\windows\logs.bat
   
   # Или напрямую
   docker-compose logs -f app
   ```

6. **Остановите приложение**
   ```bash
   # Unix (Linux/macOS)
   scripts/unix/stop.sh
   
   # Windows
   scripts\windows\stop.bat
   
   # Или напрямую через Docker Compose
   docker-compose down
   ```

### Управляющие скрипты

Проект включает удобные скрипты для управления:

**Unix (Linux/macOS):**
- `scripts/unix/start.sh` - запуск приложения
- `scripts/unix/stop.sh` - остановка приложения
- `scripts/unix/logs.sh` - просмотр логов
- `scripts/unix/clean.sh` - полная очистка (удаление volumes с данными)

**Windows:**
- `scripts\windows\start.bat` - запуск приложения
- `scripts\windows\stop.bat` - остановка приложения
- `scripts\windows\logs.bat` - просмотр логов
- `scripts\windows\clean.bat` - полная очистка (удаление volumes с данными)

### 🔧 Локальная разработка с ngrok

Для локальной разработки с webhook используйте [ngrok](https://ngrok.com/) для создания публичного HTTPS туннеля:

1. **Установите ngrok**
   ```bash
   # macOS (Homebrew)
   brew install ngrok/ngrok/ngrok
   
   # Windows (Chocolatey)
   choco install ngrok
   
   # Linux или скачайте с https://ngrok.com/download
   ```

2. **Зарегистрируйтесь на ngrok.com и получите authtoken**
   ```bash
   ngrok config add-authtoken YOUR_AUTH_TOKEN
   ```

3. **Запустите ngrok туннель**
   ```bash
   ngrok http 8080
   ```
   
   Вы увидите вывод вроде:
   ```
   Forwarding  https://abc123def456.ngrok.io -> http://localhost:8080
   ```

4. **Скопируйте HTTPS URL** (например, `https://abc123def456.ngrok.io`)

5. **Обновите .env файл с ngrok URL**
   ```env
   TELEGRAM_BOT_WEBHOOK_URL=https://abc123def456.ngrok.io/webhook
   ```

6. **Перезапустите приложение**
   ```bash
   docker-compose restart app
   ```

7. **Проверьте регистрацию webhook в логах**
   ```bash
   docker-compose logs app | grep -i webhook
   ```

**Важно:** При каждом перезапуске ngrok генерирует новый URL (в бесплатной версии), поэтому нужно обновлять `.env` и перезапускать приложение.

## 🔄 Умное редактирование сообщений с вложениями

Одна из ключевых особенностей бота - интеллектуальное управление сообщениями при работе с вложениями. Вместо создания множества новых сообщений в чате, бот обновляет существующее сообщение, обеспечивая чистоту и организованность диалога.

### Как это работает

#### 1. Сохранение контекста сообщения

Когда вы открываете список вложений события, система автоматически:
- Сохраняет ID текущего сообщения в состоянии диалога
- Запоминает ID события и чата для последующих операций
- Отслеживает время создания контекста (для проверки актуальности)

```
Вы: [Нажимаете "Вложения" в карточке события]
Система: 
  ✓ Сохранен messageId: 12345
  ✓ Сохранен eventId: 67890
  ✓ Сохранен chatId: 111222333
  ✓ Время создания: 2026-01-21 15:30:00
```

#### 2. Редактирование при операциях

Все последующие операции с вложениями используют сохраненный messageId:

**Добавление файла:**
```
Вы: [Нажимаете "Добавить файл"]
Бот: Отправьте файл для прикрепления...

Вы: [Отправляете файл document.pdf]
Система:
  ✓ Файл сохранен в БД
  ✓ Получен сохраненный messageId: 12345
  ✓ Попытка редактирования сообщения 12345
  ✓ Редактирование успешно!
  
Бот: 📎 Вложения события              ← То же сообщение обновлено!
     
     📄 document.pdf
     📊 Размер: 1.2 МБ
     📅 Загружено: 21.01.2026 15:35
```

**Удаление файла:**
```
Вы: [Нажимаете 🗑️ рядом с файлом]
Система:
  ✓ Получен messageId: 12345
  ✓ Редактирование сообщения для подтверждения
  
Бот: ⚠️ Подтверждение удаления        ← Сообщение обновлено!
     
     Удалить файл document.pdf?
     [✅ Да] [❌ Отмена]

Вы: [Нажимаете "Да"]
Система:
  ✓ Файл удален из БД
  ✓ Редактирование сообщения с обновленным списком
  
Бот: 📎 Вложения события              ← Снова обновлено!
     
     У этого события пока нет вложений
     [➕ Добавить файл] [🔙 Назад]
```

#### 3. Автоматический Fallback механизм

Система автоматически переключается на отправку нового сообщения, если редактирование невозможно:

**Случай 1: Сообщение удалено пользователем**
```
Вы: [Удаляете сообщение со списком вложений]
Вы: [Пытаетесь добавить новый файл]

Система:
  ✗ Попытка редактирования messageId: 12345
  ✗ Ошибка: Message not found (400)
  ℹ️ Переключение на fallback режим
  ✓ Отправка нового сообщения
  ✓ Сохранен новый messageId: 12346

Бот: 📎 Вложения события              ← Новое сообщение!
     
     📄 new_file.pdf
     📊 Размер: 850 КБ
     📅 Загружено: 21.01.2026 16:00
```

**Случай 2: Сообщение старше 48 часов**
```
Система:
  ℹ️ Проверка возраста контекста
  ℹ️ Контекст создан: 19.01.2026 10:00
  ℹ️ Текущее время: 21.01.2026 16:00
  ℹ️ Прошло: 54 часа (> 47 часов)
  ✗ Контекст истек
  ℹ️ Переключение на fallback режим
  ✓ Отправка нового сообщения
  ✓ Сохранен новый messageId: 12347
```

**Случай 3: Ошибка Telegram API**
```
Система:
  ✗ Попытка редактирования messageId: 12345
  ✗ Ошибка: Message can't be edited (400)
  ℹ️ Причина: Сообщение слишком старое
  ℹ️ Переключение на fallback режим
  ✓ Отправка нового сообщения
```

#### 4. Очистка контекста

Контекст автоматически очищается при:
- Возврате к карточке события (кнопка "Назад")
- Переходе к другому событию
- Истечении времени жизни (> 47 часов)

```
Вы: [Нажимаете "Назад к событию"]
Система:
  ✓ Очистка attachment message context
  ✓ Редактирование сообщения обратно к карточке события
  
Бот: 📅 25.12.2025 в 18:00            ← То же сообщение!
     📝 Новогодний ужин
     📄 Описание: Семейный праздник
     
     [📎 Вложения] [✏️ Редактировать] [🗑️ Удалить]
```

### Преимущества умного редактирования

✅ **Чистота чата** - нет множества устаревших сообщений  
✅ **Плавный UX** - все операции происходят в одном месте  
✅ **Сохранение контекста** - пользователь не теряет ориентацию  
✅ **Надежность** - автоматический fallback при проблемах  
✅ **Производительность** - меньше сообщений = меньше нагрузка на API  

### Технические детали

**Хранение контекста:**
- Контекст сохраняется в таблице `conversation_states` в PostgreSQL
- Поля: `attachment_event_id`, `attachment_chat_id`, `attachment_message_id`, `attachment_context_created_at`
- Изоляция между пользователями - каждый пользователь имеет свой контекст

**Проверка актуальности:**
- Контекст считается актуальным, если создан менее 47 часов назад
- Запас в 1 час до лимита Telegram API (48 часов)
- Автоматическая проверка при каждой операции

**Логирование:**
- Все операции редактирования логируются на уровне DEBUG/INFO
- Ошибки редактирования логируются на уровне WARN
- Переключения на fallback логируются с указанием причины

### Ключевые принципы

- **Webhook вместо Long Polling** - мгновенная обработка команд
- **Асинхронная обработка** - UpdateProcessor обрабатывает команды асинхронно
- **Dependency Injection** - Spring управляет всеми зависимостями
- **Разделение ответственности** - каждый слой имеет четкую роль
- **Scheduled Tasks** - автоматическая проверка и отправка уведомлений
- **Транзакционность** - JPA обеспечивает ACID гарантии

### Форматирование сообщений для Telegram (MarkdownV2)

При разработке новых функций бота важно правильно форматировать сообщения для Telegram. Telegram использует формат MarkdownV2, который требует экранирования специальных символов.

#### Специальные символы, требующие экранирования

```
_ * [ ] ( ) ~ ` > # + - = | { } . !
```

#### Использование MarkdownFormatter

Всегда используйте класс `MarkdownFormatter` для форматирования сообщений:

```java
import ru.golubyatnikov.family.calendar.bot.util.MarkdownFormatter;

// ✅ ПРАВИЛЬНО - автоматическое экранирование
String message = MarkdownFormatter.formatMessage(
    "✅ Дата выбрана: %s\n\nТеперь выберите час:", 
    formattedDate
);

// ❌ НЕПРАВИЛЬНО - специальные символы не экранированы
String message = String.format("✅ Дата выбрана: %s", formattedDate);
```

#### Примеры использования

```java
// Экранирование отдельной строки
String escaped = MarkdownFormatter.escape("Цена: 100$");

// Форматирование с несколькими переменными
String message = MarkdownFormatter.formatMessage(
    "Событие: %s\nДата: %s\nВремя: %s",
    eventTitle, eventDate, eventTime
);

// Стилизация текста
String bold = MarkdownFormatter.bold("Важное сообщение!");
String italic = MarkdownFormatter.italic("Примечание");
String code = MarkdownFormatter.code("/add_event");
```

#### Частые ошибки

1. **Использование String.format() напрямую** - специальные символы не экранируются
2. **Забывание экранировать статический текст** - точки, восклицательные знаки и другие символы в шаблоне
3. **Двойное экранирование** - применение escape() к уже экранированным строкам

Подробнее см. раздел "Работа с MarkdownV2 форматированием" в [SETUP.md](SETUP.md).

### Testcontainers

Проект использует Testcontainers для интеграционных тестов с реальной PostgreSQL:

```java
@SpringBootTest
@Testcontainers
class EventServiceIntegrationTest {
    
    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>(
        "postgres:18.1-alpine")
        .withDatabaseName("testdb")
        .withUsername("test")
        .withPassword("test");
    
    @DynamicPropertySource
    static void configureProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
    }
    
    @Test
    void shouldCreateAndRetrieveEvent() {
        // Тест с реальной БД
    }
}
```

### Запуск тестов

```bash
# Все тесты
mvn test

# С подробным выводом
mvn test -X

# Конкретный класс
mvn test -Dtest=EventServiceTest

# Конкретный метод
mvn test -Dtest=EventServiceTest#shouldCreateEvent

mvn package -DskipTests
```

## ❗ Troubleshooting

### Приложение не может подключиться к базе данных

**Симптомы:**
```
Connection refused: connect
Could not connect to PostgreSQL
```

**Решения:**
1. Проверьте, что PostgreSQL контейнер запущен:
   ```bash
   docker-compose ps
   ```
2. Проверьте логи PostgreSQL:
   ```bash
   docker-compose logs postgres
   ```
3. Убедитесь, что healthcheck проходит успешно:
   ```bash
   docker-compose ps postgres
   # Должно быть "healthy" в статусе
   ```
4. Проверьте переменные окружения в `.env`
5. Попробуйте пересоздать контейнеры:
   ```bash
   docker-compose down
   docker-compose up -d
   ```

### Webhook не регистрируется

**Симптомы:**
```
Failed to register webhook
Webhook registration failed
```

**Решения:**
1. Проверьте, что `TELEGRAM_BOT_WEBHOOK_URL` доступен из интернета
2. Убедитесь, что URL использует HTTPS (не HTTP)
3. Проверьте токен бота в `.env`
4. Проверьте логи приложения:
   ```bash
   docker-compose logs app | grep -i webhook
   ```
5. Для локальной разработки убедитесь, что ngrok запущен:
   ```bash
   ngrok http 8080
   ```
6. Проверьте текущий webhook через Telegram API:
   ```bash
   curl https://api.telegram.org/bot<YOUR_TOKEN>/getWebhookInfo
   ```

### Миграции Flyway не применяются

**Симптомы:**
```
Flyway migration failed
Schema validation failed
```

**Решения:**
1. Проверьте логи Flyway в логах приложения:
   ```bash
   docker-compose logs app | grep -i flyway
   ```
2. Убедитесь, что база данных создана и доступна
3. Проверьте права пользователя БД:
   ```bash
   docker-compose exec postgres psql -U botuser -d family_calendar -c "\du"
   ```
4. Если нужно сбросить миграции (ВНИМАНИЕ: удалит все данные):
   ```bash
   docker-compose down -v
   docker-compose up -d
   ```
5. Проверьте таблицу истории миграций:
   ```sql
   SELECT * FROM flyway_schema_history;
   ```

### Бот не отвечает на команды

**Симптомы:**
- Бот онлайн, но не отвечает на `/start` и другие команды

**Решения:**
1. Проверьте, что webhook зарегистрирован:
   ```bash
   curl https://api.telegram.org/bot<YOUR_TOKEN>/getWebhookInfo
   ```
2. Проверьте логи приложения на наличие ошибок:
   ```bash
   docker-compose logs -f app
   ```
3. Убедитесь, что пользователь зарегистрирован в БД:
   ```sql
   SELECT * FROM users WHERE telegram_id = YOUR_TELEGRAM_ID;
   ```
4. Проверьте, что UpdateProcessor обрабатывает команды:
   ```bash
   docker-compose logs app | grep -i "received update"
   ```

### Уведомления не отправляются

**Симптомы:**
- События создаются, но уведомления не приходят за 1 час

**Решения:**
1. Проверьте, что NotificationService запущен:
   ```bash
   docker-compose logs app | grep -i notification
   ```
2. Проверьте события в БД:
   ```sql
   SELECT * FROM events WHERE notified = false AND event_date >= CURRENT_DATE;
   ```
3. Убедитесь, что scheduled tasks работают:
   ```bash
   docker-compose logs app | grep -i "scheduled"
   ```
4. Проверьте временную зону контейнера:
   ```bash
   docker-compose exec app date
   ```

### Ошибки при сборке Docker образа

**Симптомы:**
```
ERROR: failed to solve
Build failed
```

**Решения:**
1. Очистите Docker кэш:
   ```bash
   docker system prune -a
   ```
2. Пересоберите без кэша:
   ```bash
   docker-compose build --no-cache
   ```
3. Проверьте, что Maven сборка проходит локально:
   ```bash
   mvn clean package
   ```
4. Убедитесь, что JAR файл создан:
   ```bash
   ls -lh target/*.jar
   ```

### Высокое использование памяти

**Решения:**
1. Ограничьте память для JVM в Dockerfile:
   ```dockerfile
   ENTRYPOINT ["java", "-Xmx512m", "-Xms256m", "-jar", "app.jar"]
   ```
2. Настройте limits в docker-compose.yml:
   ```yaml
   services:
     app:
       deploy:
         resources:
           limits:
             memory: 1G
   ```

### Проблемы с правами доступа к файлам

**Симптомы:**
```
Permission denied
Cannot write to directory
```

**Решения:**
1. На Linux/Mac проверьте права на скрипты:
   ```bash
   chmod +x start.sh stop.sh logs.sh clean.sh
   ```
2. Проверьте владельца файлов:
   ```bash
   ls -la
   ```
3. Если нужно, измените владельца:
   ```bash
   sudo chown -R $USER:$USER .
   ```
