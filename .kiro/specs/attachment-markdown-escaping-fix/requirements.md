# Требования: Исправление экранирования Markdown в сообщениях о вложениях

## 1. Обзор

### 1.1 Описание проблемы
При отображении списка вложений события возникает ошибка парсинга MarkdownV2 в Telegram API. Ошибка происходит из-за того, что специальные символы (точки) в размере файла и дате загрузки не экранируются должным образом.

**Пример ошибки из лога:**
```
Bad Request (400): Ошибка парсинга MarkdownV2. 
textPreview='📎 *Вложения события*🖼️ *photo\_1769005286492\.jpg*📊 Размер: 52.05 КБ📅 Загружено: 21.01.2026 14:21'
response=Bad Request: can't parse entities: Character '.' is reserved and must be escaped with the preceding '\'
```

### 1.2 Текущая реализация
В классе `AttachmentCallbackHandler`:

**Метод `handleAttachmentList()`:**
- Имя файла экранируется через локальный метод `escapeMarkdown()`
- Размер файла (например, "52.05 КБ") добавляется БЕЗ экранирования
- Дата загрузки (например, "21.01.2026 14:21") добавляется БЕЗ экранирования

**Метод `handleViewFile()`:**
- Caption формируется из имени файла БЕЗ экранирования
- Caption отправляется через `TelegramMessageService.sendFile()` с `parseMode="MarkdownV2"`

### 1.3 Корневая причина
Точки в числах (размер файла), датах и именах файлов являются зарезервированными символами в MarkdownV2 и должны экранироваться обратным слешем. При отправке файлов через Telegram API caption также требует экранирования, если используется MarkdownV2.

## 2. Функциональные требования

### 2.1 Экранирование размера файла
**Приоритет:** Критический

**Описание:** Размер файла должен экранироваться перед добавлением в сообщение.

**Критерии приемки:**
- Метод `formatFileSize()` должен возвращать экранированную строку
- Все точки в размере файла должны быть экранированы (например, "52\\.05 КБ")
- Экранирование должно применяться как для КБ, так и для МБ

### 2.2 Экранирование даты загрузки
**Приоритет:** Критический

**Описание:** Дата загрузки должна экранироваться перед добавлением в сообщение.

**Критерии приемки:**
- Дата в формате "dd.MM.yyyy HH:mm" должна быть экранирована
- Все точки в дате должны быть экранированы (например, "21\\.01\\.2026 14:21")
- Двоеточие в времени должно быть экранировано (например, "14\\:21")

### 2.3 Использование централизованного метода экранирования
**Приоритет:** Высокий

**Описание:** Вместо дублирования логики экранирования следует использовать существующий метод `MarkdownFormatter.escapeMarkdownV2()`.

**Критерии приемки:**
- Локальный метод `escapeMarkdown()` должен быть удален
- Все вызовы экранирования должны использовать `MarkdownFormatter.escapeMarkdownV2()`
- Код должен быть более поддерживаемым и единообразным

### 2.4 Экранирование caption при отправке файлов
**Приоритет:** Критический

**Описание:** Caption при отправке файлов через `sendFile()` должен экранироваться перед отправкой.

**Критерии приемки:**
- Caption в методе `handleViewFile()` должен экранироваться через `MarkdownFormatter.escapeMarkdownV2()`
- Все специальные символы в имени файла должны быть экранированы
- Файлы должны успешно отправляться без ошибок парсинга MarkdownV2

## 3. Нефункциональные требования

### 3.1 Совместимость
- Исправление не должно нарушать существующую функциональность отображения вложений
- Все эмодзи должны корректно отображаться

### 3.2 Производительность
- Экранирование не должно значительно влиять на производительность
- Метод должен работать эффективно для списков с множеством вложений

### 3.3 Поддерживаемость
- Код должен быть понятным и легко поддерживаемым
- Использование централизованного метода экранирования упрощает будущие изменения

## 4. Ограничения и предположения

### 4.1 Ограничения
- Изменения затрагивают только класс `AttachmentCallbackHandler`
- Метод `MarkdownFormatter.escapeMarkdownV2()` уже существует и корректно работает

### 4.2 Предположения
- Формат даты остается неизменным ("dd.MM.yyyy HH:mm")
- Формат размера файла остается неизменным (КБ/МБ с двумя знаками после запятой)

## 5. Критерии успеха

### 5.1 Функциональные критерии
- ✅ Сообщения о вложениях успешно отправляются без ошибок парсинга MarkdownV2
- ✅ Все специальные символы корректно экранированы
- ✅ Информация о вложениях отображается корректно в Telegram

### 5.2 Технические критерии
- ✅ Код использует централизованный метод экранирования
- ✅ Дублирование кода устранено
- ✅ Все существующие тесты проходят успешно

## 6. Зависимости

### 6.1 Внутренние зависимости
- `MarkdownFormatter.escapeMarkdownV2()` - существующий метод для экранирования
- `AttachmentCallbackHandler` - класс, требующий изменений

### 6.2 Внешние зависимости
- Telegram Bot API - требует корректного форматирования MarkdownV2

## 7. Риски

### 7.1 Технические риски
- **Риск:** Неполное экранирование может привести к новым ошибкам
- **Митигация:** Тщательное тестирование с различными вариантами имен файлов и размеров

### 7.2 Операционные риски
- **Риск:** Изменения могут повлиять на отображение существующих вложений
- **Митигация:** Тестирование на реальных данных перед развертыванием
