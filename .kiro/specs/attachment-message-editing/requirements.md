# Документ требований: Редактирование сообщений с вложениями

## Введение

Данный документ описывает требования к функциональности редактирования сообщений при работе с вложениями в Telegram боте семейного календаря. Текущая реализация создает новые сообщения в чате при каждом действии с вложениями, что загромождает чат. Требуется изменить поведение так, чтобы все операции с вложениями происходили через редактирование одного сообщения.

## Глоссарий

- **System** - система обработки вложений в Telegram боте
- **Attachment_Message** - сообщение в Telegram, содержащее информацию о вложениях события
- **Message_Id** - уникальный идентификатор сообщения в Telegram
- **Callback_Query** - запрос от inline кнопки в Telegram
- **Conversation_State** - состояние диалога пользователя с ботом
- **Edit_Operation** - операция редактирования существующего сообщения
- **Fallback_Mode** - режим отправки нового сообщения при невозможности редактирования

## Требования

### Требование 1: Сохранение идентификатора сообщения

**User Story:** Как разработчик, я хочу сохранять messageId при отображении списка вложений, чтобы система могла редактировать это сообщение при последующих операциях.

#### Acceptance Criteria

1. WHEN THE System SHALL отображает список вложений, THE System SHALL сохранить Message_Id в Conversation_State
2. WHEN пользователь выполняет действие с вложениями, THE System SHALL извлечь сохраненный Message_Id из Conversation_State
3. WHEN Message_Id отсутствует в Conversation_State, THE System SHALL использовать Fallback_Mode

### Требование 2: Редактирование при добавлении вложения

**User Story:** Как пользователь, я хочу чтобы после добавления вложения обновлялось существующее сообщение, а не создавалось новое, чтобы чат оставался чистым.

#### Acceptance Criteria

1. WHEN пользователь успешно добавляет вложение, THE System SHALL отредактировать Attachment_Message с обновленным списком вложений
2. WHEN редактирование невозможно, THE System SHALL отправить новое сообщение и сохранить новый Message_Id
3. WHEN список вложений обновляется, THE System SHALL обновить клавиатуру с актуальными кнопками

### Требование 3: Редактирование при удалении вложения

**User Story:** Как пользователь, я хочу чтобы после удаления вложения обновлялось существующее сообщение, а не создавалось новое, чтобы чат оставался чистым.

#### Acceptance Criteria

1. WHEN пользователь подтверждает удаление вложения, THE System SHALL отредактировать Attachment_Message с обновленным списком вложений
2. WHEN редактирование невозможно, THE System SHALL отправить новое сообщение и сохранить новый Message_Id
3. WHEN список вложений становится пустым, THE System SHALL отобразить сообщение "У этого события пока нет вложений"

### Требование 4: Редактирование при запросе подтверждения удаления

**User Story:** Как пользователь, я хочу чтобы запрос подтверждения удаления отображался в том же сообщении, а не создавал новое, чтобы интерфейс был последовательным.

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку удаления вложения, THE System SHALL отредактировать Attachment_Message с запросом подтверждения
2. WHEN пользователь отменяет удаление, THE System SHALL отредактировать Attachment_Message обратно к списку вложений
3. WHEN редактирование невозможно, THE System SHALL отправить новое сообщение

### Требование 5: Обработка ошибок редактирования

**User Story:** Как разработчик, я хочу корректно обрабатывать ситуации, когда редактирование невозможно, чтобы пользователь всегда получал актуальную информацию.

#### Acceptance Criteria

1. WHEN сообщение удалено пользователем, THE System SHALL отправить новое сообщение и сохранить новый Message_Id
2. WHEN сообщение слишком старое для редактирования, THE System SHALL отправить новое сообщение и сохранить новый Message_Id
3. WHEN возникает ошибка редактирования, THE System SHALL логировать детали ошибки
4. WHEN используется Fallback_Mode, THE System SHALL логировать причину переключения

### Требование 6: Управление состоянием диалога

**User Story:** Как разработчик, я хочу управлять состоянием диалога с сохранением messageId, чтобы обеспечить корректное редактирование сообщений.

#### Acceptance Criteria

1. THE Conversation_State SHALL хранить Message_Id для каждого пользователя
2. WHEN пользователь переходит к другому событию, THE System SHALL обновить сохраненный Message_Id
3. WHEN пользователь возвращается к карточке события, THE System SHALL очистить сохраненный Message_Id
4. WHEN сессия пользователя истекает, THE System SHALL очистить сохраненный Message_Id

### Требование 7: Редактирование при просмотре списка вложений

**User Story:** Как пользователь, я хочу чтобы при открытии списка вложений редактировалось существующее сообщение события, а не создавалось новое, чтобы сохранить контекст.

#### Acceptance Criteria

1. WHEN пользователь открывает список вложений из карточки события, THE System SHALL отредактировать сообщение события
2. WHEN пользователь возвращается к карточке события из списка вложений, THE System SHALL отредактировать то же сообщение
3. WHEN Message_Id доступен из Callback_Query, THE System SHALL использовать его для редактирования

### Требование 8: Обновление клавиатуры

**User Story:** Как пользователь, я хочу чтобы кнопки под сообщением всегда соответствовали текущему состоянию, чтобы интерфейс был понятным.

#### Acceptance Criteria

1. WHEN отображается список вложений, THE System SHALL показать кнопки для каждого вложения и кнопку "Добавить"
2. WHEN отображается запрос подтверждения удаления, THE System SHALL показать кнопки "Да, удалить" и "Отмена"
3. WHEN список вложений пуст, THE System SHALL показать только кнопку "Добавить" и "Назад"
4. WHEN пользователь не является создателем события, THE System SHALL скрыть кнопки "Добавить" и "Удалить"

### Требование 9: Сохранение контекста при добавлении файла

**User Story:** Как пользователь, я хочу чтобы после отправки файла система вернулась к редактированию того же сообщения, чтобы не терять контекст.

#### Acceptance Criteria

1. WHEN пользователь начинает добавление файла, THE System SHALL сохранить Message_Id в Conversation_State
2. WHEN пользователь отправляет файл, THE System SHALL использовать сохраненный Message_Id для редактирования
3. WHEN файл успешно добавлен, THE System SHALL отредактировать сообщение с обновленным списком

### Требование 10: Логирование операций редактирования

**User Story:** Как разработчик, я хочу детально логировать все операции редактирования, чтобы упростить диагностику проблем.

#### Acceptance Criteria

1. WHEN THE System SHALL выполняет Edit_Operation, THE System SHALL логировать chatId, messageId и тип операции
2. WHEN редактирование успешно, THE System SHALL логировать успех операции
3. WHEN редактирование не удается, THE System SHALL логировать причину ошибки и переключение на Fallback_Mode
4. WHEN используется сохраненный Message_Id, THE System SHALL логировать источник идентификатора
