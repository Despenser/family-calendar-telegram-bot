# Требования: Сохранение шапки "Мои события" при редактировании первого события

## Введение

При редактировании первого события в списке "Мои события" теряется шапка с заголовком "📋 Мои события" и информацией о количестве событий. Это происходит потому, что система не знает, что данное сообщение является первым в списке и должно содержать шапку.

## Глоссарий

- **Система** - Telegram-бот семейного календаря
- **Пользователь** - авторизованный пользователь бота
- **Событие** - запись в календаре с датой, временем и описанием
- **Список "Мои события"** - отображение всех событий пользователя, вызываемое командой /my_events
- **Шапка списка** - заголовок сообщения вида "📋 Мои события\nВсего событий: N"
- **Первое событие** - событие, которое отображается в одном сообщении с шапкой списка
- **MessageId** - идентификатор сообщения в Telegram, используемый для обновления сообщения
- **Контекст сообщения** - информация о том, является ли сообщение частью списка "Мои события"

## Требования

### Требование 1

**User Story:** Как пользователь, я хочу, чтобы при редактировании первого события в списке "Мои события" шапка списка сохранялась, чтобы я всегда видел общее количество событий.

#### Критерии приемки

1. WHEN пользователь редактирует первое событие в списке "Мои события" THEN система SHALL сохранить шапку "📋 Мои события\nВсего событий: N" в обновленном сообщении
2. WHEN система обновляет сообщение с первым событием THEN система SHALL объединить шапку с отформатированным событием перед отправкой
3. WHEN пользователь редактирует не первое событие в списке THEN система SHALL обновить только текст события без добавления шапки
4. WHEN система обновляет количество событий пользователя THEN система SHALL корректно обновить число N в шапке первого события

### Требование 2

**User Story:** Как система, я хочу знать, какие сообщения являются первыми в списке "Мои события", чтобы корректно обновлять их с шапкой.

#### Критерии приемки

1. WHEN система отправляет первое событие в списке "Мои события" THEN система SHALL сохранить в базе данных флаг, указывающий, что это сообщение содержит шапку списка
2. WHEN система обновляет событие THEN система SHALL проверить наличие флага шапки списка перед форматированием сообщения
3. WHEN пользователь удаляет первое событие из списка THEN система SHALL обновить флаг для следующего события, чтобы оно стало первым
4. WHEN пользователь создает новое событие с более ранней датой THEN система SHALL обновить флаги, чтобы новое событие стало первым в списке

### Требование 3

**User Story:** Как разработчик, я хочу минимизировать изменения в существующей архитектуре, чтобы избежать регрессий и упростить поддержку.

#### Критерии приемки

1. WHEN система определяет, нужна ли шапка для сообщения THEN система SHALL использовать информацию из базы данных, а не передавать дополнительные параметры через все слои
2. WHEN система форматирует сообщение о событии THEN система SHALL использовать существующий метод buildEventMessage из BotMessageBuilder
3. WHEN система добавляет шапку к сообщению THEN система SHALL использовать существующий метод buildMyEventsHeader из BotMessageBuilder
4. WHEN система обновляет событие через sendOrUpdateEventMessage THEN система SHALL автоматически определять необходимость добавления шапки на основе данных из базы
5. WHEN обработчики callback редактируют первое событие THEN система SHALL проверять флаг isMyEventsHeader и добавлять шапку перед обновлением сообщения

### Требование 4

**User Story:** Как пользователь, я хочу, чтобы при удалении первого события следующее событие автоматически получало шапку, чтобы список оставался корректным.

#### Критерии приемки

1. WHEN пользователь удаляет первое событие из списка "Мои события" THEN система SHALL определить следующее событие по дате
2. WHEN система определяет новое первое событие THEN система SHALL установить для него флаг шапки списка
3. WHEN система обновляет новое первое событие THEN система SHALL включить шапку с обновленным количеством событий
4. WHEN в списке остается только одно событие THEN система SHALL сохранить шапку для этого события
