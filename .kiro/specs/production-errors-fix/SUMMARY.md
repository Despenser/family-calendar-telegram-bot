# Сводка: Ошибки в продакшене и план исправления

## Обнаруженные критические ошибки

### 1. Ошибки парсинга MarkdownV2 (КРИТИЧНО)

**Проблема:**
```
Bad Request (400): can't parse entities: Character '(' is reserved and must be escaped
Bad Request (400): can't parse entities: Character '.' is reserved and must be escaped
```

**Частота:** Множественные ошибки при отправке сообщений "Предстоящие события" и "Мои события"

**Причина:** Метод `MarkdownFormatter.escapeMarkdownV2()` не экранирует все зарезервированные символы

**Решение:**
- Обновить список экранируемых символов: `_`, `*`, `[`, `]`, `(`, `)`, `~`, `` ` ``, `>`, `#`, `+`, `-`, `=`, `|`, `{`, `}`, `.`, `!`
- Добавить fallback на plain text при критических ошибках
- Улучшить логирование с указанием проблемного текста

**Приоритет:** 🔴 ВЫСОКИЙ

---

### 2. Неизвестные callback-запросы фильтрации (КРИТИЧНО)

**Проблема:**
```
WARN - Неизвестный callback data: 'filter_all', telegramId=526536667
WARN - Неизвестный callback data: 'filter_family', telegramId=526536667
WARN - Неизвестный callback data: 'filter_personal', telegramId=526536667
```

**Частота:** При каждой попытке использовать фильтрацию

**Причина:** Отсутствует обработчик `FilterCallbackHandler` для callback с префиксом `filter_`

**Решение:**
- Создать `FilterCallbackHandler` для обработки callback фильтрации
- Зарегистрировать обработчик в `CallbackQueryDispatcher`
- Реализовать логику фильтрации событий по типу

**Приоритет:** 🔴 ВЫСОКИЙ

---

### 3. Пустой ответ от команды /filter (КРИТИЧНО)

**Проблема:**
```
WARN - Пустой ответ от обработчика команды: command=/filter
```

**Частота:** При каждом вызове команды /filter

**Причина:** `FilterCommandHandler` возвращает пустой ответ или не реализован полностью

**Решение:**
- Реализовать метод `handle()` в `FilterCommandHandler`
- Создать inline-клавиатуру с опциями фильтрации
- Вернуть `SendMessage` с текстом и клавиатурой

**Приоритет:** 🔴 ВЫСОКИЙ

---

### 4. Устаревшие callback-запросы (СРЕДНИЙ)

**Проблема:**
```
ERROR - Bad Request: query is too old and response timeout expired or query ID is invalid
ERROR - Все попытки ответа на callback query исчерпаны
```

**Частота:** Периодически при медленной обработке

**Причина:** Система пытается ответить на устаревшие callback queries (старше 30 секунд)

**Решение:**
- Добавить проверку возраста callback query
- Прекратить повторные попытки для устаревших запросов
- Логировать как INFO вместо ERROR

**Приоритет:** 🟡 СРЕДНИЙ

---

### 5. Предупреждения о версиях (НИЗКИЙ)

**Проблема:**
```
WARN - Flyway upgrade recommended: PostgreSQL 18.1 is newer than this version of Flyway
WARN - PostgreSQLDialect does not need to be specified explicitly
WARN - spring.jpa.open-in-view is enabled by default
```

**Частота:** При каждом запуске приложения

**Причина:** Устаревшие зависимости и конфигурация

**Решение:**
- Обновить Flyway до версии 10.21.0
- Удалить явное указание `hibernate.dialect`
- Установить `spring.jpa.open-in-view: false`

**Приоритет:** 🟢 НИЗКИЙ
