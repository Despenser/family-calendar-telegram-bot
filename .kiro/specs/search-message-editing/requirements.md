# Требования: Редактирование сообщения при поиске событий

## Введение

Эта спецификация описывает улучшение пользовательского опыта при поиске событий путем редактирования одного сообщения вместо отправки множества новых сообщений. В настоящее время команда /search отправляет новое сообщение для каждого этапа поиска (запрос текста, результаты), что загромождает чат. Новая реализация будет редактировать одно сообщение на протяжении всего процесса поиска и предоставит кнопку для повторного поиска.

## Глоссарь

- **SearchCommandHandler**: Обработчик команды /search для поиска событий по тексту
- **Сообщение_Поиска**: Единое сообщение, которое редактируется на протяжении всего процесса поиска
- **Кнопка_Повтора**: Inline-кнопка "🔍 Найти заново" для инициации нового поиска
- **Состояние_Поиска**: Информация о текущем сообщении поиска, сохраненная в ConversationState

## Требования

### Требование 1: Редактирование сообщения при вводе запроса

**User Story:** Как пользователь, я хочу, чтобы результаты поиска отображались в том же сообщении, что и запрос, чтобы чат не загромождался множеством сообщений.

#### Acceptance Criteria

1. WHEN пользователь вводит команду /search THEN система SHALL отправить сообщение с запросом ввести текст для поиска
2. WHEN система отправляет запрос на ввод текста THEN она SHALL сохранить message_id этого сообщения в ConversationState
3. WHEN пользователь вводит поисковый запрос THEN система SHALL отредактировать исходное сообщение, заменив его результатами поиска
4. WHEN сообщение редактируется THEN система SHALL NOT отправлять новое сообщение с результатами

### Требование 2: Отображение результатов поиска в отредактированном сообщении

**User Story:** Как пользователь, я хочу видеть результаты поиска в понятном формате в том же сообщении, чтобы легко отслеживать процесс поиска.

#### Acceptance Criteria

1. WHEN результаты поиска отображаются THEN отредактированное сообщение SHALL содержать заголовок "🔍 **Результаты поиска**"
2. WHEN результаты поиска отображаются THEN сообщение SHALL показывать поисковый запрос в формате "_Запрос: \"текст\"_"
3. WHEN найдены события THEN сообщение SHALL отображать список событий с использованием EventFormatter.formatSearchResult()
4. WHEN найдены события THEN сообщение SHALL показывать счетчик "_Найдено событий: N_"
5. WHEN поиск не дал результатов THEN сообщение SHALL показывать "По запросу \"текст\" ничего не найдено."
6. WHEN результаты поиска отображаются (найдены или не найдены) THEN сообщение SHALL содержать кнопку "🔍 Найти заново"

### Требование 3: Кнопка повторного поиска

**User Story:** Как пользователь, я хочу иметь возможность начать новый поиск после просмотра результатов, чтобы не вводить команду /search заново.

#### Acceptance Criteria

1. WHEN результаты поиска отображаются THEN система SHALL добавить inline-кнопку "🔍 Найти заново"
2. WHEN пользователь нажимает кнопку "Найти заново" THEN система SHALL отредактировать сообщение, вернув его к состоянию запроса текста для поиска
3. WHEN кнопка "Найти заново" нажата THEN система SHALL установить состояние ожидания нового поискового запроса
4. WHEN кнопка "Найти заново" нажата THEN система SHALL сохранить message_id для последующего редактирования

### Требование 4: Сохранение состояния поиска

**User Story:** Как система, я должна отслеживать состояние поиска для каждого пользователя, чтобы корректно редактировать сообщения и обрабатывать запросы.

#### Acceptance Criteria

1. WHEN начинается процесс поиска THEN система SHALL сохранить message_id сообщения поиска в ConversationState
2. WHEN пользователь вводит поисковый запрос THEN система SHALL использовать сохраненный message_id для редактирования сообщения
3. WHEN поиск завершается THEN система SHALL сохранить состояние для возможности повторного поиска
4. WHEN пользователь начинает другую операцию THEN система SHALL очистить состояние поиска

### Требование 5: Обработка callback для кнопки повторного поиска

**User Story:** Как разработчик, я хочу иметь отдельный callback handler для обработки нажатия кнопки "Найти заново", чтобы логика была изолирована и поддерживаема.

#### Acceptance Criteria

1. WHEN создается кнопка "Найти заново" THEN она SHALL использовать callback_data с префиксом "search_again:"
2. WHEN пользователь нажимает кнопку "Найти заново" THEN CallbackQueryDispatcher SHALL направить запрос в SearchCommandHandler
3. WHEN callback обрабатывается THEN система SHALL отредактировать сообщение, показав запрос на ввод текста
4. WHEN callback обрабатывается THEN система SHALL установить состояние ожидания поискового запроса

### Требование 6: Валидация и обработка ошибок

**User Story:** Как пользователь, я хочу получать понятные сообщения об ошибках, если что-то пошло не так в процессе поиска.

#### Acceptance Criteria

1. WHEN не удается отредактировать сообщение THEN система SHALL отправить новое сообщение с результатами поиска
2. WHEN message_id не найден в состоянии THEN система SHALL отправить новое сообщение вместо редактирования
3. WHEN происходит ошибка при редактировании THEN система SHALL залогировать ошибку и продолжить работу
4. WHEN поисковый запрос слишком короткий THEN система SHALL отредактировать сообщение, показав ошибку валидации

### Требование 7: Удаление пользовательских сообщений

**User Story:** Как пользователь, я хочу, чтобы мои введенные поисковые запросы автоматически удалялись из чата, чтобы чат оставался чистым и не загромождался.

#### Acceptance Criteria

1. WHEN пользователь вводит поисковый запрос THEN система SHALL удалить сообщение пользователя с текстом запроса
2. WHEN сообщение пользователя удаляется THEN система SHALL продолжить обработку поискового запроса
3. WHEN не удается удалить сообщение пользователя THEN система SHALL залогировать ошибку и продолжить работу
4. WHEN сообщение удалено THEN в чате SHALL остаться только отредактированное сообщение бота с результатами

### Требование 8: Обратная совместимость

**User Story:** Как разработчик, я хочу сохранить существующую функциональность поиска, чтобы не сломать текущее поведение системы.

#### Acceptance Criteria

1. WHEN реализуется редактирование сообщений THEN существующая логика поиска SearchService SHALL остаться без изменений
2. WHEN реализуется редактирование сообщений THEN форматирование результатов с использованием EventFormatter SHALL остаться без изменений
3. WHEN реализуется редактирование сообщений THEN валидация поисковых запросов SHALL остаться без изменений
4. WHEN реализуется редактирование сообщений THEN все существующие тесты SHALL продолжать проходить
