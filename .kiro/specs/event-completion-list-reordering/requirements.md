# Требования: Переупорядочивание списка при завершении события

## Введение

Данная функциональность улучшает пользовательский опыт при завершении событий в списке "Мои события". Когда пользователь завершает событие, которое находится не в конце списка, оно должно автоматически перемещаться вниз, чтобы пользователь мог комфортно добавить заметку о завершении, видя оставшиеся активные события выше.

## Глоссарий

- **System**: Telegram-бот для управления семейным календарём
- **Event**: Событие в календаре пользователя
- **My_Events_List**: Список событий пользователя, отображаемый по команде /myevents
- **Completion_Note**: Заметка, которую пользователь может добавить при завершении события
- **Active_Event**: Событие со статусом, отличным от "завершено"
- **Completed_Event**: Событие со статусом "завершено"

## Требования

### Требование 1: Переупорядочивание при завершении события

**User Story:** Как пользователь, я хочу, чтобы завершённое событие перемещалось вниз списка "Мои события", чтобы я мог комфортно добавить заметку о завершении, видя активные события выше.

#### Критерии приёмки

1. WHEN пользователь завершает событие в списке My_Events_List AND это событие не является последним в списке THEN THE System SHALL переместить завершённое событие вниз списка
2. WHEN пользователь завершает событие в списке My_Events_List THEN THE System SHALL отобразить все активные события выше завершённого события
3. WHEN пользователь завершает последнее событие в списке My_Events_List THEN THE System SHALL оставить его на текущей позиции
4. WHEN завершённое событие перемещается вниз списка THEN THE System SHALL сохранить относительный порядок активных событий
5. WHEN завершённое событие перемещается вниз списка THEN THE System SHALL обновить сообщение со списком событий с новым порядком

### Требование 2: Сохранение контекста для добавления заметки

**User Story:** Как пользователь, я хочу, чтобы после завершения события интерфейс для добавления заметки отображался в правильном контексте, чтобы я понимал, к какому событию добавляю заметку.

#### Критерии приёмки

1. WHEN пользователь завершает событие THEN THE System SHALL отобразить интерфейс для добавления заметки под переупорядоченным списком
2. WHEN отображается интерфейс для добавления заметки THEN THE System SHALL чётко указать, к какому событию относится заметка
3. WHEN пользователь добавляет заметку к завершённому событию THEN THE System SHALL сохранить заметку и обновить отображение события

### Требование 3: Обработка множественных завершений

**User Story:** Как пользователь, я хочу иметь возможность последовательно завершать несколько событий, чтобы эффективно управлять своим списком задач.

#### Критерии приёмки

1. WHEN пользователь завершает несколько событий подряд THEN THE System SHALL корректно переупорядочивать список после каждого завершения
2. WHEN в списке остаются только завершённые события THEN THE System SHALL отображать их в порядке завершения
3. WHEN пользователь завершает все активные события THEN THE System SHALL отобразить соответствующее сообщение о пустом списке активных событий

### Требование 4: Совместимость с существующей функциональностью

**User Story:** Как разработчик, я хочу, чтобы новая функциональность не нарушала существующее поведение системы, чтобы обеспечить стабильность приложения.

#### Критерии приёмки

1. WHEN событие завершается с переупорядочиванием THEN THE System SHALL сохранить все существующие данные события
2. WHEN список переупорядочивается THEN THE System SHALL корректно обновить message_id для заголовка списка
3. WHEN происходит переупорядочивание THEN THE System SHALL сохранить состояние разговора (conversation state) для корректной работы callback-обработчиков
4. WHEN событие перемещается в списке THEN THE System SHALL сохранить все связанные данные (вложения, комментарии, чек-листы)
