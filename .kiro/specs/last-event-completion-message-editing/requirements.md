# Requirements Document

## Введение

При завершении последнего события в списке "Мои события" система отправляет **новое сообщение** с предложением добавить заметку. Это создаёт лишние сообщения в чате и нарушает пользовательский опыт. Требуется изменить поведение так, чтобы при завершении последнего события сообщение **редактировалось** (как это происходит при завершении не последнего события через переупорядочивание), а не создавалось новое.

Текущее поведение:
- **Последнее событие**: отправляется НОВОЕ сообщение с завершённым событием и кнопками
- **Не последнее событие**: все сообщения удаляются и отправляются заново в новом порядке (переупорядочивание)

Требуемое поведение:
- **Последнее событие**: существующее сообщение события РЕДАКТИРУЕТСЯ, показывая завершённое событие с кнопками
- **Не последнее событие**: текущая логика переупорядочивания сохраняется

## Глоссарий

- **EventService**: Сервис для работы с событиями
- **completeEventWithReordering**: Метод завершения события с переупорядочиванием списка
- **sendCompletedEventWithNote**: Метод отправки нового сообщения с завершённым событием и кнопками для добавления заметки
- **TelegramMessageService**: Сервис для работы с Telegram API
- **editMessage**: Метод редактирования существующего сообщения в Telegram
- **Последнее событие**: Событие, которое находится в конце списка "Мои события" (не требует переупорядочивания)
- **messageId**: Идентификатор сообщения в Telegram, сохранённый в поле Event.messageId
- **BotMessageBuilder**: Сервис для формирования текста сообщений бота
- **KeyboardService**: Сервис для создания inline-клавиатур

## Требования

### Требование 1

**User Story:** Как пользователь, я хочу чтобы при завершении последнего события в списке "Мои события" существующее сообщение редактировалось, а не создавалось новое, чтобы чат не загромождался лишними сообщениями.

#### Критерии приемки

1. WHEN пользователь завершает последнее событие в списке "Мои события" THEN система SHALL отредактировать существующее сообщение события
2. WHEN система редактирует сообщение последнего события THEN система SHALL отобразить статус "завершено" и кнопки "📝 Добавить заметку" и "⏭️ Пропустить"
3. WHEN система редактирует сообщение последнего события THEN система SHALL сохранить тот же messageId в поле Event.messageId
4. WHEN пользователь завершает последнее событие THEN система SHALL НЕ создавать новое сообщение
5. WHEN пользователь завершает НЕ последнее событие THEN система SHALL продолжать использовать текущую логику переупорядочивания

### Требование 2

**User Story:** Как пользователь, я хочу видеть единообразное поведение при завершении событий, чтобы интерфейс был предсказуемым и понятным.

#### Критерии приемки

1. WHEN пользователь завершает любое событие THEN система SHALL использовать редактирование сообщений вместо создания новых
2. WHEN событие завершено THEN система SHALL отображать одинаковый формат сообщения независимо от позиции события в списке
3. WHEN отображаются кнопки для добавления заметки THEN система SHALL использовать одинаковые кнопки для всех завершённых событий
4. WHEN пользователь взаимодействует с завершённым событием THEN система SHALL использовать сохранённый messageId для редактирования

### Требование 3

**User Story:** Как разработчик, я хочу чтобы метод completeEventWithReordering использовал редактирование сообщений для последнего события, чтобы обеспечить единообразие кода и поведения.

#### Критерии приемки

1. WHEN метод completeEventWithReordering обрабатывает последнее событие THEN система SHALL использовать TelegramMessageService.editMessage вместо sendMessage
2. WHEN система редактирует сообщение последнего события THEN система SHALL использовать существующий messageId из Event.messageId
3. WHEN messageId отсутствует у последнего события THEN система SHALL отправить новое сообщение как fallback
4. WHEN происходит ошибка редактирования сообщения THEN система SHALL логировать ошибку и продолжить работу

### Требование 4

**User Story:** Как система, я должна корректно обрабатывать случаи, когда сообщение не может быть отредактировано, чтобы обеспечить надёжность работы.

#### Критерии приемки

1. WHEN у события отсутствует messageId THEN система SHALL отправить новое сообщение вместо редактирования
2. WHEN Telegram API возвращает ошибку при редактировании THEN система SHALL логировать ошибку и отправить новое сообщение
3. WHEN сообщение было удалено пользователем THEN система SHALL обработать ошибку и отправить новое сообщение
4. WHEN происходит любая ошибка редактирования THEN система SHALL НЕ прерывать процесс завершения события
