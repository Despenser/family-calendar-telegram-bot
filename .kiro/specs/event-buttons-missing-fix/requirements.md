# Требования: Исправление пропавших кнопок редактирования и удаления событий

## Введение

Пользователи сообщают, что кнопки редактирования и удаления событий не отображаются при просмотре списка событий через команду `/my_events`. Это критическая проблема, так как без этих кнопок пользователи не могут управлять своими событиями.

## Глоссарий

- **Система** - Telegram бот семейного календаря
- **Пользователь** - авторизованный пользователь бота
- **Событие** - запись в календаре с датой, временем и описанием
- **Inline_Кнопки** - интерактивные кнопки, отображаемые под сообщением в Telegram
- **Callback_Query** - запрос, отправляемый при нажатии на inline кнопку

## Требования

### Требование 1: Диагностика проблемы

**User Story:** Как разработчик, я хочу понять причину отсутствия кнопок, чтобы правильно исправить проблему.

#### Критерии приемки

1. WHEN система отправляет событие пользователю, THEN Система ДОЛЖНА логировать информацию о создании inline клавиатуры
2. WHEN inline клавиатура создается, THEN Система ДОЛЖНА логировать количество кнопок в клавиатуре
3. WHEN сообщение с кнопками отправляется, THEN Система ДОЛЖНА логировать успешность отправки
4. WHEN возникает ошибка при отправке, THEN Система ДОЛЖНА логировать детальную информацию об ошибке

### Требование 2: Отображение кнопок управления событиями

**User Story:** Как пользователь, я хочу видеть кнопки редактирования и удаления под каждым событием, чтобы управлять своими событиями.

#### Критерии приемки

1. WHEN пользователь выполняет команду /my_events, THEN Система ДОЛЖНА отобразить каждое событие с inline кнопками
2. WHEN событие отображается, THEN Система ДОЛЖНА показать кнопку "✏️ Редактировать"
3. WHEN событие отображается, THEN Система ДОЛЖНА показать кнопку "🗑️ Удалить"
4. WHEN кнопки создаются, THEN Система ДОЛЖНА установить корректные callback_data для каждой кнопки
5. WHEN callback_data устанавливается, THEN Система ДОЛЖНА использовать формат "edit_event_{eventId}" для редактирования
6. WHEN callback_data устанавливается, THEN Система ДОЛЖНА использовать формат "delete_event_{eventId}" для удаления

### Требование 3: Обработка нажатий на кнопки

**User Story:** Как пользователь, я хочу, чтобы кнопки реагировали на нажатия, чтобы выполнять действия с событиями.

#### Критерии приемки

1. WHEN пользователь нажимает кнопку "Редактировать", THEN Система ДОЛЖНА обработать callback query
2. WHEN пользователь нажимает кнопку "Удалить", THEN Система ДОЛЖНА обработать callback query
3. WHEN callback query обрабатывается, THEN Система ДОЛЖНА отправить ответ пользователю
4. WHEN callback query обрабатывается, THEN Система ДОЛЖНА вызвать answerCallbackQuery для подтверждения

### Требование 4: Корректность форматирования сообщений

**User Story:** Как пользователь, я хочу, чтобы сообщения с событиями корректно отображались, чтобы я мог читать информацию о событиях.

#### Критерии приемки

1. WHEN событие форматируется для отправки, THEN Система ДОЛЖНА корректно экранировать специальные символы MarkdownV2
2. WHEN сообщение содержит специальные символы, THEN Система ДОЛЖНА использовать escape() для их экранирования
3. WHEN сообщение отправляется, THEN Система ДОЛЖНА использовать parseMode="MarkdownV2"
4. IF форматирование некорректно, THEN Система ДОЛЖНА логировать ошибку и отправлять сообщение без форматирования

### Требование 5: Обработка ошибок

**User Story:** Как разработчик, я хочу, чтобы система корректно обрабатывала ошибки, чтобы пользователи получали понятные сообщения.

#### Критерии приемки

1. IF отправка сообщения с кнопками не удалась, THEN Система ДОЛЖНА логировать детальную информацию об ошибке
2. IF отправка сообщения не удалась, THEN Система ДОЛЖНА продолжить обработку остальных событий
3. IF все попытки отправки не удались, THEN Система ДОЛЖНА уведомить пользователя об ошибке
4. WHEN возникает TelegramApiException, THEN Система ДОЛЖНА записать метрику ошибки
