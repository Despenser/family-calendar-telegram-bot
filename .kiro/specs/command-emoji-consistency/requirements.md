# Requirements Document: Добавление эмодзи к командам в сообщениях

## Introduction

Данная спецификация описывает требования к добавлению эмодзи к командам в сообщениях пользователю для обеспечения визуальной консистентности с командами /start и /help, где эмодзи уже используются.

## Glossary

- **System**: Telegram бот семейного календаря
- **Command**: Команда бота, начинающаяся с символа "/" (например, /start, /help, /add_event)
- **Emoji**: Графический символ (эмодзи), используемый для визуального выделения команды
- **Message**: Текстовое сообщение, отправляемое ботом пользователю
- **User**: Пользователь Telegram, взаимодействующий с ботом

## Requirements

### Requirement 1: Консистентность эмодзи в CommandDispatcher

**User Story:** Как пользователь, я хочу видеть эмодзи рядом с командами в сообщениях об ошибках, чтобы команды были визуально выделены и легко узнаваемы.

#### Acceptance Criteria

1. WHEN пользователь отправляет сообщение без текста THEN THE System SHALL отобразить сообщение с эмодзи 📚 перед командой /help
2. WHEN пользователь отправляет команду без символа "/" THEN THE System SHALL отобразить сообщение с эмодзи 📚 перед командой /help
3. WHEN пользователь отправляет неизвестную команду THEN THE System SHALL отобразить сообщение с эмодзи 📚 перед командой /help
4. WHEN неавторизованный пользователь пытается выполнить команду, требующую авторизации THEN THE System SHALL отобразить сообщение с эмодзи 🚀 перед командой /start

### Requirement 2: Консистентность эмодзи в UpdateProcessor

**User Story:** Как пользователь, я хочу видеть эмодзи рядом с командами в различных сообщениях UpdateProcessor, чтобы команды были визуально выделены.

#### Acceptance Criteria

1. WHEN происходит ошибка при создании события THEN THE System SHALL отобразить сообщение с эмодзи ➕ перед командой /add_event
2. WHEN пользователь отправляет текст в неправильном формате для быстрого создания события THEN THE System SHALL отобразить сообщение с эмодзи ➕ перед командой /add_event
3. WHEN неавторизованный пользователь пытается отправить файл THEN THE System SHALL отобразить сообщение с эмодзи 🚀 перед командой /start
4. WHEN пользователь пытается прикрепить файл без создания события THEN THE System SHALL отобразить сообщение с эмодзи ➕ перед командой /add_event
5. WHEN пользователь отправляет команду без символа "/" THEN THE System SHALL отобразить сообщение с эмодзи 📚 перед командой /help
6. WHEN пользователь отправляет неизвестную команду THEN THE System SHALL отобразить сообщение с эмодзи 📚 перед командой /help

### Requirement 3: Консистентность эмодзи в EventService

**User Story:** Как пользователь, я хочу видеть эмодзи рядом с командой /add_event в сообщении о пустом списке событий, чтобы команда была визуально выделена.

#### Acceptance Criteria

1. WHEN пользователь открывает пустой список "Мои события" THEN THE System SHALL отобразить сообщение с эмодзи ➕ перед командой /add_event

### Requirement 4: Консистентность эмодзи в SearchCommandHandler

**User Story:** Как пользователь, я хочу видеть эмодзи рядом с командами /today и /week в сообщении об отсутствии результатов поиска, чтобы команды были визуально выделены.

#### Acceptance Criteria

1. WHEN поиск не находит результатов THEN THE System SHALL отобразить сообщение с эмодзи 📅 перед командой /today
2. WHEN поиск не находит результатов THEN THE System SHALL отобразить сообщение с эмодзи 📆 перед командой /week
3. WHEN происходит ошибка при повторном поиске THEN THE System SHALL отобразить сообщение с эмодзи 🔍 перед командой /search

### Requirement 5: Консистентность эмодзи в CallbackQueryDispatcher

**User Story:** Как пользователь, я хочу видеть эмодзи рядом с командой /start в сообщении об ошибке авторизации, чтобы команда была визуально выделена.

#### Acceptance Criteria

1. WHEN неавторизованный пользователь пытается выполнить callback query THEN THE System SHALL отобразить сообщение с эмодзи 🚀 перед командой /start

### Requirement 6: Использование существующего маппинга эмодзи

**User Story:** Как разработчик, я хочу использовать существующий маппинг эмодзи из HelpCommandHandler, чтобы обеспечить консистентность эмодзи во всем приложении.

#### Acceptance Criteria

1. THE System SHALL использовать следующие эмодзи для команд:
   - 🚀 для /start
   - 📚 для /help
   - ➕ для /add_event
   - 📝 для /my_events
   - 📋 для /upcoming_events
   - 📅 для /today
   - 📆 для /week
   - 🔍 для /search
   - 🫧 для /filter
   - 📊 для /stats
   - 🗑️ для /trash
2. THE System SHALL обеспечить консистентность эмодзи между HelpCommandHandler, StartCommandHandler и всеми остальными обработчиками
