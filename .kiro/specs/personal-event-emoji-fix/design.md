# Design Document

## Overview

Данный дизайн описывает изменение визуального представления персональных событий в Telegram-боте семейного календаря. Текущая реализация использует эмодзи замка 🔒 для обозначения персональных событий, что создает неправильное визуальное впечатление. Замок ассоциируется с блокировкой или ограничением доступа, в то время как персональное событие - это просто событие, видимое только создателю. Более подходящим эмодзи является 👤 (человек), который лучше отражает персональный характер события.

## Architecture

Изменения затрагивают только слой представления (UI) и не влияют на бизнес-логику или хранение данных. Все изменения локализованы в классах, отвечающих за формирование сообщений и клавиатур.

### Затронутые компоненты

1. **KeyboardService** - создание inline-клавиатуры выбора типа события
2. **ReminderService** - форматирование текста напоминаний о событиях
3. **MyEventsCommandHandler** - отображение деталей события в списке "Мои события"
4. **BotMessageBuilder** - формирование сообщения о выборе типа события

## Components and Interfaces

### KeyboardService

**Метод:** `createEventTypeSelectionKeyboard()`

**Текущая реализация:**
```java
InlineKeyboardButton personalBtn = new InlineKeyboardButton("🔒 Персональное событие");
```

**Новая реализация:**
```java
InlineKeyboardButton personalBtn = new InlineKeyboardButton("👤 Персональное событие");
```

### ReminderService

**Метод:** `formatReminderMessage(Event event, String reminderType)`

**Текущая реализация:**
```java
if (event.getIsPersonal()) {
    message.append("🔒 ").append(bold("Персональное событие")).append("\n");
}
```

**Новая реализация:**
```java
if (event.getIsPersonal()) {
    message.append("👤 ").append(bold("Персональное событие")).append("\n");
}
```

### MyEventsCommandHandler

**Метод:** `formatEventDetails(Event event, Long userId)`

**Текущая реализация:**
```java
if (event.getIsPersonal()) {
    details.append("🔒 ").append(bold("Персональное событие")).append("\n");
}
```

**Новая реализация:**
```java
if (event.getIsPersonal()) {
    details.append("👤 ").append(bold("Персональное событие")).append("\n");
}
```

### BotMessageBuilder

**Метод:** `formatEventTypeSelectionMessage(boolean isPersonal)`

**Текущая реализация:**
```java
if (isPersonal) {
    return bold(EVENT_CREATION_HEADER) + "\n\n" +
           "✅ " + escape("Выбрано: Персональное событие") + "\n\n" +
           italic("Только вы будете видеть это событие.") + "\n\n" +
           "📅 " + escape("Теперь выберите дату события:");
}
```

**Новая реализация:** Не требует изменений, так как эмодзи не используется в этом сообщении.

## Data Models

Изменения не затрагивают модели данных. Все изменения касаются только визуального представления.

## Correctness Properties

### Property 1: Консистентность эмодзи персонального события

*For any* контекст отображения персонального события (клавиатура выбора типа, напоминание, детали события), система должна использовать эмодзи 👤 для обозначения персонального события.

**Validates: Requirements 1.1, 1.3**

### Property 2: Функциональность выбора типа события

*For any* выбор типа события через клавиатуру, система должна корректно обработать callback и создать событие с правильным типом (персональное/семейное), независимо от изменения эмодзи.

**Validates: Requirements 1.2**

## Error Handling

Изменения не вводят новых сценариев ошибок. Существующая обработка ошибок остается без изменений.

## Testing Strategy

### Unit Tests

1. **KeyboardServiceTest.testCreateEventTypeSelectionKeyboard()**
   - Проверить, что кнопка персонального события содержит эмодзи 👤
   - Проверить, что callback data остается неизменным ("event_type_personal")

2. **ReminderServiceTest.testFormatReminderMessageForPersonalEvent()**
   - Проверить, что сообщение напоминания о персональном событии содержит эмодзи 👤
   - Проверить, что текст "Персональное событие" присутствует

3. **MyEventsCommandHandlerTest.testFormatEventDetailsForPersonalEvent()**
   - Проверить, что детали персонального события содержат эмодзи 👤
   - Проверить, что текст "Персональное событие" присутствует

### Property-Based Tests

Не требуются для данного изменения, так как это простая замена константы.

### Manual Testing

1. Создать новое событие и проверить, что кнопка "Персональное событие" отображается с эмодзи 👤
2. Выбрать персональное событие и убедиться, что оно создается корректно
3. Просмотреть детали персонального события в "Мои события" и проверить эмодзи 👤
4. Получить напоминание о персональном событии и проверить эмодзи 👤

## Implementation Notes

- Изменения минимальны и затрагивают только строковые константы
- Не требуется миграция данных
- Обратная совместимость полностью сохраняется
- Изменения не влияют на производительность
