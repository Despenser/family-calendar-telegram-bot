# Проектирование: Устранение дублирования команд /week и /upcoming_events

## Обзор

Текущая реализация команд `/week` и `/upcoming_events` содержит дублирование функциональности - обе команды показывают события на 7 дней. Это решение устраняет дублирование путем разграничения назначения команд:

- **`/week`** - краткий обзор событий на текущую неделю (7 дней) с группировкой по дням
- **`/upcoming_events`** - полный список всех предстоящих событий на месяц (30 дней) с детальной информацией

Такое разделение дает пользователям два инструмента для разных сценариев использования:
- Быстрый просмотр ближайших планов (неделя)
- Долгосрочное планирование (месяц)

## Архитектура

### Текущая архитектура

```
┌─────────────────────┐         ┌──────────────────┐
│ WeekCommandHandler  │────────▶│  EventService    │
└─────────────────────┘         │                  │
                                │ getUpcomingEvents│
┌─────────────────────────────┐ │   (familyId, 7)  │
│ UpcomingEventsCommandHandler│─▶│                  │
└─────────────────────────────┘ └──────────────────┘
                                         │
                                         ▼
                                ┌──────────────────┐
                                │ EventRepository  │
                                └──────────────────┘
```

Проблема: оба обработчика используют одинаковый параметр `days = 7`.

### Целевая архитектура

```
┌─────────────────────┐         ┌──────────────────┐
│ WeekCommandHandler  │────────▶│  EventService    │
│   (7 дней)          │         │                  │
└─────────────────────┘         │ getUpcomingEvents│
                                │   (familyId, N)  │
┌─────────────────────────────┐ │                  │
│ UpcomingEventsCommandHandler│─▶│  N = 7 или 30   │
│   (30 дней)                  │ └──────────────────┘
└─────────────────────────────┘         │
                                        ▼
                                ┌──────────────────┐
                                │ EventRepository  │
                                └──────────────────┘
```

Решение: разные значения параметра `days` для разных сценариев использования.

## Компоненты и интерфейсы

### 1. WeekCommandHandler

**Назначение:** Обработка команды `/week` для отображения событий на текущую неделю.

**Изменения:**
- Сохраняет текущую реализацию с параметром `days = 7`
- Обновляет описание команды для ясности
- Использует компактный формат с группировкой по дням

**Интерфейс:**
```java
public class WeekCommandHandler implements CommandHandler {
    private static final int WEEK_DAYS = 7;
    
    @Override
    public String handle(Message message, User user);
    
    @Override
    public String getCommand(); // "/week"
    
    @Override
    public String getDescription(); // "Показать события на неделю (7 дней)"
    
    @Override
    public boolean requiresAuth(); // true
}
```

### 2. UpcomingEventsCommandHandler

**Назначение:** Обработка команды `/upcoming_events` для отображения всех предстоящих событий на месяц.

**Изменения:**
- Изменяет константу `DEFAULT_DAYS` с 7 на 30
- Обновляет описание команды
- Обновляет сообщения пользователю (указание периода 30 дней)
- Сохраняет детальный формат отображения

**Интерфейс:**
```java
public class UpcomingEventsCommandHandler implements CommandHandler {
    private static final int DEFAULT_DAYS = 30; // Изменено с 7 на 30
    
    @Override
    public String handle(Message message, User user);
    
    @Override
    public String getCommand(); // "/upcoming_events"
    
    @Override
    public String getDescription(); // "Показать все предстоящие события (30 дней)"
    
    @Override
    public boolean requiresAuth(); // true
}
```

### 3. EventService

**Назначение:** Бизнес-логика для работы с событиями.

**Изменения:** Не требуются - метод `getUpcomingEvents(familyId, days)` уже поддерживает параметризацию.

**Используемый метод:**
```java
@Transactional(readOnly = true)
public List<Event> getUpcomingEvents(Long familyId, int days) {
    LocalDate startDate = LocalDate.now();
    LocalDate endDate = startDate.plusDays(days);
    return eventRepository.findByFamilyIdAndEventDateBetween(familyId, startDate, endDate);
}
```

### 4. Фильтрация персональных событий

Оба обработчика должны применять единую логику фильтрации:

```java
List<Event> filteredEvents = events.stream()
    .filter(event -> !event.getIsPersonal() || event.belongsToUser(user.getId()))
    .collect(Collectors.toList());
```

**Правила фильтрации:**
- Семейные события (`isPersonal = false`) видны всем членам семьи
- Персональные события (`isPersonal = true`) видны только создателю

### Рефлексия свойств

После анализа критериев приемки выявлена избыточность:
- Свойства 1.4, 4.1 и 4.2 проверяют одну и ту же логику фильтрации - объединены в одно свойство
- Свойство 2.4 дублирует проверку полноты информации из 2.2 - удалено

### Свойство 1: Диапазон событий для команды /week

*Для любой* семьи и любого пользователя, команда `/week` должна возвращать только те события, которые находятся в диапазоне от текущей даты до текущей даты + 7 дней включительно.

**Проверяет требования:** 1.1, 5.2

**Тестовая стратегия:**
- Создать случайную семью с событиями на разные периоды (до сегодня, в пределах 7 дней, после 7 дней)
- Вызвать команду `/week`
- Проверить, что все возвращенные события имеют дату в диапазоне [сегодня, сегодня + 7 дней]
- Проверить, что события вне диапазона не включены

### Свойство 2: Диапазон событий для команды /upcoming_events

*Для любой* семьи и любого пользователя, команда `/upcoming_events` должна возвращать только те события, которые находятся в диапазоне от текущей даты до текущей даты + 30 дней включительно.

**Проверяет требования:** 2.1, 5.3

**Тестовая стратегия:**
- Создать случайную семью с событиями на разные периоды (до сегодня, в пределах 30 дней, после 30 дней)
- Вызвать команду `/upcoming_events`
- Проверить, что все возвращенные события имеют дату в диапазоне [сегодня, сегодня + 30 дней]
- Проверить, что события вне диапазона не включены

### Свойство 3: Фильтрация персональных событий

*Для любого* набора событий семьи, результат команды (как `/week`, так и `/upcoming_events`) должен содержать:
- Все семейные события (где `isPersonal = false`)
- Только те персональные события (где `isPersonal = true`), где создатель совпадает с текущим пользователем

**Проверяет требования:** 1.4, 4.1, 4.2

**Тестовая стратегия:**
- Создать семью с несколькими пользователями
- Создать случайный набор семейных и персональных событий от разных пользователей
- Вызвать команду от имени конкретного пользователя
- Проверить, что результат содержит все семейные события
- Проверить, что результат содержит только персональные события текущего пользователя
- Проверить, что персональные события других пользователей отсутствуют

### Свойство 4: Группировка по датам в команде /week

*Для любого* набора событий, результат команды `/week` должен группировать события по датам, и каждая дата должна иметь заголовок дня.

**Проверяет требования:** 1.2

**Тестовая стратегия:**
- Создать события на разные дни в пределах недели
- Вызвать команду `/week`
- Проверить, что в результате присутствуют заголовки дней
- Проверить, что события под каждым заголовком имеют соответствующую дату

### Свойство 5: Детальный формат в команде /upcoming_events

*Для любого* события в результате команды `/upcoming_events`, отформатированная строка должна содержать дату, время, описание (если есть) и имя создателя.

**Проверяет требования:** 2.2, 2.4

**Тестовая стратегия:**
- Создать случайные события с различными полями
- Вызвать команду `/upcoming_events`
- Для каждого события проверить наличие в выводе:
  - Даты события
  - Времени события
  - Описания (если оно не пустое)
  - Имени создателя

### Свойство 6: Хронологическая сортировка в команде /upcoming_events

*Для любого* набора событий, результат команды `/upcoming_events` должен быть отсортирован по дате и времени в хронологическом порядке (от ближайших к более поздним).

**Проверяет требования:** 2.5

**Тестовая стратегия:**
- Создать случайный набор событий с разными датами и временем
- Вызвать команду `/upcoming_events`
- Проверить, что каждое следующее событие в списке имеет дату/время не раньше предыдущего

### Свойство 7: Маркировка персональных событий

*Для любого* персонального события в результате команды, отформатированная строка должна содержать иконку "🔒".

### Свойство 8: Маркировка семейных событий

**Проверяет требования:** 4.4

**Тестовая стратегия:**

## Обработка ошибок

### Сценарии ошибок

1. **Пользователь не принадлежит семье**
   - Обе команды требуют, чтобы пользователь был членом семьи
   - Возвращается сообщение: "Вы не принадлежите ни одной семье"

2. **Нет событий в указанном периоде**
   - `/week`: "На ближайшую неделю событий не запланировано. Время для новых планов! 📝"
   - `/upcoming_events`: "На ближайшие 30 дней событий не запланировано.\n\nИспользуйте /add_event для добавления нового события."

3. **Ошибка при получении событий**
   - Логируется исключение
   - Возвращается: "❌ Произошла ошибка при получении событий. Попробуйте позже."

### Логирование

Оба обработчика должны логировать:
- **DEBUG**: Начало обработки команды с ID пользователя и семьи
- **DEBUG**: Количество найденных событий
- **INFO**: Успешная отправка результата пользователю
- **WARN**: Попытка использования без семьи
- **ERROR**: Исключения при обработке

**Влияние на производительность:**
- Команда `/upcoming_events` будет запрашивать больше данных (30 дней вместо 7)
