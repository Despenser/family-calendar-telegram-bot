# Требования: Устранение дублирования команд /week и /upcoming_events

## Введение

В настоящее время команды `/week` и `/upcoming_events` дублируют функциональность, обе показывая события на ближайшие 7 дней. Это создает путаницу для пользователей и избыточность в системе. Необходимо разграничить функциональность этих команд, чтобы каждая имела свое уникальное назначение.

## Глоссарь

- **Система** - Telegram бот семейного календаря
- **Пользователь** - авторизованный участник семьи, использующий бота
- **Событие** - запланированное мероприятие в календаре семьи
- **Неделя** - период в 7 дней, начиная с текущей даты
- **Предстоящие события** - события, запланированные на будущий период времени
- **Семейное событие** - событие, видимое всем членам семьи
- **Персональное событие** - событие, видимое только создателю

## Требования

### Требование 1

**Пользовательская история:** Как пользователь, я хочу видеть краткий обзор событий на текущую неделю, чтобы быстро понять ближайшие планы семьи.

#### Критерии приемки

1. WHEN пользователь вызывает команду `/week`, THEN Система SHALL отобразить события на ближайшие 7 дней, сгруппированные по датам
2. WHEN Система отображает события по команде `/week`, THEN Система SHALL использовать компактный формат с группировкой по дням недели
3. WHEN у пользователя нет событий на неделю, THEN Система SHALL отобразить сообщение "На ближайшую неделю событий не запланировано"
4. WHEN Система отображает события по команде `/week`, THEN Система SHALL показывать как семейные, так и персональные события пользователя
5. WHEN Система отображает события по команде `/week`, THEN Система SHALL выделять "Сегодня" и "Завтра" специальными маркерами

### Требование 2

**Пользовательская история:** Как пользователь, я хочу видеть полный список предстоящих событий на более длительный период, чтобы планировать дела заранее.

#### Критерии приемки

1. WHEN пользователь вызывает команду `/upcoming_events`, THEN Система SHALL отобразить события на ближайшие 30 дней
2. WHEN Система отображает события по команде `/upcoming_events`, THEN Система SHALL использовать детальный формат с полной информацией о каждом событии
3. WHEN у пользователя нет предстоящих событий, THEN Система SHALL отобразить сообщение "На ближайшие 30 дней событий не запланировано"
4. WHEN Система отображает события по команде `/upcoming_events`, THEN Система SHALL показывать дату, время, описание и создателя каждого события
5. WHEN Система отображает события по команде `/upcoming_events`, THEN Система SHALL сортировать события по дате и времени в хронологическом порядке

### Требование 3

**Пользовательская история:** Как пользователь, я хочу понимать разницу между командами `/week` и `/upcoming_events`, чтобы выбирать подходящую для моих нужд.

#### Критерии приемки

1. WHEN пользователь вызывает команду `/help`, THEN Система SHALL отображать описание команды `/week` как "Показать события на неделю (7 дней)"
2. WHEN пользователь вызывает команду `/help`, THEN Система SHALL отображать описание команды `/upcoming_events` как "Показать все предстоящие события (30 дней)"
3. WHEN Система отображает результат команды `/week`, THEN Система SHALL включать заголовок "События на неделю" с указанием диапазона дат
4. WHEN Система отображает результат команды `/upcoming_events`, THEN Система SHALL включать заголовок "Предстоящие события семьи (30 дней)"

### Требование 4

**Пользовательская история:** Как пользователь, я хочу, чтобы обе команды корректно фильтровали персональные события, чтобы видеть только доступную мне информацию.

#### Критерии приемки

1. WHEN Система получает события для отображения, THEN Система SHALL показывать все семейные события (где isPersonal = false)
2. WHEN Система получает события для отображения, THEN Система SHALL показывать только те персональные события, где создатель совпадает с текущим пользователем
3. WHEN Система отображает персональное событие, THEN Система SHALL помечать его иконкой "🔒"
4. WHEN Система отображает семейное событие, THEN Система SHALL помечать его иконкой "👨‍👩‍👧‍👦"

### Требование 5

**Пользовательская история:** Как разработчик, я хочу, чтобы обе команды использовали единый сервисный метод для получения событий, чтобы избежать дублирования кода и упростить поддержку.

#### Критерии приемки

1. WHEN обработчик команды запрашивает события, THEN Система SHALL использовать метод `EventService.getUpcomingEvents(familyId, days)` с соответствующим параметром days
2. WHEN вызывается команда `/week`, THEN Система SHALL передавать параметр days = 7
3. WHEN вызывается команда `/upcoming_events`, THEN Система SHALL передавать параметр days = 30
4. WHEN Система применяет фильтрацию персональных событий, THEN Система SHALL использовать единую логику фильтрации в обоих обработчиках
