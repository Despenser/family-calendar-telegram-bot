# Документ требований: Исправление LazyInitializationException при возврате к напоминанию

## Введение

При нажатии кнопки "Назад к напоминанию" в интерфейсе события возникает ошибка `LazyInitializationException` при попытке доступа к полю `User.timezone`. Это происходит потому, что метод `ReminderService.formatShortReminderMessage()` пытается получить доступ к lazy-loaded полю User после закрытия Hibernate сессии.

## Глоссарий

- **System**: Telegram-бот семейного календаря
- **ReminderService**: Сервис для работы с напоминаниями
- **EventCallbackHandler**: Обработчик callback-запросов для событий
- **LazyInitializationException**: Исключение Hibernate при попытке доступа к lazy-loaded полю вне сессии
- **Reminder**: Напоминание о событии
- **Event**: Событие в календаре
- **User**: Пользователь системы
- **Timezone**: Часовой пояс пользователя

## Требования

### Требование 1: Передача timezone в метод форматирования

**User Story:** Как разработчик, я хочу передавать timezone явно в метод форматирования, чтобы избежать LazyInitializationException при доступе к User.timezone.

#### Критерии приемки

1. WHEN метод `formatShortReminderMessage` вызывается с параметром `recipientTimezone`, THEN система НЕ ДОЛЖНА обращаться к `event.getUser().getTimezone()`
2. WHEN метод `formatShortReminderMessage` получает `recipientTimezone`, THEN система ДОЛЖНА использовать этот timezone для форматирования времени события
3. WHEN вызывающий код передает timezone в `formatShortReminderMessage`, THEN система ДОЛЖНА использовать переданный timezone вместо получения его из User

### Требование 2: Удаление вызова getUserTimezone из formatShortReminderMessage

**User Story:** Как разработчик, я хочу удалить вызов `getUserTimezone` из метода `formatShortReminderMessage`, чтобы метод не зависел от состояния Hibernate сессии.

#### Критерии приемки

1. WHEN метод `formatShortReminderMessage` выполняется, THEN система НЕ ДОЛЖНА вызывать метод `getUserTimezone`
2. WHEN метод `formatShortReminderMessage` форматирует сообщение, THEN система ДОЛЖНА использовать только переданный параметр `recipientTimezone`
3. WHEN метод `formatShortReminderMessage` завершается, THEN система НЕ ДОЛЖНА генерировать `LazyInitializationException`

### Требование 3: Корректная работа возврата к напоминанию

**User Story:** Как пользователь, я хочу иметь возможность вернуться к напоминанию из детального просмотра события, чтобы увидеть короткое сообщение напоминания.

#### Критерии приемки

1. WHEN пользователь нажимает кнопку "Назад к напоминанию", THEN система ДОЛЖНА отобразить короткое сообщение напоминания
2. WHEN система отображает короткое сообщение напоминания, THEN время события ДОЛЖНО быть отформатировано в timezone пользователя
3. WHEN система обрабатывает возврат к напоминанию, THEN система НЕ ДОЛЖНА генерировать `LazyInitializationException`
4. WHEN система форматирует короткое сообщение, THEN формат сообщения ДОЛЖЕН соответствовать типу напоминания (EVENING_BEFORE, ONE_HOUR_BEFORE, FIFTEEN_MINUTES_BEFORE)

### Требование 4: Обработка ошибок при форматировании

**User Story:** Как разработчик, я хочу корректно обрабатывать ошибки при форматировании напоминаний, чтобы пользователь всегда получал сообщение, даже если произошла ошибка.

#### Критерии приемки

1. WHEN происходит ошибка при форматировании времени, THEN система ДОЛЖНА использовать fallback формат с базовым сообщением
2. WHEN система использует fallback формат, THEN сообщение ДОЛЖНО содержать название события
3. WHEN система обрабатывает ошибку, THEN ошибка ДОЛЖНА быть залогирована с уровнем ERROR
4. WHEN система использует fallback формат, THEN пользователь НЕ ДОЛЖЕН видеть техническую ошибку
