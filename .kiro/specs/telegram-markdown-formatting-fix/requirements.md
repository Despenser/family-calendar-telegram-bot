# Документ требований: Исправление markdown-форматирования в сообщениях Telegram бота

## Введение

Данный документ описывает требования к исправлению проблемы с отображением markdown-форматирования в сообщениях Telegram бота при создании событий. В настоящее время текст отображается без форматирования и переносов строк, что ухудшает читаемость и пользовательский опыт.

## Глоссарий

- **MarkdownV2**: Формат разметки текста, поддерживаемый Telegram Bot API для форматирования сообщений (жирный текст, курсив, моноширинный шрифт и т.д.)
- **MarkdownFormatter**: Утилитный класс для экранирования специальных символов MarkdownV2
- **TelegramMessageService**: Сервис для отправки сообщений через Telegram Bot API
- **UpdateProcessor**: Сервис для обработки входящих обновлений от пользователей
- **Экранирование**: Процесс добавления обратного слеша перед специальными символами MarkdownV2

## Требования

### Требование 1: Корректное форматирование заголовков

**User Story:** Как пользователь, я хочу видеть заголовки сообщений выделенными жирным шрифтом, чтобы легко различать разделы сообщения.

#### Критерии приемки

1. WHEN бот отправляет сообщение с заголовком "Создание нового события", THEN заголовок SHALL быть отформатирован жирным шрифтом с использованием MarkdownV2
2. WHEN заголовок содержит эмодзи, THEN эмодзи SHALL отображаться корректно без экранирования
3. WHEN заголовок форматируется, THEN все специальные символы MarkdownV2 в тексте заголовка SHALL быть корректно экранированы

### Требование 2: Переносы строк между секциями

**User Story:** Как пользователь, я хочу видеть четкое разделение между секциями сообщения, чтобы легко читать информацию.

#### Критерии приемки

1. WHEN бот отправляет многострочное сообщение, THEN между секциями SHALL быть двойные переносы строк (\n\n)
2. WHEN сообщение содержит заголовок и контент, THEN между ними SHALL быть двойной перенос строки
3. WHEN сообщение содержит несколько элементов информации, THEN между ними SHALL быть двойные переносы строк

### Требование 3: Корректное экранирование специальных символов

**User Story:** Как разработчик, я хочу, чтобы все специальные символы MarkdownV2 корректно экранировались, чтобы избежать ошибок парсинга при отправке сообщений.

#### Критерии приемки

1. WHEN текст содержит специальные символы MarkdownV2 (_ * [ ] ( ) ~ \` > # + - = | { } . !), THEN они SHALL быть экранированы обратным слешем
2. WHEN используется метод formatMessage, THEN он SHALL автоматически экранировать все специальные символы в результате форматирования
3. WHEN текст содержит эмодзи, THEN эмодзи SHALL НЕ экранироваться

### Требование 4: Использование MarkdownFormatter для форматирования

**User Story:** Как разработчик, я хочу использовать централизованную утилиту для форматирования текста, чтобы обеспечить консистентность форматирования во всем приложении.

#### Критерии приемки

1. WHEN необходимо отформатировать текст жирным шрифтом, THEN SHALL использоваться метод MarkdownFormatter.bold()
2. WHEN необходимо экранировать специальные символы, THEN SHALL использоваться метод MarkdownFormatter.escape() или MarkdownFormatter.formatMessage()
3. WHEN форматируется сообщение с параметрами, THEN SHALL использоваться метод MarkdownFormatter.formatMessage()

### Требование 5: Корректное отображение информации о событии

**User Story:** Как пользователь, я хочу видеть информацию о создаваемом событии в структурированном виде, чтобы легко проверить введенные данные.

#### Критерии приемки

1. WHEN отображается название события, THEN перед ним SHALL быть эмодзи галочки (✅) и текст "Название:"
2. WHEN отображается описание события, THEN перед ним SHALL быть эмодзи галочки (✅) и текст "Описание:"
3. WHEN отображается дата события, THEN перед ней SHALL быть эмодзи галочки (✅) и текст "Дата:"
4. WHEN отображается время события, THEN перед ним SHALL быть эмодзи галочки (✅) и текст "Время:"
5. WHEN отображается несколько элементов информации, THEN каждый элемент SHALL быть на отдельной строке с одинарным переносом

### Требование 6: Обработка ошибок форматирования

**User Story:** Как разработчик, я хочу, чтобы система корректно обрабатывала ошибки форматирования, чтобы пользователи всегда получали сообщения, даже если форматирование не удалось.

#### Критерии приемки

1. WHEN возникает ошибка парсинга MarkdownV2 (400 Bad Request), THEN система SHALL автоматически переключиться на отправку без форматирования (plain text)
2. WHEN происходит fallback на plain text, THEN система SHALL записать метрику "markdown_parse_error_fallback"
3. WHEN происходит fallback на plain text, THEN система SHALL залогировать предупреждение с деталями ошибки

### Требование 7: Тестирование форматирования

**User Story:** Как разработчик, я хочу иметь автоматические тесты для проверки корректности форматирования, чтобы предотвратить регрессии.

#### Критерии приемки

1. WHEN создается тест для форматирования сообщения, THEN он SHALL проверять наличие жирного форматирования заголовка
2. WHEN создается тест для форматирования сообщения, THEN он SHALL проверять наличие переносов строк между секциями
3. WHEN создается тест для форматирования сообщения, THEN он SHALL проверять корректное экранирование специальных символов
4. WHEN создается тест для форматирования сообщения, THEN он SHALL проверять корректное отображение эмодзи
