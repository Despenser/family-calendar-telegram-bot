# Документ требований: Управление сообщениями в корзине

## Введение

Данный документ описывает требования к реализации механики управления сообщениями в корзине `/trash`, аналогичной механике команды `/my_events`. Цель - обеспечить единообразный пользовательский опыт при работе с событиями в корзине и активными событиями.

## Глоссарий

- **Система** - Telegram бот семейного календаря
- **Корзина** - список удаленных событий, доступный по команде `/trash`
- **Событие** - запись в календаре с датой, временем и описанием
- **Шапка** - заголовочное сообщение со счетчиком событий
- **Сообщение события** - Telegram сообщение, отображающее информацию о событии
- **MessageId** - уникальный идентификатор сообщения в Telegram
- **Inline-кнопки** - кнопки под сообщением для выполнения действий

## Требования

### Требование 1

**User Story:** Как пользователь, я хочу, чтобы сообщения о восстановленных или удаленных навсегда событиях исчезали из чата, чтобы корзина оставалась актуальной и не содержала устаревшей информации.

#### Acceptance Criteria

1. WHEN пользователь восстанавливает событие из корзины THEN Система SHALL удалить сообщение этого события из чата
2. WHEN пользователь удаляет событие навсегда THEN Система SHALL удалить сообщение этого события из чата
3. WHEN Система удаляет сообщение события THEN Система SHALL использовать сохраненный messageId для идентификации сообщения
4. WHEN событие восстанавливается или удаляется навсегда THEN Система SHALL НЕ отправлять дополнительные уведомления типа "♻️ Событие восстановлено" или "❌ Событие удалено навсегда"

### Требование 2

**User Story:** Как пользователь, я хочу, чтобы шапка корзины переходила ко второму событию при удалении или восстановлении первого, чтобы всегда видеть актуальный счетчик событий в корзине.

#### Acceptance Criteria

1. WHEN первое событие в корзине восстанавливается или удаляется навсегда THEN Система SHALL установить флаг isTrashHeader для второго события в корзине
2. WHEN Система устанавливает флаг isTrashHeader для нового события THEN Система SHALL сбросить флаг isTrashHeader у предыдущего события
3. WHEN Система обновляет флаг isTrashHeader THEN Система SHALL обновить сообщение нового первого события с добавлением шапки
4. WHEN в корзине остается только одно событие THEN Система SHALL установить флаг isTrashHeader для этого события

### Требование 3

**User Story:** Как пользователь, я хочу видеть стандартное сообщение "Корзина пуста", когда в корзине не остается событий, чтобы понимать текущее состояние корзины.

#### Acceptance Criteria

1. WHEN последнее событие в корзине восстанавливается или удаляется навсегда THEN Система SHALL отправить сообщение "🗑️ Корзина\n\nКорзина пуста.\n\nУдаленные события хранятся здесь 30 дней, после чего автоматически удаляются навсегда."
2. WHEN Система отправляет сообщение о пустой корзине THEN Система SHALL использовать MarkdownV2 форматирование
3. WHEN пользователь вызывает команду /trash и корзина пуста THEN Система SHALL отправить то же сообщение о пустой корзине

### Требование 4

**User Story:** Как пользователь, я хочу, чтобы при открытии корзины первое событие отображалось вместе с шапкой в одном сообщении, чтобы интерфейс был единообразным с командой /my_events.

#### Acceptance Criteria

1. WHEN пользователь вызывает команду /trash и в корзине есть события THEN Система SHALL отправить первое сообщение с объединенной шапкой и первым событием
2. WHEN Система отправляет объединенное сообщение THEN Система SHALL сохранить messageId в поле messageId первого события
3. WHEN Система отправляет объединенное сообщение THEN Система SHALL установить флаг isTrashHeader=true для первого события
4. WHEN Система отправляет остальные события THEN Система SHALL отправить их отдельными сообщениями с сохранением messageId

### Требование 5

**User Story:** Как разработчик, я хочу, чтобы в модели Event был флаг isTrashHeader, чтобы отслеживать, какое событие в корзине содержит шапку.

#### Acceptance Criteria

1. WHEN Система инициализируется THEN модель Event SHALL содержать поле isTrashHeader типа Boolean
2. WHEN создается новое событие THEN поле isTrashHeader SHALL иметь значение по умолчанию false или null
3. WHEN Система сохраняет событие с флагом isTrashHeader THEN значение SHALL сохраняться в базе данных
4. WHEN Система загружает событие из базы данных THEN значение isTrashHeader SHALL корректно восстанавливаться

### Требование 6

**User Story:** Как пользователь, я хочу, чтобы счетчик событий в шапке корзины автоматически обновлялся при изменении количества событий, чтобы всегда видеть актуальную информацию.

#### Acceptance Criteria

1. WHEN событие восстанавливается из корзины THEN Система SHALL обновить счетчик в шапке корзины
2. WHEN событие удаляется навсегда THEN Система SHALL обновить счетчик в шапке корзины
3. WHEN Система обновляет счетчик THEN Система SHALL использовать метод editMessageText Telegram API
4. WHEN обновление счетчика не удается THEN Система SHALL логировать ошибку и продолжить работу без выброса исключения
