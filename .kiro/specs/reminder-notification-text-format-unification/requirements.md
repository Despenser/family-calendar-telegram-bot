# Requirements Document

## Introduction

Унификация формата текста уведомлений о напоминаниях и удаление функционала кастомных напоминаний. Необходимо:
1. Убрать эмодзи типа события (семейное/личное) из заголовка уведомления
2. Использовать специфичные эмодзи для каждого типа напоминания
3. Удалить функционал создания кастомных напоминаний (CUSTOM)
4. Оставить только фиксированные типы: накануне, за 1 час, за 15 минут
5. Обеспечить возврат к короткой версии уведомления при нажатии "Назад к напоминанию"

## Glossary

- **Reminder_Service**: Сервис для управления напоминаниями о событиях
- **Notification_Message**: Текстовое сообщение уведомления о напоминании
- **Short_Notification**: Короткая версия уведомления, содержащая только заголовок с эмодзи и названием события
- **Full_Notification**: Полная версия уведомления, содержащая заголовок, дату, время, описание и информацию о создателе
- **Event_Type_Emoji**: Эмодзи, обозначающий тип события (👤 для персональных, 👨‍👩‍👧‍👦 для семейных)
- **Reminder_Type**: Тип напоминания (ONE_HOUR_BEFORE, FIFTEEN_MINUTES_BEFORE, EVENING_BEFORE)
- **Moon_Emoji**: Эмодзи луны 🌙, используемый для напоминаний накануне
- **Lightning_Emoji**: Эмодзи молнии ⚡, используемый для напоминаний за 1 час
- **Fire_Emoji**: Эмодзи огня 🔥, используемый для напоминаний за 15 минут
- **Custom_Reminder**: Кастомное напоминание с произвольным временем (удаляется)
- **Back_To_Reminder_Button**: Кнопка "◀️ Назад к напоминанию" для возврата к короткой версии уведомления
- **View_Details_Button**: Кнопка "📋 Посмотреть детали" для просмотра полной информации о событии

## Requirements

### Requirement 1: Специфичные эмодзи для фиксированных типов напоминаний (короткая версия)

**User Story:** Как пользователь, я хочу видеть разные эмодзи для разных типов напоминаний в короткой версии уведомления, чтобы быстро понимать, когда произойдет событие.

#### Acceptance Criteria

1. WHEN формируется короткое уведомление о напоминании за 1 час THEN THE Reminder_Service SHALL использовать формат "⚡ Напоминание: через 1 час начнется событие - {название события}"
2. WHEN формируется короткое уведомление о напоминании за 15 минут THEN THE Reminder_Service SHALL использовать формат "🔥 Напоминание: через 15 минут начнется событие - {название события}"
3. WHEN формируется короткое уведомление о напоминании накануне THEN THE Reminder_Service SHALL использовать формат "🌙 Напоминание: завтра в {время} у вас событие - {название события}"

### Requirement 2: Полная версия уведомления с эмодзи 🔔

**User Story:** Как пользователь, я хочу видеть полную информацию о событии при нажатии "Посмотреть детали" с единым форматом и эмодзи 🔔, чтобы получить все детали события.

#### Acceptance Criteria

1. WHEN пользователь нажимает "Посмотреть детали" THEN THE Reminder_Service SHALL показывать полную версию с заголовком "🔔 Напоминание о событии"
2. WHEN показывается полная версия THEN THE Reminder_Service SHALL включать название события, дату, время, описание, тип события и тип напоминания
3. WHEN показывается полная версия THEN THE Reminder_Service SHALL использовать единый формат для всех типов напоминаний
4. WHEN показывается полная версия THEN THE Reminder_Service SHALL показывать полное описание события без обрезки

### Requirement 3: Удаление функционала кастомных напоминаний

**User Story:** Как разработчик, я хочу упростить систему напоминаний, оставив только фиксированные типы, чтобы упростить поддержку и использование.

#### Acceptance Criteria

1. WHEN пользователь пытается создать кастомное напоминание THEN THE Reminder_Service SHALL НЕ предоставлять такую возможность
2. WHEN система обрабатывает напоминания THEN THE Reminder_Service SHALL поддерживать только три типа: EVENING_BEFORE, ONE_HOUR_BEFORE, FIFTEEN_MINUTES_BEFORE
3. WHEN пользователь настраивает напоминания THEN THE System SHALL предоставлять только возможность включить или выключить каждый из трех фиксированных типов
4. WHEN существуют старые кастомные напоминания в БД THEN THE System SHALL корректно обрабатывать их при миграции или удалении

### Requirement 4: Короткая версия при возврате к напоминанию

**User Story:** Как пользователь, я хочу видеть короткую версию уведомления при нажатии "Назад к напоминанию", чтобы быстро вернуться к минималистичному виду напоминания.

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "Назад к напоминанию" THEN THE System SHALL отображать короткую версию уведомления с заголовком в формате "{эмодзи} Напоминание: {текст времени} - {название события}"
2. WHEN отображается короткая версия уведомления THEN THE System SHALL НЕ включать дату, время, описание и информацию о создателе
3. WHEN отображается короткая версия уведомления для напоминания за 1 час THEN THE System SHALL использовать текст "⚡ Напоминание: через 1 час начнется событие - {название события}"
4. WHEN отображается короткая версия уведомления для напоминания за 15 минут THEN THE System SHALL использовать текст "🔥 Напоминание: через 15 минут начнется событие - {название события}"
5. WHEN отображается короткая версия уведомления для напоминания накануне THEN THE System SHALL использовать текст "🌙 Напоминание: завтра в {время} у вас событие - {название события}"
6. WHEN отображается короткая версия уведомления THEN THE System SHALL сохранять клавиатуру с кнопкой "📋 Посмотреть детали"

### Requirement 5: Обратная совместимость

**User Story:** Как разработчик, я хочу сохранить существующую функциональность уведомлений, чтобы не нарушить работу системы.

#### Acceptance Criteria

1. WHEN изменяется формат уведомлений THEN THE Reminder_Service SHALL сохранять существующую логику отправки уведомлений
2. WHEN изменяется формат уведомлений THEN THE Reminder_Service SHALL сохранять существующую логику работы с timezone
3. WHEN изменяется формат уведомлений THEN THE Reminder_Service SHALL сохранять существующую логику обработки ошибок
4. WHEN изменяется формат уведомлений THEN THE Reminder_Service SHALL сохранять существующую клавиатуру с кнопкой "Посмотреть детали"
