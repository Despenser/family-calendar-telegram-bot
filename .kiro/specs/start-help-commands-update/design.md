# Дизайн: Актуализация команд /start и /help

## Overview

Данный дизайн описывает актуализацию команд /start и /help для отражения полного функционала Семейного Календаря Бота. Основные изменения включают:

- Добавление всех новых команд (/today, /week, /search, /filter, /stats, /trash)
- Организацию команд по функциональным категориям
- Обновление описаний команд
- Сохранение приоритета команды /add_event
- Улучшение форматирования и читаемости

## Architecture

Архитектура решения основана на существующей структуре обработчиков команд:

```
StartCommandHandler
├── buildWelcomeMessageForRegisteredUser()
│   └── Формирует приветствие с основными командами
└── buildWelcomeMessageForUnregisteredUser()
    └── Формирует приветствие для незарегистрированных

HelpCommandHandler
├── buildCommandsList()
│   ├── Получает все CommandHandler из Spring контекста
│   ├── Группирует команды по категориям
│   └── Форматирует с учетом авторизации
├── buildHelpMessage()
│   └── Формирует полное сообщение справки
└── getCommandEmoji()
    └── Возвращает эмодзи для команды
```

Изменения не затрагивают базовую архитектуру, только содержимое сообщений и логику группировки.

## Correctness Properties


*A property is a characteristic or behavior that should hold true across all valid executions of a system-essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Все команды присутствуют в выводе /help

*For any* набор зарегистрированных CommandHandler, вывод метода buildCommandsList должен содержать все команды из этого набора (кроме /start).

**Validates: Requirements 1.1**

**Обоснование:** Это свойство гарантирует, что пользователь увидит полный список доступных команд, что критично для обнаружения функционала.

### Property 2: Команды группируются по категориям

*For any* набор команд, вывод /help должен содержать заголовки всех категорий, к которым принадлежат эти команды, и команды должны следовать после заголовка своей категории.

**Validates: Requirements 1.2**

**Обоснование:** Группировка улучшает читаемость и помогает пользователям быстро находить нужные команды.

### Property 3: Команды с авторизацией помечены замком для неавторизованных

*For any* команда, требующая авторизации (requiresAuth=true), при вызове buildCommandsList с isAuthorized=false, эта команда должна быть помечена эмодзи "🔒".

**Validates: Requirements 1.3**

**Обоснование:** Визуальная индикация помогает пользователям понять, какие команды требуют регистрации.

### Property 4: Авторизованные пользователи не видят замки

*For any* набор команд, при вызове buildCommandsList с isAuthorized=true, ни одна команда не должна содержать эмодзи "🔒".

**Validates: Requirements 1.4**

**Обоснование:** Авторизованным пользователям не нужны индикаторы ограничений, так как у них есть доступ ко всем командам.

### Property 5: Команды в кликабельном формате

*For any* вывод команд (в /help или /start), команды не должны содержать backticks (`) или моноширинное форматирование, чтобы оставаться кликабельными в Telegram.

**Validates: Requirements 1.5, 3.5**

**Обоснование:** Кликабельные команды улучшают UX, позволяя пользователям быстро выполнять команды одним нажатием.

### Property 6: Все категории представлены в /start

*For any* вывод команды /start для зарегистрированного пользователя, должна присутствовать хотя бы одна команда из каждой категории (VIEW_EVENTS, MANAGE_EVENTS, SEARCH_FILTER, STATS_TRASH).

**Validates: Requirements 3.2**

**Обоснование:** Представленность всех категорий дает пользователю полное представление о возможностях бота.

### Property 7: Корректное экранирование MarkdownV2

*For any* строка с специальными символами MarkdownV2 (_, *, [, ], (, ), ~, `, >, #, +, -, =, |, {, }, ., !), после применения метода escape() все эти символы должны быть экранированы обратным слэшем.

**Validates: Requirements 6.1, 6.2**

**Обоснование:** Корректное экранирование предотвращает ошибки форматирования и обеспечивает правильное отображение текста.

### Property 8: Корректное форматирование заголовков и текста

*For any* сообщение, содержащее заголовки и вспомогательный текст, заголовки должны быть обернуты в bold форматирование (*текст*), а вспомогательный текст - в italic форматирование (_текст_).

**Validates: Requirements 6.3, 6.4**

**Обоснование:** Правильное форматирование улучшает читаемость и визуальную иерархию информации.

### Property 9: Эмодзи не нарушают форматирование

*For any* сообщение, содержащее эмодзи и MarkdownV2 форматирование, эмодзи не должны вызывать ошибки парсинга или нарушать форматирование окружающего текста.

**Validates: Requirements 6.5**

**Обоснование:** Эмодзи широко используются для улучшения UX, и они должны корректно работать с форматированием.

## Error Handling

### Ошибки форматирования MarkdownV2

**Проблема:** Неправильное экранирование специальных символов может привести к ошибке 400 от Telegram API.

**Решение:**
- Использовать централизованные методы escape(), bold(), italic() из MarkdownFormatter
- Все пользовательские данные должны проходить через escape()
- Тестировать с различными специальными символами

### Отсутствие команд

**Проблема:** Если список CommandHandler пуст, пользователь не увидит команд.

**Решение:**
- Добавить проверку на пустой список
- Вернуть информативное сообщение об отсутствии команд
- Логировать предупреждение для мониторинга

### Неизвестная категория команды

**Проблема:** Новая команда может не иметь маппинга на категорию.

**Решение:**
- Использовать категорию по умолчанию (HELP)
- Логировать предупреждение о неизвестной команде
- Добавить документацию о необходимости регистрации категории

### Обратная совместимость

Изменения не нарушают обратную совместимость:
- Интерфейс CommandHandler не изменяется
- Публичные методы StartCommandHandler и HelpCommandHandler сохраняют сигнатуры
- Изменяется только содержимое сообщений

### Производительность

Группировка команд добавляет O(n) операций, где n - количество команд. При текущем количестве команд (11) это незначительно.

### Локализация

Все тексты на русском языке в соответствии с требованиями проекта. При необходимости добавления других языков потребуется:
- Вынести тексты в ресурсные файлы
- Добавить поддержку локализации в MarkdownFormatter
- Обновить тесты для проверки всех языков
