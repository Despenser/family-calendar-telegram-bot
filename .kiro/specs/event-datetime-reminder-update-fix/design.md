# Design Document

## Overview

Данный документ описывает проектное решение для устранения проблемы дублирования уведомлений о событиях. Проблема вызвана тем, что метод отправки напоминаний вызывается дважды каждую минуту из-за дублирования аннотаций `@Scheduled`. Дополнительно, метод обновления напоминаний при изменении даты/времени события работает некорректно.

Решение включает:
1. Удаление дублирующей аннотации `@Scheduled` из `ReminderService.sendReminders()`
2. Рефакторинг метода `recalculateReminders` для удаления и пересоздания напоминаний вместо их обновления
3. Улучшение логирования для диагностики проблем

## Architecture

### Текущая архитектура (проблемная)

```
┌─────────────────────────────────────┐
│   Spring Scheduler                  │
│                                     │
│  Каждую минуту (fixedRate=60000):  │
│                                     │
│  1. ReminderService.sendReminders() │ ← @Scheduled
│     └─> Отправка напоминаний        │
│                                     │
│  2. ReminderScheduler.check...()    │ ← @Scheduled
│     └─> reminderService.sendReminders()
│         └─> Отправка напоминаний    │ ← ДУБЛИКАТ!
│                                     │
└─────────────────────────────────────┘
```

### Целевая архитектура (исправленная)

```
┌─────────────────────────────────────┐
│   Spring Scheduler                  │
│                                     │
│  Каждую минуту (fixedRate=60000):  │
│                                     │
│  ReminderScheduler.check...()       │ ← @Scheduled (единственный)
│  └─> reminderService.sendReminders()│
│      └─> Отправка напоминаний       │
│                                     │
└─────────────────────────────────────┘
```

## Components and Interfaces

### 1. ReminderService

**Изменения:**
- Удалить аннотацию `@Scheduled` из метода `sendReminders()`
- Рефакторинг метода `recalculateReminders()` для удаления и пересоздания напоминаний

**Методы:**

```java
// Удалить @Scheduled отсюда!
public void sendReminders() {
    // Существующая логика отправки напоминаний
    // Вызывается только из ReminderScheduler
}

// Рефакторинг этого метода
public void recalculateReminders(Long eventId) {
    // 1. Получить событие
    // 2. Получить все неотправленные напоминания
    // 3. Сохранить типы и параметры напоминаний
    // 4. Удалить все неотправленные напоминания
    // 5. Пересоздать напоминания с новыми временами
    // 6. Логирование всех операций
}
```

### 2. ReminderScheduler

**Изменения:**
- Оставить аннотацию `@Scheduled` только здесь
- Добавить дополнительное логирование

**Методы:**

```java
@Scheduled(fixedRate = 60000) // Единственный @Scheduled для напоминаний
public void checkAndSendReminders() {
    log.debug("Запуск планировщика напоминаний");
    
    try {
        reminderService.sendReminders();
        log.debug("Планировщик напоминаний завершил работу");
    } catch (Exception e) {
        log.error("Ошибка при выполнении планировщика напоминаний: {}", e.getMessage(), e);
    }
}
```

### 3. EventService

**Изменения:**
- Метод `handleEventDateTimeChange()` остается без изменений
- Он уже корректно вызывает `reminderService.recalculateReminders()`

## Correctness Properties

*Свойство корректности (correctness property) — это характеристика или поведение, которое должно выполняться для всех допустимых выполнений системы. По сути, это формальное утверждение о том, что система должна делать. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Property 1: Единственный планировщик отправки

*For any* момент времени, в системе должен существовать ровно один активный планировщик с аннотацией `@Scheduled` для отправки напоминаний.

**Validates: Requirements 1.1, 1.2, 1.4**

### Property 2: Отправка напоминания один раз

*For any* напоминание с `sent=false` и `reminder_time <= now`, оно должно быть отправлено ровно один раз в течение одной минуты.

**Validates: Requirements 1.5**

### Property 3: Удаление старых напоминаний при обновлении

*For any* событие, при изменении его даты или времени, все неотправленные напоминания должны быть удалены перед созданием новых.

**Validates: Requirements 2.1, 3.1**

### Property 4: Сохранение типов напоминаний при обновлении

*For any* событие с напоминаниями, при изменении даты/времени события, типы напоминаний (MORNING_OF_DAY, ONE_HOUR_BEFORE и т.д.) должны сохраниться.

**Validates: Requirements 2.3, 3.3**

### Property 5: Пропуск напоминаний в прошлом

*For any* напоминание, если его рассчитанное время оказывается в прошлом, оно не должно быть создано.

**Validates: Requirements 2.4, 3.4**

### Property 6: Отсутствие дублированных напоминаний

*For any* событие, после завершения операции обновления напоминаний, в базе данных не должно существовать дублированных напоминаний (с одинаковыми event_id, reminder_type, custom_minutes).

**Validates: Requirements 2.5, 3.5**

### Property 7: Атомарность операции обновления

*For any* операция обновления напоминаний, удаление старых и создание новых напоминаний должны выполняться в одной транзакции.

**Validates: Requirements 4.1**

### Property 8: Откат при ошибке

*For any* операция обновления напоминаний, если происходит ошибка при создании новых напоминаний, удаление старых напоминаний должно быть откачено.

**Validates: Requirements 4.2**

## Error Handling

### 1. Ошибки при отправке напоминаний

**Текущее поведение:** Корректное - используются блокировки и обработка исключений.

**Изменения:** Не требуются.

### 2. Ошибки при обновлении напоминаний

**Текущее поведение:** Ошибки логируются, но транзакция может быть частично выполнена.

**Новое поведение:**
- Использовать `@Transactional` для атомарности
- При ошибке создания новых напоминаний откатывать удаление старых
- Логировать детали ошибки с уровнем ERROR

### 3. Ошибки при отсутствии напоминаний

**Текущее поведение:** Метод завершается без ошибок.

**Новое поведение:** Сохранить текущее поведение, добавить логирование DEBUG.

## Implementation Notes

### Порядок изменений

1. **Удалить @Scheduled из ReminderService.sendReminders()**
   - Это самое критичное изменение
   - Сразу устранит проблему дублирования

2. **Рефакторинг recalculateReminders()**
   - Добавить метод для сохранения информации о напоминаниях
   - Добавить метод для удаления старых напоминаний
   - Добавить метод для создания новых напоминаний
   - Обернуть все в `@Transactional`

3. **Улучшить логирование**
   - Добавить логи в начале и конце каждой операции
   - Логировать количество удаленных/созданных напоминаний
   - Логировать типы напоминаний

### Обратная совместимость

Все изменения обратно совместимы:
- API методов не меняется
- Структура БД не меняется
- Поведение для пользователей улучшается (меньше дубликатов)

### Производительность

Изменения не должны повлиять на производительность:
- Удаление `@Scheduled` уменьшает нагрузку (меньше вызовов)
- Рефакторинг `recalculateReminders` может немного увеличить время выполнения, но это редкая операция
- Использование транзакций добавляет небольшой overhead, но гарантирует консистентность

### Миграция

Миграция БД не требуется - все изменения только в коде.
