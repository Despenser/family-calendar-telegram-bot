# Requirements Document

## Introduction

Пользователи получают дублированные уведомления о событиях. Проблема вызвана тем, что метод отправки напоминаний `ReminderService.sendReminders()` вызывается дважды каждую минуту:

1. **Прямой вызов через @Scheduled**: Метод `ReminderService.sendReminders()` имеет аннотацию `@Scheduled(fixedRate = 60000)`, что запускает его каждую минуту.

2. **Вызов через ReminderScheduler**: Класс `ReminderScheduler.checkAndSendReminders()` также имеет аннотацию `@Scheduled(fixedRate = 60000)` и вызывает `reminderService.sendReminders()`.

Это приводит к тому, что каждое напоминание отправляется дважды в течение одной минуты. Хотя в коде есть механизм блокировок для предотвращения дублирования, он не всегда срабатывает корректно при одновременном выполнении двух планировщиков.

Дополнительно, при изменении даты/времени события метод `recalculateReminders` обновляет существующие напоминания вместо их пересоздания, что может приводить к проблемам при изменении даты/времени события.

## Glossary

- **System**: Система управления напоминаниями о событиях
- **Reminder**: Напоминание о событии с определенным временем отправки
- **Event**: Событие в календаре с датой и временем
- **ReminderService**: Сервис для управления напоминаниями
- **EventService**: Сервис для управления событиями
- **Scheduler**: Планировщик, который отправляет напоминания по расписанию

## Requirements

### Requirement 1: Устранение дублирования планировщиков отправки напоминаний

**User Story:** Как пользователь, я хочу получать только одно уведомление для каждого напоминания, чтобы не получать спам-сообщения.

#### Acceptance Criteria

1. WHEN система запускается THEN THE System SHALL иметь только один активный планировщик для отправки напоминаний
2. WHEN наступает время отправки напоминаний THEN THE System SHALL вызвать метод sendReminders только один раз в минуту
3. WHEN метод sendReminders выполняется THEN THE System SHALL не иметь аннотации @Scheduled на самом методе
4. WHEN ReminderScheduler запускается THEN THE System SHALL быть единственным компонентом с аннотацией @Scheduled для отправки напоминаний
5. WHEN напоминание отправлено THEN THE System SHALL гарантировать, что оно не будет отправлено повторно в течение той же минуты

### Requirement 2: Корректное обновление напоминаний при изменении даты события

**User Story:** Как пользователь, я хочу, чтобы при изменении даты события все напоминания обновлялись корректно, чтобы я не получал дублированные или неправильные уведомления.

#### Acceptance Criteria

1. WHEN пользователь изменяет дату события THEN THE System SHALL удалить все существующие неотправленные напоминания для этого события
2. WHEN пользователь изменяет дату события THEN THE System SHALL пересчитать и создать новые напоминания с учетом новой даты
3. WHEN пользователь изменяет дату события THEN THE System SHALL сохранить типы напоминаний (MORNING_OF_DAY, ONE_HOUR_BEFORE и т.д.)
4. WHEN новое время напоминания оказывается в прошлом THEN THE System SHALL пропустить создание такого напоминания
5. WHEN изменение даты события завершено THEN THE System SHALL гарантировать отсутствие дублированных напоминаний

### Requirement 3: Корректное обновление напоминаний при изменении времени события

**User Story:** Как пользователь, я хочу, чтобы при изменении времени события все напоминания обновлялись корректно, чтобы я получал уведомления в правильное время.

#### Acceptance Criteria

1. WHEN пользователь изменяет время события THEN THE System SHALL удалить все существующие неотправленные напоминания для этого события
2. WHEN пользователь изменяет время события THEN THE System SHALL пересчитать и создать новые напоминания с учетом нового времени
3. WHEN пользователь изменяет время события THEN THE System SHALL сохранить типы напоминаний и их параметры (customMinutes для CUSTOM типа)
4. WHEN новое время напоминания оказывается в прошлом THEN THE System SHALL пропустить создание такого напоминания
5. WHEN изменение времени события завершено THEN THE System SHALL гарантировать, что каждое напоминание существует в единственном экземпляре

### Requirement 4: Атомарность операции обновления напоминаний

**User Story:** Как разработчик, я хочу, чтобы операция обновления напоминаний была атомарной, чтобы избежать race conditions и несогласованного состояния данных.

#### Acceptance Criteria

1. WHEN происходит обновление напоминаний THEN THE System SHALL выполнить удаление старых и создание новых напоминаний в одной транзакции
2. WHEN происходит ошибка при создании новых напоминаний THEN THE System SHALL откатить удаление старых напоминаний
3. WHEN происходит обновление напоминаний THEN THE System SHALL использовать блокировку для предотвращения одновременного изменения напоминаний события

### Requirement 5: Логирование операций обновления напоминаний

**User Story:** Как администратор системы, я хочу видеть подробные логи операций обновления напоминаний, чтобы отслеживать проблемы и диагностировать ошибки.

#### Acceptance Criteria

1. WHEN начинается обновление напоминаний THEN THE System SHALL залогировать eventId, старую дату/время и новую дату/время
2. WHEN удаляются старые напоминания THEN THE System SHALL залогировать количество удаленных напоминаний и их типы
3. WHEN создаются новые напоминания THEN THE System SHALL залогировать количество созданных напоминаний и их времена отправки
4. WHEN напоминание пропускается из-за времени в прошлом THEN THE System SHALL залогировать причину пропуска с уровнем WARN
5. WHEN происходит ошибка при обновлении напоминаний THEN THE System SHALL залогировать детали ошибки с уровнем ERROR

### Requirement 6: Обработка edge cases при обновлении напоминаний

**User Story:** Как пользователь, я хочу, чтобы система корректно обрабатывала все граничные случаи при обновлении напоминаний, чтобы избежать неожиданного поведения.

#### Acceptance Criteria

1. WHEN событие не имеет напоминаний THEN THE System SHALL корректно завершить операцию обновления без ошибок
2. WHEN все новые времена напоминаний оказываются в прошлом THEN THE System SHALL удалить старые напоминания и не создавать новые
3. WHEN событие не имеет даты или времени THEN THE System SHALL залогировать предупреждение и пропустить обновление напоминаний
4. WHEN происходит изменение даты/времени события, у которого уже были отправлены некоторые напоминания THEN THE System SHALL обновить только неотправленные напоминания
5. WHEN пользователь изменяет дату/время события несколько раз подряд THEN THE System SHALL корректно обрабатывать каждое изменение без накопления дублированных напоминаний
