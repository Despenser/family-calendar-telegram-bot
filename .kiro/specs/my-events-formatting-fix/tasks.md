# План реализации: Исправление форматирования списка активных событий

## Обзор

Данный план описывает задачи для исправления форматирования вывода списка активных событий в команде `/my_events`. Основная цель - объединить заголовок и первое событие в одном сообщении, как это реализовано в команде `/trash`.

## Задачи

- [x] 1. Рефакторинг метода handle() в MyEventsCommandHandler
  - Извлечь логику формирования заголовка в отдельный метод `buildHeader(int eventCount)`
  - Изменить логику отправки первого события: объединить заголовок и первое событие в одном сообщении
  - Добавить обработку ошибок при отправке объединенного сообщения с fallback механизмом
  - Обеспечить отправку остальных событий отдельными сообщениями (существующая логика)
  - _Requirements: 1.1, 1.2, 2.1, 2.2, 2.3, 4.1, 4.2, 4.3_

- [ ]* 1.1 Написать unit-тесты для нового поведения
  - Тест для пустого списка событий (проверка сообщения об отсутствии событий)
  - Тест для одного события (проверка объединения заголовка и события)
  - Тест для нескольких событий (проверка объединения заголовка с первым событием и отдельной отправки остальных)
  - Тест для fallback механизма при ошибке MarkdownV2
  - _Requirements: 1.1, 1.2, 1.3, 4.1, 4.2_

- [x] 2. Checkpoint - Проверка работоспособности
  - Убедиться, что все тесты проходят
  - Проверить логирование ошибок
  - Спросить пользователя, если возникли вопросы

- [x] 3. Обновление документации в коде
  - Обновить JavaDoc для метода `handle()` с описанием нового поведения
  - Добавить JavaDoc для нового метода `buildHeader()`
  - Обновить примеры в комментариях класса
  - _Requirements: 1.1, 2.1_

## Примечания

- Задачи, помеченные `*`, являются опциональными и могут быть пропущены для более быстрого MVP
- Каждая задача ссылается на конкретные требования для отслеживаемости
- Checkpoint обеспечивает инкрементальную валидацию
- Изменения минимальны и затрагивают только один класс
