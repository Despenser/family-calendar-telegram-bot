# Документ требований: Реорганизация скриптов запуска

## Введение

Проект содержит несколько скриптов для управления Docker Compose (запуск, остановка, просмотр логов, очистка), которые в настоящее время находятся в корне проекта. Необходимо реорганизовать структуру, переместив все скрипты в отдельную директорию `scripts` с подпапками для разных операционных систем, чтобы улучшить организацию проекта и упростить навигацию.

## Глоссарий

- **Скрипт запуска**: Исполняемый файл (.sh или .bat), который автоматизирует операции с Docker Compose
- **Корневая директория**: Главная папка проекта, где находится pom.xml и docker-compose.yml
- **scripts**: Новая директория для хранения всех скриптов управления проектом
- **windows**: Поддиректория в scripts для .bat файлов (Windows)
- **unix**: Поддиректория в scripts для .sh файлов (Linux/macOS)

## Требования

### Требование 1

**User Story:** Как разработчик, я хочу иметь организованную структуру скриптов в отдельной папке, чтобы корень проекта был чище и понятнее.

#### Критерии приёмки

1. WHEN система создаёт новую структуру THEN система SHALL создать директорию `scripts` в корне проекта
2. WHEN система создаёт новую структуру THEN система SHALL создать поддиректорию `scripts/windows` для Windows скриптов
3. WHEN система создаёт новую структуру THEN система SHALL создать поддиректорию `scripts/unix` для Unix скриптов
4. WHEN система перемещает скрипты THEN система SHALL переместить все .bat файлы в `scripts/windows`
5. WHEN система перемещает скрипты THEN система SHALL переместить все .sh файлы в `scripts/unix`

### Требование 2

**User Story:** Как разработчик, я хочу, чтобы скрипты продолжали работать после перемещения, чтобы не нарушить существующую функциональность.

#### Критерии приёмки

1. WHEN скрипт выполняется из новой локации THEN система SHALL корректно находить docker-compose.yml в корне проекта
2. WHEN скрипт выполняется из новой локации THEN система SHALL корректно находить .env файл в корне проекта
3. WHEN скрипт выполняется из новой локации THEN система SHALL выполнять все docker-compose команды относительно корня проекта
4. WHEN скрипт содержит относительные пути THEN система SHALL обновить эти пути для работы из новой локации

### Требование 3

**User Story:** Как разработчик, я хочу иметь обновлённую документацию, чтобы знать, как использовать скрипты из новой локации.

#### Критерии приёмки

1. WHEN документация обновляется THEN система SHALL обновить README.md с новыми путями к скриптам
2. WHEN документация обновляется THEN система SHALL указать правильные команды запуска для Windows (scripts\windows\start.bat)
3. WHEN документация обновляется THEN система SHALL указать правильные команды запуска для Unix (scripts/unix/start.sh)
4. WHEN пользователь читает документацию THEN система SHALL предоставить примеры использования всех скриптов из новой локации

### Требование 4

**User Story:** Как разработчик, я хочу удалить старые скрипты из корня, чтобы избежать путаницы и дублирования.

#### Критерии приёмки

1. WHEN новые скрипты созданы и протестированы THEN система SHALL удалить clean.bat из корня проекта
2. WHEN новые скрипты созданы и протестированы THEN система SHALL удалить clean.sh из корня проекта
3. WHEN новые скрипты созданы и протестированы THEN система SHALL удалить logs.bat из корня проекта
4. WHEN новые скрипты созданы и протестированы THEN система SHALL удалить logs.sh из корня проекта
5. WHEN новые скрипты созданы и протестированы THEN система SHALL удалить start.bat из корня проекта
6. WHEN новые скрипты созданы и протестированы THEN система SHALL удалить start.sh из корня проекта
7. WHEN новые скрипты созданы и протестированы THEN система SHALL удалить stop.bat из корня проекта
8. WHEN новые скрипты созданы и протестированы THEN система SHALL удалить stop.sh из корня проекта
