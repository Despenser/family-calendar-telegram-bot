# Документ требований: Завершение реализации функционала вложений к событиям

## Введение

Данный документ описывает требования к завершению реализации функционала работы с вложениями к событиям в Telegram-боте семейного календаря. Частичная реализация уже существует (модель Attachment, сервис AttachmentService, репозиторий AttachmentRepository), но отсутствует пользовательский интерфейс и интеграция с основным потоком работы бота.

Функционал вложений позволяет пользователям прикреплять файлы (документы, фотографии, видео, аудио) к событиям календаря для хранения связанной информации, такой как билеты, документы, изображения и другие материалы.

## Глоссарь

- **System** - Telegram-бот семейного календаря
- **User** - пользователь бота, авторизованный в системе
- **Event** - событие в календаре
- **Attachment** - вложение (файл), прикрепленное к событию
- **Event_Creator** - пользователь, создавший событие
- **File_Types** - поддерживаемые типы файлов: document, photo, video, audio
- **Telegram_File_ID** - уникальный идентификатор файла в Telegram API
- **Attachment_List** - список вложений события
- **Event_Card** - карточка события с информацией и кнопками управления
- **Callback_Handler** - обработчик callback-запросов от inline-кнопок
- **Update_Processor** - процессор обновлений от Telegram API
- **Conversation_State** - состояние диалога пользователя с ботом
- **Max_File_Size** - максимальный размер файла 20 МБ

## Требования

### Требование 1: Доступ к функционалу вложений

**User Story:** Как пользователь, я хочу видеть кнопку "📎 Вложения" в карточке события, чтобы иметь доступ к функционалу управления вложениями.

#### Acceptance Criteria

1. WHEN пользователь просматривает карточку события, THE System SHALL отображать кнопку "📎 Вложения" в inline-клавиатуре
2. WHEN пользователь нажимает кнопку "📎 Вложения", THE System SHALL отображать список вложений события или сообщение об отсутствии вложений
3. WHERE событие имеет вложения, THE System SHALL отображать количество вложений в формате "📎 Вложения (N)"

### Требование 2: Загрузка файлов

**User Story:** Как создатель события, я хочу загружать файлы к событию, чтобы хранить связанную с событием информацию.

#### Acceptance Criteria

1. WHEN Event_Creator нажимает кнопку "➕ Добавить файл" в списке вложений, THE System SHALL перевести пользователя в режим ожидания файла
2. WHEN пользователь в режиме ожидания файла отправляет файл типа document, THE System SHALL сохранить вложение с типом "document"
3. WHEN пользователь в режиме ожидания файла отправляет фотографию, THE System SHALL сохранить вложение с типом "photo"
4. WHEN пользователь в режиме ожидания файла отправляет видео, THE System SHALL сохранить вложение с типом "video"
5. WHEN пользователь в режиме ожидания файла отправляет аудио, THE System SHALL сохранить вложение с типом "audio"
6. WHEN файл успешно сохранен, THE System SHALL отобразить подтверждающее сообщение с информацией о файле
7. WHEN файл успешно сохранен, THE System SHALL очистить состояние ожидания файла

### Требование 3: Валидация размера файла

**User Story:** Как система, я должна проверять размер загружаемых файлов, чтобы предотвратить загрузку слишком больших файлов.

#### Acceptance Criteria

1. WHEN пользователь отправляет файл размером более Max_File_Size, THE System SHALL отклонить загрузку
2. WHEN загрузка отклонена из-за размера, THE System SHALL отобразить сообщение с указанием фактического размера файла и лимита
3. WHEN пользователь отправляет файл размером менее или равным Max_File_Size, THE System SHALL принять файл для сохранения

### Требование 4: Отображение списка вложений

**User Story:** Как пользователь, я хочу видеть список всех вложений события, чтобы знать какие файлы прикреплены.

#### Acceptance Criteria

1. WHEN пользователь открывает список вложений, THE System SHALL отобразить все вложения события, отсортированные по дате загрузки
2. WHEN отображается вложение, THE System SHALL показать имя файла, тип файла и размер файла
3. WHEN отображается вложение, THE System SHALL показать дату и время загрузки
4. WHERE событие не имеет вложений, THE System SHALL отобразить сообщение "У этого события пока нет вложений"
5. WHERE пользователь является Event_Creator, THE System SHALL отобразить кнопку "➕ Добавить файл"

### Требование 5: Просмотр вложения

**User Story:** Как пользователь, я хочу просматривать прикрепленные файлы, чтобы получить доступ к сохраненной информации.

#### Acceptance Criteria

1. WHEN пользователь нажимает на вложение в списке, THE System SHALL отправить файл пользователю через Telegram API
2. WHEN файл типа "photo", THE System SHALL отправить фотографию с подписью, содержащей имя файла
3. WHEN файл типа "document", THE System SHALL отправить документ с оригинальным именем файла
4. WHEN файл типа "video", THE System SHALL отправить видео с подписью, содержащей имя файла
5. WHEN файл типа "audio", THE System SHALL отправить аудио с подписью, содержащей имя файла
6. IF отправка файла не удалась, THEN THE System SHALL отобразить сообщение об ошибке

### Требование 6: Удаление вложения

**User Story:** Как создатель события, я хочу удалять вложения, чтобы управлять прикрепленными файлами.

#### Acceptance Criteria

1. WHEN Event_Creator нажимает кнопку удаления вложения, THE System SHALL запросить подтверждение удаления
2. WHEN Event_Creator подтверждает удаление, THE System SHALL удалить вложение из базы данных
3. WHEN вложение удалено, THE System SHALL обновить список вложений
4. WHEN вложение удалено, THE System SHALL отобразить подтверждающее сообщение
5. WHEN пользователь не является Event_Creator, THE System SHALL не отображать кнопку удаления вложения

### Требование 7: Проверка прав доступа

**User Story:** Как система, я должна проверять права доступа к операциям с вложениями, чтобы обеспечить безопасность данных.

#### Acceptance Criteria

1. WHEN пользователь пытается добавить вложение к событию, THE System SHALL проверить, что пользователь является Event_Creator
2. WHEN пользователь пытается удалить вложение, THE System SHALL проверить, что пользователь является Event_Creator
3. IF пользователь не является Event_Creator, THEN THE System SHALL отклонить операцию и отобразить сообщение об ошибке
4. WHEN пользователь просматривает вложения, THE System SHALL разрешить просмотр всем членам семьи

### Требование 8: Интеграция с состоянием диалога

**User Story:** Как система, я должна корректно управлять состоянием диалога при работе с вложениями, чтобы обеспечить правильную обработку сообщений.

#### Acceptance Criteria

1. WHEN пользователь переходит в режим ожидания файла, THE System SHALL сохранить состояние в Conversation_State_Service
2. WHEN пользователь отправляет файл в режиме ожидания, THE System SHALL обработать файл и очистить состояние
3. WHEN пользователь отменяет добавление файла, THE System SHALL очистить состояние ожидания файла
4. WHEN пользователь находится в режиме ожидания файла и отправляет текстовое сообщение, THE System SHALL отобразить подсказку о необходимости отправить файл

### Требование 9: Обработка ошибок Telegram API

**User Story:** Как система, я должна корректно обрабатывать ошибки Telegram API, чтобы обеспечить стабильную работу функционала.

#### Acceptance Criteria

1. IF Telegram API возвращает ошибку при получении файла, THEN THE System SHALL отобразить сообщение об ошибке пользователю
2. IF Telegram API возвращает ошибку при отправке файла, THEN THE System SHALL отобразить сообщение об ошибке пользователю
3. WHEN происходит ошибка, THE System SHALL логировать детали ошибки для диагностики
4. WHEN происходит ошибка, THE System SHALL очистить состояние диалога для предотвращения зависания

### Требование 10: Пользовательский интерфейс

**User Story:** Как пользователь, я хочу иметь интуитивно понятный интерфейс для работы с вложениями, чтобы легко управлять файлами.

#### Acceptance Criteria

1. WHEN отображается список вложений, THE System SHALL использовать эмодзи для визуального обозначения типов файлов
2. WHEN отображается размер файла, THE System SHALL форматировать размер в удобочитаемом формате (КБ, МБ)
3. WHEN отображается дата загрузки, THE System SHALL форматировать дату в формате "dd.MM.yyyy HH:mm"
4. WHEN пользователь взаимодействует с вложениями, THE System SHALL использовать inline-клавиатуры для действий
5. WHEN отображаются сообщения, THE System SHALL использовать Markdown-форматирование для улучшения читаемости
