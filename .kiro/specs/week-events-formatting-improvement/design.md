# Design Document

## Overview

Данный документ описывает проектирование улучшений форматирования отображения событий на неделю в Telegram-боте семейного календаря. Изменения направлены на улучшение читаемости и локализацию интерфейса путем:

1. Добавления пустых строк между событиями одного дня
2. Локализации названий дней недели на русский язык
3. Изменения формата заголовка для завтрашних событий
4. Корректировки эмодзи для личных событий

Все изменения будут внесены в класс `EventFormatter`, который является централизованным компонентом для форматирования событий во всех командах списка событий (`/today`, `/week`, `/upcoming_events`).

## Architecture

### Текущая архитектура

Система использует следующую архитектуру для отображения событий:

```
WeekCommandHandler
    ↓
EventService (получение событий)
    ↓
EventFormatter (форматирование)
    ↓
MarkdownFormatter (экранирование Telegram Markdown)
    ↓
TelegramMessageService (отправка)
```

### Изменяемые компоненты

Изменения затронут только класс `EventFormatter`:

- Метод `formatEvent()` - добавление пустой строки после каждого события
- Метод `formatDayHeader()` - локализация дней недели и изменение формата заголовка для завтрашних событий
- Приватный метод `getEventTypeIcon()` - изменение эмодзи для личных событий

Класс `WeekCommandHandler` потребует минимальных изменений в логике вывода событий для корректной обработки пустых строк между событиями одного дня.

## Components and Interfaces

### EventFormatter

Утилитный класс для форматирования событий. Изменения:

#### 1. Метод formatEvent()

**Текущая сигнатура:**
```java
public static String formatEvent(Event event, User currentUser)
```

**Изменение:** Метод будет возвращать событие с завершающей пустой строкой для разделения событий внутри одного дня.

**Обоснование:** Это обеспечит единообразное форматирование во всех командах и упростит логику в обработчиках команд.

#### 2. Метод formatDayHeader()

**Текущая сигнатура:**
```java
public static String formatDayHeader(LocalDate date, LocalDate today)
```

**Изменения:**
- Локализация дней недели с английского на русский
- Изменение формата для завтрашнего дня: `🔜 ДД.ММ (Завтра - День_недели)`
- Сохранение текущего формата для других дней: `📆 ДД.ММ (День_недели)`

#### 3. Приватный метод getEventTypeIcon()

**Текущая реализация:**
```java
private static String getEventTypeIcon(Event event) {
    return event.getIsPersonal() ? "🔒 " : "👨‍👩‍👧‍👦 ";
}
```

**Изменение:** Замена эмодзи для личных событий с `🔒` на `👤`:
```java
private static String getEventTypeIcon(Event event) {
    return event.getIsPersonal() ? "👤 " : "👨‍👩‍👧‍👦 ";
}
```

### WeekCommandHandler

**Изменения в логике вывода:**

Текущая логика добавляет `\n` после каждого события. После изменений в `formatEvent()` (который будет возвращать событие с завершающей пустой строкой), необходимо:

1. Удалить добавление `\n` после каждого события в цикле
2. Удалить дополнительную пустую строку после всех событий дня

## Data Models

Изменения в моделях данных не требуются. Используются существующие модели:

- `Event` - модель события с полями `isPersonal`, `title`, `eventTime`, `endTime`, `description`, `user`
- `User` - модель пользователя

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system-essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: События одного дня разделены пустыми строками

*For any* список событий одного дня, содержащий более одного события, между каждой парой последовательных событий должна присутствовать ровно одна пустая строка.

**Validates: Requirements 1.1**

### Property 2: Разделители дней не имеют лишних пустых строк

*For any* отформатированный вывод событий на неделю, перед каждым разделителем дня не должно быть дополнительных пустых строк (только одна пустая строка после последнего события предыдущего дня).

**Validates: Requirements 1.3**

### Property 3: Дни недели отображаются на русском языке

*For any* дата, отформатированный заголовок дня должен содержать русское название дня недели (Понедельник, Вторник, Среда, Четверг, Пятница, Суббота, Воскресенье) и не должен содержать английские названия (Monday, Tuesday, Wednesday, Thursday, Friday, Saturday, Sunday).

**Validates: Requirements 2.1, 2.2**

### Property 4: Заголовок других дней имеет корректный формат

*For any* дата, которая не является сегодняшним или завтрашним днем, отформатированный заголовок должен соответствовать формату "📆 ДД.ММ (День_недели)" с русским названием дня недели.

**Validates: Requirements 3.2**

### Property 5: Личные события отображаются с эмодзи 👤

*For any* личное событие (isPersonal = true), отформатированная строка события должна содержать эмодзи 👤 и не должна содержать эмодзи 👨‍👩‍👧‍👦.

**Validates: Requirements 4.1**

### Property 6: Семейные события отображаются с эмодзи 👨‍👩‍👧‍👦

*For any* семейное событие (isPersonal = false), отформатированная строка события должна содержать эмодзи 👨‍👩‍👧‍👦 и не должна содержать эмодзи 👤.

**Validates: Requirements 4.2**

### Property 7: Разделители дней имеют единообразный формат

*For any* отформатированный вывод событий на неделю с несколькими днями, все разделители между днями должны иметь одинаковый формат (одинаковую строку символов).

**Validates: Requirements 5.2**

### Property 8: Разделитель имеет пустую строку после, а не перед

*For any* отформатированный вывод событий на неделю с несколькими днями, после каждого разделителя между днями должна быть пустая строка, а перед разделителем не должно быть дополнительных пустых строк (кроме той, что добавляется после последнего события предыдущего дня).

**Validates: Requirements 5.4**

### Property 9: Счетчик событий отформатирован курсивом

*For any* отформатированный вывод событий на неделю, итоговый счетчик событий должен быть отформатирован курсивом (обрамлен символами `_`).

**Validates: Requirements 5.5**

## Error Handling

Изменения не вводят новых сценариев ошибок. Существующая обработка ошибок в `WeekCommandHandler` остается без изменений:

- Обработка исключений при получении событий
- Логирование ошибок
- Возврат понятного сообщения об ошибке пользователю

Валидация входных параметров в `EventFormatter` остается на текущем уровне:
- Проверка на null для параметров `event`, `currentUser`, `date`, `today`
- Выброс `IllegalArgumentException` при некорректных параметрах

## Testing Strategy

### Unit Tests

Будут созданы unit-тесты для проверки конкретных сценариев форматирования:

1. **Тест форматирования заголовка для завтрашнего дня** - проверка формата "🔜 ДД.ММ (Завтра - День_недели)"
2. **Тест наличия заголовка с диапазоном дат** - проверка присутствия заголовка в выводе команды /week
3. **Тест расположения счетчика событий** - проверка, что счетчик находится в конце без разделителей перед ним
4. **Тест одного события в день** - проверка отсутствия лишних пустых строк для единственного события

### Property-Based Tests

Будут использованы property-based тесты для проверки универсальных свойств:

**Библиотека:** jqwik (уже используется в проекте)

**Конфигурация:** Минимум 100 итераций для каждого теста

**Тесты:**

1. **Property 1: События одного дня разделены пустыми строками**
   - Генерация: список из 2-10 случайных событий для одной даты
   - Проверка: между каждой парой событий есть ровно одна пустая строка
   - Тег: `**Feature: week-events-formatting-improvement, Property 1: События одного дня разделены пустыми строками**`

2. **Property 2: Разделители дней не имеют лишних пустых строк**
   - Генерация: события для 2-7 разных дней
   - Проверка: перед каждым разделителем нет дополнительных пустых строк
   - Тег: `**Feature: week-events-formatting-improvement, Property 2: Разделители дней не имеют лишних пустых строк**`

3. **Property 3: Дни недели отображаются на русском языке**
   - Генерация: случайные даты в пределах года
   - Проверка: заголовок содержит русское название дня и не содержит английское
   - Тег: `**Feature: week-events-formatting-improvement, Property 3: Дни недели отображаются на русском языке**`

4. **Property 4: Заголовок других дней имеет корректный формат**
   - Генерация: случайные даты, исключая сегодня и завтра
   - Проверка: формат соответствует "📆 ДД.ММ (День_недели)"
   - Тег: `**Feature: week-events-formatting-improvement, Property 4: Заголовок других дней имеет корректный формат**`

5. **Property 5: Личные события отображаются с эмодзи 👤**
   - Генерация: случайные личные события (isPersonal = true)
   - Проверка: отформатированная строка содержит 👤 и не содержит 👨‍👩‍👧‍👦
   - Тег: `**Feature: week-events-formatting-improvement, Property 5: Личные события отображаются с эмодзи 👤**`

6. **Property 6: Семейные события отображаются с эмодзи 👨‍👩‍👧‍👦**
   - Генерация: случайные семейные события (isPersonal = false)
   - Проверка: отформатированная строка содержит 👨‍👩‍👧‍👦 и не содержит 👤
   - Тег: `**Feature: week-events-formatting-improvement, Property 6: Семейные события отображаются с эмодзи 👨‍👩‍👧‍👦**`

7. **Property 7: Разделители дней имеют единообразный формат**

### Integration Tests

Интеграционные тесты не требуются, так как изменения касаются только форматирования вывода и не затрагивают взаимодействие с базой данных или внешними сервисами.

## Implementation Notes

### Локализация дней недели

Для локализации дней недели будет использован `DateTimeFormatter` с русской локалью:

```java
private static final DateTimeFormatter SHORT_DATE_FORMATTER = 
    DateTimeFormatter.ofPattern("dd.MM (EEEE)", new Locale("ru"));
```

### Формат завтрашнего дня

Для формата "Завтра - День_недели" потребуется:
1. Определить, является ли дата завтрашним днем
2. Отформатировать дату с русским названием дня
3. Собрать строку в формате "🔜 ДД.ММ (Завтра - День_недели)"

### Пустые строки между событиями

Метод `formatEvent()` будет возвращать событие с завершающей пустой строкой. В `WeekCommandHandler` необходимо:
1. Удалить явное добавление `\n` после каждого события
2. Удалить дополнительную пустую строку после всех событий дня
3. Сохранить логику добавления разделителей между днями

### Обратная совместимость

Изменения затрагивают только визуальное представление и не влияют на:
- Логику получения событий
- Фильтрацию событий
- Хранение данных
- API взаимодействия

Все существующие тесты для `WeekCommandHandler` и других команд, использующих `EventFormatter`, потребуют обновления для соответствия новому формату вывода.

## Performance Considerations

Изменения не влияют на производительность:
- Добавление пустых строк - O(1) операция
- Локализация дней недели - использование стандартного `DateTimeFormatter` с кэшированием
- Изменение эмодзи - замена константы

## Security Considerations

Изменения не вводят новых угроз безопасности. Все данные продолжают экранироваться через `MarkdownFormatter.escape()` для предотвращения инъекций Telegram Markdown.

## Dependencies

Изменения не требуют добавления новых зависимостей. Используются существующие:
- Java 17+ (для `DateTimeFormatter` с локалью)
- jqwik (для property-based тестов, уже присутствует в проекте)
