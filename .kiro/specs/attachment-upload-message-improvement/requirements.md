# Документ требований

## Введение

Данный документ описывает требования к улучшению UX при добавлении вложений к событиям в Telegram боте семейного календаря. Текущая реализация создает отдельное новое сообщение с инструкцией при выборе "Добавить вложение", что приводит к плохому пользовательскому опыту. Требуется изменить поведение так, чтобы текущее сообщение редактировалось вместо создания нового, и добавить возможность отмены процесса.

## Глоссарий

- **System** - Telegram бот семейного календаря
- **User** - пользователь Telegram бота
- **Event** - событие в семейном календаре
- **Attachment** - вложение (файл), прикрепленное к событию
- **Event_Message** - сообщение с карточкой события в Telegram
- **Attachment_Upload_State** - состояние ожидания загрузки файла от пользователя
- **Callback_Query** - запрос от inline кнопки в Telegram
- **Message_Edit** - операция редактирования существующего сообщения в Telegram

## Требования

### Requirement 1: Редактирование сообщения вместо создания нового

**User Story:** Как пользователь, я хочу, чтобы при выборе "Добавить вложение" текущее сообщение события редактировалось, а не создавалось новое сообщение, чтобы интерфейс оставался чистым и понятным.

#### Acceptance Criteria

1. WHEN User нажимает кнопку "Добавить вложение" на Event_Message, THEN THE System SHALL отредактировать текущее Event_Message вместо отправки нового сообщения
2. WHEN Event_Message редактируется для режима загрузки вложения, THEN THE System SHALL отобразить инструкцию по загрузке файла в отредактированном сообщении
3. WHEN Event_Message редактируется для режима загрузки вложения, THEN THE System SHALL сохранить messageId для последующего восстановления исходного вида события

### Requirement 2: Кнопка отмены процесса загрузки

**User Story:** Как пользователь, я хочу иметь возможность отменить процесс добавления вложения, чтобы вернуться к обычному просмотру события без загрузки файла.

#### Acceptance Criteria

1. WHEN Event_Message отредактировано для режима загрузки вложения, THEN THE System SHALL отобразить inline кнопку "Отмена"
2. WHEN User нажимает кнопку "Отмена" в режиме загрузки вложения, THEN THE System SHALL отредактировать Event_Message обратно к стандартному виду карточки события
3. WHEN User нажимает кнопку "Отмена" в режиме загрузки вложения, THEN THE System SHALL очистить Attachment_Upload_State для данного User
4. WHEN User нажимает кнопку "Отмена" в режиме загрузки вложения, THEN THE System SHALL восстановить стандартные кнопки управления событием

### Requirement 3: Сохранение контекста сообщения

**User Story:** Как система, я должна сохранять контекст сообщения события, чтобы корректно редактировать его при переходе между режимами просмотра и загрузки вложения.

#### Acceptance Criteria

1. WHEN User нажимает кнопку "Добавить вложение", THEN THE System SHALL сохранить messageId текущего Event_Message в ConversationState
2. WHEN User нажимает кнопку "Добавить вложение", THEN THE System SHALL сохранить chatId текущего чата в ConversationState
3. WHEN User нажимает кнопку "Добавить вложение", THEN THE System SHALL сохранить eventId текущего события в ConversationState
4. WHEN System редактирует Event_Message обратно к стандартному виду, THEN THE System SHALL использовать сохраненные messageId, chatId и eventId из ConversationState

### Requirement 4: Обработка ошибок редактирования

**User Story:** Как система, я должна корректно обрабатывать ситуации, когда редактирование сообщения невозможно, чтобы пользователь всегда получал корректный интерфейс.

#### Acceptance Criteria

1. IF редактирование Event_Message не удалось из-за удаления сообщения пользователем, THEN THE System SHALL отправить новое сообщение с инструкцией по загрузке файла
2. IF редактирование Event_Message не удалось из-за истечения времени (>48 часов), THEN THE System SHALL отправить новое сообщение с инструкцией по загрузке файла
3. WHEN редактирование Event_Message не удалось, THEN THE System SHALL залогировать причину ошибки для диагностики
4. WHEN отправляется новое сообщение вместо редактирования, THEN THE System SHALL сохранить messageId нового сообщения для последующих операций

### Requirement 5: Формат инструкции по загрузке

**User Story:** Как пользователь, я хочу видеть понятную инструкцию по загрузке файла, чтобы знать, какие файлы я могу загрузить и каковы ограничения.

#### Acceptance Criteria

1. WHEN Event_Message отредактировано для режима загрузки вложения, THEN THE System SHALL отобразить заголовок "Отправьте файл для прикрепления к событию"
2. WHEN Event_Message отредактировано для режима загрузки вложения, THEN THE System SHALL отобразить максимальный размер файла (20 МБ)
3. WHEN Event_Message отредактировано для режима загрузки вложения, THEN THE System SHALL отобразить список поддерживаемых типов файлов (документы, фотографии, видео, аудио)
4. WHEN Event_Message отредактировано для режима загрузки вложения, THEN THE System SHALL использовать MarkdownV2 форматирование для улучшения читаемости

### Requirement 6: Callback data для кнопки отмены

**User Story:** Как система, я должна корректно формировать callback data для кнопки отмены, чтобы обработчик мог идентифицировать действие и событие.

#### Acceptance Criteria

1. WHEN System создает кнопку "Отмена" для режима загрузки вложения, THEN THE System SHALL использовать формат callback data "attach_file_cancel_add_{eventId}"
2. WHEN System обрабатывает Callback_Query с action "cancel" и subAction "add", THEN THE System SHALL извлечь eventId из callback data
3. WHEN System обрабатывает Callback_Query с action "cancel" и subAction "add", THEN THE System SHALL вызвать обработчик отмены добавления вложения

### Requirement 7: Восстановление стандартного вида события

**User Story:** Как пользователь, я хочу, чтобы при отмене загрузки вложения сообщение вернулось к стандартному виду карточки события, чтобы я мог продолжить работу с событием.

#### Acceptance Criteria

1. WHEN User нажимает кнопку "Отмена", THEN THE System SHALL отобразить название события в отредактированном сообщении
2. WHEN User нажимает кнопку "Отмена", THEN THE System SHALL отобразить дату и время события в отредактированном сообщении
3. WHEN User нажимает кнопку "Отмена", THEN THE System SHALL отобразить описание события (если есть) в отредактированном сообщении
4. WHEN User нажимает кнопку "Отмена", THEN THE System SHALL отобразить стандартные кнопки управления событием (Редактировать, Удалить, Вложения)
5. WHEN User нажимает кнопку "Отмена", THEN THE System SHALL использовать тот же формат отображения, что и при первоначальном открытии события

### Requirement 8: Проверка прав доступа

**User Story:** Как система, я должна проверять права доступа пользователя перед редактированием сообщения, чтобы только создатель события мог добавлять вложения.

#### Acceptance Criteria

1. WHEN User нажимает кнопку "Добавить вложение", THEN THE System SHALL проверить, что User является создателем Event
2. IF User не является создателем Event, THEN THE System SHALL отправить Callback_Query ответ с сообщением "Нет прав доступа"
3. IF User не является создателем Event, THEN THE System SHALL не редактировать Event_Message
4. IF User не является создателем Event, THEN THE System SHALL не устанавливать Attachment_Upload_State

### Requirement 9: Удаление сообщения пользователя с файлом

**User Story:** Как пользователь, я хочу, чтобы мое сообщение с загруженным файлом автоматически удалялось после успешной загрузки, чтобы чат оставался чистым и не засорялся дублирующимися файлами.

#### Acceptance Criteria

1. WHEN User отправляет файл (документ, фото, видео или аудио) в режиме ожидания загрузки вложения, THEN THE System SHALL удалить сообщение User с файлом после успешного сохранения вложения
2. WHEN сообщение User с файлом удалено, THEN THE System SHALL залогировать успешное удаление на уровне DEBUG
3. IF удаление сообщения User не удалось (сообщение уже удалено, нет прав), THEN THE System SHALL залогировать предупреждение на уровне WARN
4. IF удаление сообщения User не удалось, THEN THE System SHALL продолжить выполнение без прерывания процесса загрузки вложения
5. WHEN сообщение User удалено, THEN THE System SHALL обновить сообщение с инструкцией, показав актуальный список вложений
