# Документ проектирования

## Обзор

Данный документ описывает проектное решение для улучшения отображения событий в команде /filter. Текущая реализация использует упрощенное форматирование, которое не соответствует форматированию в других командах (например, /my_events). Решение заключается в использовании существующего компонента `BotMessageBuilder` для централизованного и консистентного форматирования событий.

## Архитектура

### Текущая архитектура

```
FilterCommandHandler
  └─> formatEvent() - собственная реализация форматирования
      └─> Использует MarkdownFormatter напрямую
```

### Целевая архитектура

```
FilterCommandHandler
  └─> BotMessageBuilder.buildEventMessage() - централизованное форматирование
      └─> Использует MarkdownFormatter
```

## Компоненты и интерфейсы

### FilterCommandHandler

**Изменяемые методы:**

1. `formatEvent(Event event, User user)` - будет удален
2. `handleFilterCallback(CallbackQuery callbackQuery, User user)` - будет обновлен для использования `BotMessageBuilder`

**Новые зависимости:**

- `BotMessageBuilder` - для централизованного форматирования событий

### BotMessageBuilder

**Используемые методы:**

- `buildEventMessage(Event event)` - форматирует событие с полной информацией, включая:
  - Эмодзи 📌 перед названием
  - Эмодзи 📅 перед датой
  - Эмодзи 🕐 перед временем
  - Тип события (👨‍👩‍👧‍👦 для семейных, 👤 для персональных)
  - Описание события с эмодзи 📝 (если есть)

## Модели данных

Используются существующие модели без изменений:

- `Event` - модель события с полями:
  - `title` - название
  - `eventDate` - дата
  - `eventTime` - время начала
  - `endTime` - время окончания (опционально)
  - `description` - описание (опционально)
  - `isPersonal` - флаг персонального события
  - `user` - создатель события

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться для всех допустимых выполнений системы - по сути, формальное утверждение о том, что система должна делать. Свойства служат мостом между человекочитаемыми спецификациями и машинопроверяемыми гарантиями корректности.*

### Свойство 1: Наличие базовых эмодзи

*Для любого* события, отображаемого в результатах фильтрации, отформатированное сообщение должно содержать эмодзи 📌 перед названием, эмодзи 📅 перед датой и эмодзи 🕐 перед временем

**Проверяет: Требования 1.1, 1.2, 1.3**

### Свойство 2: Корректный эмодзи типа события

*Для любого* события, отображаемого в результатах фильтрации, отформатированное сообщение должно содержать эмодзи 👨‍👩‍👧‍👦 если событие семейное (isPersonal = false), или эмодзи 👤 если событие персональное (isPersonal = true)

**Проверяет: Требования 1.4, 1.5**

### Свойство 3: Корректное отображение описания

*Для любого* события, отображаемого в результатах фильтрации, отформатированное сообщение должно содержать строку с эмодзи 📝 и текстом описания тогда и только тогда, когда описание события непустое

**Проверяет: Требования 2.1, 2.2**

### Свойство 4: Корректное количество разделителей

*Для любого* списка из N событий (где N ≥ 1), отображаемого в результатах фильтрации, количество разделительных линий между событиями должно быть равно N-1

**Проверяет: Требования 3.1, 3.2**

### Свойство 5: Консистентность форматирования

*Для любого* события, отформатированное сообщение, созданное через BotMessageBuilder.buildEventMessage(), должно быть идентичным независимо от контекста использования (фильтр, /my_events, и т.д.)

**Проверяет: Требования 4.1**

### Свойство 6: Корректное экранирование MarkdownV2

*Для любого* события со специальными символами MarkdownV2 в пользовательских данных (название, описание), отформатированное сообщение должно содержать корректно экранированные специальные символы

**Проверяет: Требования 4.2**

## Обработка ошибок

### Существующая обработка

`FilterCommandHandler` уже имеет обработку ошибок:

```java
try {
    // Логика фильтрации
} catch (Exception e) {
    log.error("Ошибка при обработке фильтрации для пользователя ID={}", user.getId(), e);
    messageService.sendMessage(chatId, 
        "❌ " + escape("Произошла ошибка при фильтрации событий. Попробуйте позже."));
}
```

Эта обработка сохраняется без изменений.

### Новые сценарии ошибок

`BotMessageBuilder.buildEventMessage()` может выбросить `IllegalArgumentException` если event == null. Это не должно произойти в нормальном потоке, так как события получаются из базы данных через `SearchService`.

## Стратегия тестирования

### Unit-тесты

1. **Тест форматирования события с описанием**
   - Создать событие с описанием
   - Вызвать `BotMessageBuilder.buildEventMessage()`
   - Проверить наличие всех эмодзи и описания

2. **Тест форматирования события без описания**
   - Создать событие без описания
   - Вызвать `BotMessageBuilder.buildEventMessage()`
   - Проверить наличие всех эмодзи и отсутствие строки с описанием

3. **Тест разделения событий**
   - Создать список из нескольких событий
   - Сформировать сообщение с разделителями
   - Проверить количество разделителей

4. **Тест экранирования специальных символов**
   - Создать событие с специальными символами MarkdownV2
   - Вызвать `BotMessageBuilder.buildEventMessage()`
   - Проверить корректное экранирование

### Property-based тесты

Используется библиотека **jqwik** для Java (уже используется в проекте).

Каждый property-based тест должен выполнять минимум 100 итераций.

## Детали реализации

### Изменения в FilterCommandHandler

#### 1. Добавление зависимости

```java
@RequiredArgsConstructor
@Slf4j
public class FilterCommandHandler implements CommandHandler {
    
    private final KeyboardService keyboardService;
    private final SearchService searchService;
    private final TelegramMessageService messageService;
    private final BotMessageBuilder botMessageBuilder; // Новая зависимость
    
    // ...
}
```

#### 2. Обновление метода handleFilterCallback

```java
public void handleFilterCallback(CallbackQuery callbackQuery, User user) {
    String data = callbackQuery.getData();
    Long chatId = callbackQuery.getMessage().getChatId();
    
    log.debug("Обработка callback фильтрации '{}' для пользователя ID={}", data, user.getId());
    
    try {
        SearchService.EventFilter filter = parseFilter(data);
        
        if (filter == null) {
            log.warn("Неизвестный фильтр: {}", data);
            return;
        }
        
        // Выполнение фильтрации
        List<Event> results = searchService.filterEvents(
            user.getFamily().getId(),
            user.getId(),
            filter
        );
        
        // Формирование сообщения с результатами
        String filterName = getFilterName(filter);
        StringBuilder messageBuilder = new StringBuilder();
        messageBuilder.append(formatMessage("🔎 %s\n\n", filterName));
        
        if (results.isEmpty()) {
            messageBuilder.append(escape("Событий не найдено.")).append("\n\n");
            messageBuilder.append(italic("Попробуйте другой фильтр или создайте новое событие."));
        } else {
            // Используем BotMessageBuilder для форматирования каждого события
            for (int i = 0; i < results.size(); i++) {
                Event event = results.get(i);
                messageBuilder.append(botMessageBuilder.buildEventMessage(event));
                
                // Добавляем разделитель между событиями (но не после последнего)
                if (i < results.size() - 1) {
                    messageBuilder.append("\n").append(escape("─────────────────────")).append("\n");
                }
            }
            messageBuilder.append(String.format("\n\n%s", italic("Найдено событий: " + results.size())));
        }
        
        messageService.sendMessage(chatId, messageBuilder.toString());
        log.debug("Пользователю ID={} отправлено {} событий по фильтру {}", 
                 user.getId(), results.size(), filter);
        
    } catch (Exception e) {
        log.error("Ошибка при обработке фильтрации для пользователя ID={}", user.getId(), e);
        try {
            messageService.sendMessage(chatId, 
                "❌ " + escape("Произошла ошибка при фильтрации событий. Попробуйте позже."));
        } catch (Exception ex) {
            log.error("Ошибка при отправке сообщения об ошибке: {}", ex.getMessage(), ex);
        }
    }
}
```

#### 3. Удаление метода formatEvent

Метод `formatEvent(Event event, User user)` будет полностью удален, так как его функциональность заменяется на `BotMessageBuilder.buildEventMessage()`.

### Разделительная линия

Используется символ горизонтальной линии: `─────────────────────` (20 символов)

Этот символ не требует экранирования в MarkdownV2, но для консистентности применяется `escape()`.

## Альтернативные решения

### Альтернатива 1: Расширить существующий formatEvent

**Плюсы:**
- Минимальные изменения в коде
- Не требует новых зависимостей

**Минусы:**
- Дублирование логики форматирования
- Сложность поддержки консистентности между командами
- Нарушение принципа DRY

**Решение:** Отклонено в пользу использования `BotMessageBuilder`

### Альтернатива 2: Создать отдельный метод в BotMessageBuilder для фильтра

**Плюсы:**
- Возможность кастомизации для фильтра

**Минусы:**
- Дублирование кода
- Усложнение поддержки

**Решение:** Отклонено, так как существующий метод `buildEventMessage()` полностью покрывает требования

## Влияние на производительность

Изменения не влияют на производительность:
- `BotMessageBuilder.buildEventMessage()` использует те же операции, что и текущий `formatEvent()`
- Добавление разделительных линий - это простая конкатенация строк
- Количество событий в результатах фильтрации обычно невелико (< 100)

## Миграция и обратная совместимость

Изменения не требуют миграции данных и полностью обратно совместимы:
- API не меняется
- Формат callback данных остается прежним
- Изменяется только визуальное представление событий
