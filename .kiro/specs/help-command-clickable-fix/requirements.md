# Документ требований

## Введение

Данная спецификация описывает исправление отображения команд во всех сообщениях Telegram-бота семейного календаря. В настоящее время команды отображаются в моноширинном формате (с использованием backticks), что делает их некликабельными в Telegram-клиенте. Это создает плохой пользовательский опыт, так как пользователи не могут просто нажать на команду для её выполнения. Проблема затрагивает команду `/help`, контекстные подсказки, сообщения об ошибках и другие места, где упоминаются команды бота.

## Глоссарий

- **Система**: Существующее Spring Boot приложение семейного календарь-бота
- **HelpCommandHandler**: Обработчик команды /help, отображающий список всех доступных команд
- **ContextualHintsService**: Сервис для отображения контекстных подсказок пользователю
- **Кликабельная команда**: Команда в формате `/command`, которую Telegram автоматически распознает и делает кликабельной
- **Моноширинный формат**: Текст, обернутый в backticks (`` `текст` ``), отображается моноширинным шрифтом
- **MarkdownFormatter**: Утилитный класс для форматирования текста в MarkdownV2 формате
- **Handler**: Обработчик команд бота (StartCommandHandler, TodayCommandHandler и т.д.)

## Требования

### Требование 1

**Пользовательская история:** Как пользователь бота, я хочу видеть кликабельные команды в справке `/help`, чтобы я мог быстро выполнить нужную команду одним нажатием.

#### Критерии приемки

1. WHEN пользователь отправляет команду `/help`, THEN Система ДОЛЖНА отображать команды в формате `/command` без моноширинного форматирования
2. WHEN команда отображается в списке справки, THEN Telegram-клиент ДОЛЖЕН автоматически распознать её как кликабельную команду
3. WHEN пользователь нажимает на команду в справке, THEN Telegram ДОЛЖЕН автоматически отправить эту команду боту
4. WHEN команда отображается, THEN описание команды ДОЛЖНО быть корректно экранировано для MarkdownV2
5. WHEN список команд формируется, THEN команды ДОЛЖНЫ быть отсортированы в алфавитном порядке

### Требование 2

**Пользовательская история:** Как разработчик, я хочу, чтобы форматирование команд в справке было единообразным, чтобы обеспечить консистентность пользовательского опыта.

#### Критерии приемки

1. WHEN формируется строка с командой, THEN Система ДОЛЖНА использовать формат: `/command - описание`
2. WHEN описание содержит специальные символы MarkdownV2, THEN Система ДОЛЖНА корректно экранировать их
3. WHEN команда не имеет описания, THEN Система ДОЛЖНА отображать только команду без тире
4. WHEN список команд пуст, THEN Система ДОЛЖНА отображать сообщение об отсутствии доступных команд
5. WHEN метод `buildCommandsList()` вызывается, THEN Система НЕ ДОЛЖНА использовать метод `code()` для форматирования команд

### Требование 3

**Пользовательская история:** Как пользователь бота, я хочу видеть визуально структурированную справку, чтобы легко находить нужные команды.

#### Критерии приемки

1. WHEN отображается справка, THEN заголовок ДОЛЖЕН быть отформатирован жирным шрифтом
2. WHEN отображается справка, THEN каждая команда ДОЛЖНА быть на отдельной строке
3. WHEN отображается справка, THEN между заголовком и списком команд ДОЛЖНА быть пустая строка
4. WHEN отображается справка, THEN после списка команд ДОЛЖНА быть пустая строка перед инструкциями
5. WHEN отображается справка, THEN инструкции по использованию ДОЛЖНЫ быть корректно экранированы

### Требование 4

**Пользовательская история:** Как пользователь бота, я хочу видеть кликабельные команды в контекстных подсказках, чтобы быстро выполнять рекомендуемые действия.

#### Критерии приемки

1. WHEN ContextualHintsService формирует подсказку с упоминанием команды, THEN Система ДОЛЖНА отображать команду в формате `/command` без моноширинного форматирования
2. WHEN подсказка содержит несколько команд, THEN все команды ДОЛЖНЫ быть кликабельными
3. WHEN подсказка отображается после добавления события, THEN команды `/today` и `/week` ДОЛЖНЫ быть кликабельными
4. WHEN подсказка отображается, THEN текст подсказки ДОЛЖЕН быть корректно экранирован
5. WHEN метод `getHint()` вызывается, THEN Система НЕ ДОЛЖНА использовать метод `code()` для форматирования команд

### Требование 5

**Пользовательская история:** Как пользователь бота, я хочу видеть кликабельные команды в сообщениях об ошибках, чтобы быстро исправить ситуацию.

#### Критерии приемки

1. WHEN Система отправляет сообщение об ошибке с рекомендацией использовать команду, THEN команда ДОЛЖНА быть кликабельной
2. WHEN сообщение об ошибке содержит несколько команд, THEN все команды ДОЛЖНЫ быть кликабельными
3. WHEN отображается ошибка валидации, THEN рекомендуемые команды ДОЛЖНЫ быть в формате `/command`
4. WHEN отображается сообщение о необходимости авторизации, THEN команда `/start` ДОЛЖНА быть кликабельной
5. WHEN формируется сообщение об ошибке, THEN Система НЕ ДОЛЖНА использовать метод `code()` для форматирования команд

### Требование 6

**Пользовательская история:** Как пользователь бота, я хочу видеть кликабельные команды в приветственном сообщении, чтобы быстро начать работу с ботом.

#### Критерии приемки

1. WHEN StartCommandHandler отправляет приветственное сообщение, THEN все упомянутые команды ДОЛЖНЫ быть кликабельными
2. WHEN приветствие содержит список основных команд, THEN каждая команда ДОЛЖНА быть в формате `/command`
3. WHEN приветствие отображается новому пользователю, THEN команды для начала работы ДОЛЖНЫ быть кликабельными
4. WHEN приветствие содержит инструкции, THEN команды в инструкциях ДОЛЖНЫ быть кликабельными
5. WHEN формируется приветственное сообщение, THEN Система НЕ ДОЛЖНА использовать метод `code()` для форматирования команд

### Требование 7

**Пользовательская история:** Как пользователь бота, я хочу видеть кликабельные команды в любых информационных сообщениях, чтобы легко переходить к нужным действиям.

#### Критерии приемки

1. WHEN любой обработчик команд упоминает другую команду в своем ответе, THEN упомянутая команда ДОЛЖНА быть кликабельной
2. WHEN сообщение содержит рекомендацию использовать команду, THEN команда ДОЛЖНА быть в формате `/command`
3. WHEN отображается сообщение об отсутствии событий с рекомендацией, THEN рекомендуемые команды ДОЛЖНЫ быть кликабельными
4. WHEN формируется любое сообщение с упоминанием команды, THEN Система НЕ ДОЛЖНА использовать метод `code()` для форматирования команд
5. WHEN сообщение содержит ссылку на справку, THEN команда `/help` ДОЛЖНА быть кликабельной

### Требование 8

**Пользовательская история:** Как разработчик, я хочу иметь единый подход к отображению команд во всех сообщениях, чтобы обеспечить консистентность пользовательского опыта.

#### Критерии приемки

1. WHEN разработчик добавляет упоминание команды в сообщение, THEN он ДОЛЖЕН использовать простой текст `/command` без дополнительного форматирования
2. WHEN в коде используется метод `code()` для команды, THEN это ДОЛЖНО быть заменено на простой экранированный текст
3. WHEN формируется сообщение с командой, THEN символ `/` ДОЛЖЕН быть корректно экранирован для MarkdownV2
4. WHEN в MarkdownFormatter используется метод `escape()`, THEN он ДОЛЖЕН корректно обрабатывать символ `/`
5. WHEN создается новый обработчик команд, THEN он ДОЛЖЕН следовать единому подходу к отображению команд
