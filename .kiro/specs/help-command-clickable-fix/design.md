# Документ дизайна

## Обзор

Данный документ описывает дизайн решения для исправления отображения команд во всех сообщениях Telegram-бота семейного календаря. Проблема заключается в том, что команды отображаются в моноширинном формате (с использованием метода `code()` из `MarkdownFormatter`), что делает их некликабельными в Telegram-клиенте.

Корневая причина: в различных обработчиках команд и сервисах используется метод `MarkdownFormatter.code()` для форматирования команд, что оборачивает их в backticks (`` `команда` ``). Telegram не распознает такие команды как кликабельные.

Решение включает:
1. Удаление использования `code()` для форматирования команд во всех местах кода
2. Замена на простой экранированный текст в формате `/command`
3. Обновление всех обработчиков команд, сервисов и планировщиков
4. Обеспечение единообразного подхода к отображению команд

## Архитектура

### Текущая архитектура (проблема)

```
┌─────────────────────┐
│  HelpCommandHandler │
│                     │
│  buildCommandsList()│
│  использует code()  │
└──────────┬──────────┘
           │
           │ `/help` → `\`/help\``
           ▼
┌─────────────────────┐
│ MarkdownFormatter   │
│ code(text)          │
│ возвращает `text`   │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  Telegram API       │
│  (команда НЕ        │
│   кликабельна)      │
└─────────────────────┘
```

### Новая архитектура (решение)

```
┌─────────────────────┐
│  HelpCommandHandler │
│                     │
│  buildCommandsList()│
│  использует escape()│
└──────────┬──────────┘
           │
           │ `/help` → `/help`

┌─────────────────────┐
│ MarkdownFormatter   │
│ escape(text)        │

└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  Telegram API       │

```

## Компоненты и интерфейсы

### 1. MarkdownFormatter (Обновление)

Необходимо убедиться, что метод `escape()` корректно обрабатывает символ `/`.

**Текущая реализация:**
```java
public static String escape(String text) {
    if (text == null || text.isEmpty()) {
        return "";
    }
    
    // Экранируем специальные символы MarkdownV2
    return text.replace("\\", "\\\\")
               .replace("_", "\\_")
               .replace("*", "\\*")
               // ... другие символы
}
```

**Проверка:** Убедиться, что символ `/` НЕ экранируется, так как он не является специальным символом MarkdownV2.

**Примечание:** Согласно документации Telegram Bot API, символ `/` не требует экранирования в MarkdownV2. Команды в формате `/command` автоматически распознаются Telegram как кликабельные.

### 2. HelpCommandHandler (Обновление)

Основное изменение - замена `code()` на `escape()` в методе `buildCommandsList()`.

**Было:**
```java
private String buildCommandsList() {
    if (commandHandlers == null || commandHandlers.isEmpty()) {
        log.warn("Список обработчиков команд пуст");
        return escape("В данный момент команды недоступны.");
    }

    return commandHandlers.stream()
            .filter(handler -> handler != null)
            .sorted(Comparator.comparing(CommandHandler::getCommand))
            .map(handler -> code(handler.getCommand()) + " " + escape("-") + " " + escape(handler.getDescription()))
            .collect(Collectors.joining("\n"));
}
```

**Стало:**
```java
private String buildCommandsList() {
    if (commandHandlers == null || commandHandlers.isEmpty()) {
        log.warn("Список обработчиков команд пуст");
        return escape("В данный момент команды недоступны.");
    }

    return commandHandlers.stream()
            .filter(handler -> handler != null)
            .sorted(Comparator.comparing(CommandHandler::getCommand))
            .map(handler -> escape(handler.getCommand()) + " " + escape("-") + " " + escape(handler.getDescription()))
            .collect(Collectors.joining("\n"));
}
```

**Ключевые изменения:**
- Заменить `code(handler.getCommand())` на `escape(handler.getCommand())`
- Команда теперь отображается как `/help` вместо `` `/help` ``
- Telegram автоматически распознает её как кликабельную

### 3. ContextualHintsService (Обновление)

Необходимо найти все места, где используется `code()` для команд, и заменить на `escape()`.

**Пример изменения:**
```java
// Было:
return "Событие добавлено! Используйте " + code("/today") + " для просмотра событий на сегодня.";

// Стало:
return "Событие добавлено! Используйте " + escape("/today") + " для просмотра событий на сегодня.";
```

**Методы для проверки:**
- `getHint(HintContext context)` - основной метод формирования подсказок
- Все приватные методы, формирующие текст подсказок

### 4. StartCommandHandler (Обновление)

Проверить приветственное сообщение на наличие команд в моноширинном формате.

**Пример изменения:**
```java
// Было:
String message = "Добро пожаловать! Используйте " + code("/help") + " для просмотра всех команд.";

// Стало:
String message = "Добро пожаловать! Используйте " + escape("/help") + " для просмотра всех команд.";
```

### 5. Другие обработчики команд

Необходимо проверить все обработчики команд на наличие упоминаний других команд:

**Обработчики для проверки:**
- `TodayCommandHandler` - может упоминать `/week` или `/add_event`
- `WeekCommandHandler` - может упоминать `/today` или `/add_event`
- `SearchCommandHandler` - может упоминать `/help`
- `FilterCommandHandler` - может упоминать другие команды
- `StatsCommandHandler` - может упоминать другие команды
- `TrashCommandHandler` - может упоминать `/my_events`
- `MyEventsCommandHandler` - может упоминать другие команды
- `UpcomingEventsCommandHandler` - может упоминать другие команды

**Подход:**
1. Найти все использования `code()` в каждом обработчике
2. Проверить, является ли аргумент командой (начинается с `/`)
3. Если да - заменить на `escape()`
4. Если нет (например, код или техническая информация) - оставить `code()`

### 6. Сообщения об ошибках

Проверить все места, где формируются сообщения об ошибках с упоминанием команд:

**Места для проверки:**
- `GlobalExceptionHandler` - обработка исключений
- `ValidationExceptionHandler` - ошибки валидации
- Методы валидации в сервисах
- Обработчики ошибок в командах

**Пример изменения:**
```java

// Стало:

```

## Модели данных

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться во всех допустимых выполнениях системы - по сути, формальное утверждение о том, что система должна делать. Свойства служат мостом между спецификациями, читаемыми человеком, и гарантиями корректности, проверяемыми машиной.*

### Свойство 1: Команды не используют моноширинное форматирование

*Для любого* сообщения, содержащего упоминание команды бота (текст, начинающийся с `/`), команда должна быть отформатирована с использованием `escape()`, а не `code()`.

**Проверяет: Требования 1.1, 2.5, 4.1, 5.5, 6.5, 7.4, 8.2**

### Свойство 2: Команды кликабельны в Telegram

*Для любого* сообщения, отправленного ботом и содержащего команду в формате `/command`, Telegram-клиент должен автоматически распознать её как кликабельную команду.

**Проверяет: Требования 1.2, 1.3, 4.2, 5.2, 6.2, 7.2**

### Свойство 3: Описания команд корректно экранированы

*Для любого* описания команды в справке `/help`, все специальные символы MarkdownV2 должны быть корректно экранированы с использованием метода `escape()`.

**Проверяет: Требования 1.4, 2.2**

### Свойство 4: Команды отсортированы в алфавитном порядке

*Для любого* списка команд в справке `/help`, команды должны быть отсортированы в алфавитном порядке по названию команды.

**Проверяет: Требования 1.5**

### Свойство 5: Единообразное форматирование команд

*Для любого* места в коде, где формируется сообщение с упоминанием команды, должен использоваться единый подход: `escape("/command")` вместо `code("/command")`.

**Проверяет: Требования 8.1, 8.2, 8.5**

## Обработка ошибок

### 1. Команды без описания

**Проблема:** Некоторые команды могут не иметь описания.

**Решение:**
- Метод `getDescription()` в интерфейсе `CommandHandler` должен возвращать пустую строку вместо null
- В `buildCommandsList()` проверять, не пустое ли описание
- Если описание пустое, отображать только команду без тире

```java
.map(handler -> {
    String command = escape(handler.getCommand());
    String description = handler.getDescription();
    if (description == null || description.isEmpty()) {
        return command;
    }
    return command + " " + escape("-") + " " + escape(description);
})
```

### 2. Пустой список команд

**Проблема:** Список обработчиков команд может быть пустым.

**Решение:**
- Уже реализовано в текущем коде
- Возвращается сообщение: "В данный момент команды недоступны."

### 3. Null значения в списке обработчиков

**Проблема:** Список может содержать null значения.

**Решение:**
- Уже реализовано в текущем коде
- Используется `.filter(handler -> handler != null)`

## Альтернативные решения

### Альтернатива 1: Создать отдельный метод command() в MarkdownFormatter

**Плюсы:**
- Явное указание намерения (это команда, а не просто текст)
- Легче найти все места использования

**Минусы:**
- Дополнительный метод, который просто вызывает `escape()`
- Избыточность в коде

**Решение:** Отклонено. Использование `escape()` достаточно явно и не требует дополнительного метода.

### Альтернатива 2: Использовать HTML-теги для команд

**Плюсы:**
- Можно использовать `<code>/command</code>` для визуального выделения
- Команды останутся кликабельными

**Минусы:**
- Требует переключения на HTML parseMode
- Несовместимо с текущим MarkdownV2 подходом
- Требует масштабного рефакторинга

**Решение:** Отклонено. Остаемся с MarkdownV2 и простым текстом для команд.
