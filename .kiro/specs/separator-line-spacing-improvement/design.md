# Дизайн: Улучшение форматирования разделительных линий

## Обзор

Данный документ описывает дизайн улучшения форматирования разделительных линий в командах бота семейного календаря. Цель - улучшить визуальное восприятие списков событий путем добавления пустых строк вокруг разделительных линий.

Текущая реализация использует разделительные линии без дополнительных пустых строк, что делает списки событий визуально плотными и менее читаемыми. Новая реализация добавит пустые строки в соответствии с требованиями для каждой команды.

## Архитектура

Изменения затронут следующие компоненты:

1. **SearchCommandHandler** - обработчик команды `/search`
2. **FilterCommandHandler** - обработчик команды `/filter`
3. **WeekCommandHandler** - обработчик команды `/week`
4. **UpcomingEventsCommandHandler** - обработчик команды `/upcoming_events`

Все изменения будут локальными в пределах методов форматирования результатов. Класс `EventFormatter` не требует изменений, так как он предоставляет метод `formatDaySeparator()`, который возвращает только саму линию без пустых строк.

## Компоненты и интерфейсы

### SearchCommandHandler

**Текущая реализация:**
```java
// Добавляем разделитель между событиями (но не после последнего)
if (i < results.size() - 1) {
    messageBuilder.append(EventFormatter.formatDaySeparator());
    messageBuilder.append(escape("\n"));
}
```

**Новая реализация:**
```java
// Добавляем разделитель между событиями (но не после последнего)
if (i < results.size() - 1) {
    messageBuilder.append(escape("\n"));  // Пустая строка ПЕРЕД разделителем
    messageBuilder.append(EventFormatter.formatDaySeparator());
    messageBuilder.append(escape("\n\n")); // Пустая строка ПОСЛЕ разделителя
}
```

### FilterCommandHandler

**Текущая реализация:**
```java
// Добавляем разделитель между событиями (но не после последнего)
if (i < results.size() - 1) {
    messageBuilder.append("\n").append(escape("─────────────────────")).append("\n");
}
```

**Новая реализация:**
```java
// Добавляем разделитель между событиями (но не после последнего)
if (i < results.size() - 1) {
    messageBuilder.append("\n\n")  // Пустая строка ПЕРЕД разделителем
                  .append(escape("─────────────────────"))
                  .append("\n\n");  // Пустая строка ПОСЛЕ разделителя
}
```

### WeekCommandHandler

**Текущая реализация:**
```java
// Добавляем разделитель перед каждым днем, кроме первого
if (!firstDay) {
    messageBuilder.append(EventFormatter.formatDaySeparator());
    messageBuilder.append(escape("\n"));
}
firstDay = false;
```

**Новая реализация:**
```java
// Добавляем разделитель перед каждым днем, кроме первого
if (!firstDay) {
    messageBuilder.append(EventFormatter.formatDaySeparator());
    messageBuilder.append(escape("\n\n")); // Пустая строка ПОСЛЕ разделителя
}
firstDay = false;
```

### UpcomingEventsCommandHandler

**Текущая реализация:**

```java
if (!firstDay) {
```

```java
    messageBuilder.append(escape("\n\n")); // Пустая строка ПОСЛЕ разделителя

```

## Модели данных

Изменения не затрагивают модели данных. Все изменения касаются только форматирования строк.

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться во всех допустимых выполнениях системы - по сути, формальное утверждение о том, что должна делать система. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*


### Property 1: Правильное форматирование разделителей между событиями в поиске

*For any* результатов поиска с несколькими событиями, разделительная линия между событиями должна иметь пустую строку до и после себя (паттерн: `\n\n─────\n\n`)

**Validates: Requirements 1.1, 1.2**

### Property 2: Правильное форматирование разделителей между событиями в фильтрации

*For any* результатов фильтрации с несколькими событиями, разделительная линия между событиями должна иметь пустую строку до и после себя (паттерн: `\n\n─────\n\n`)

**Validates: Requirements 2.1, 2.2**

### Property 3: Отсутствие разделителя после последнего события

*For any* результатов поиска или фильтрации, разделительная линия не должна появляться после последнего события в списке

**Validates: Requirements 1.3, 2.3**

### Property 4: Правильное форматирование разделителей между днями

*For any* результатов команд week или upcoming_events с несколькими днями, разделительная линия между днями должна иметь пустую строку после себя (паттерн: `─────\n\n`)

**Validates: Requirements 3.1, 4.1**

### Property 5: Отсутствие разделителя перед первым днем

*For any* результатов команд week или upcoming_events, разделительная линия не должна появляться перед первым днем после заголовка команды

**Validates: Requirements 3.2, 4.2**

### Property 6: Единообразие визуального представления разделителей

*For all* команд списка событий (search, filter, week, upcoming_events), разделительная линия должна использовать одинаковый символ и длину

**Validates: Requirements 5.2**

## Обработка ошибок

Изменения не вводят новых точек отказа. Все изменения касаются только форматирования строк, которое выполняется в памяти. Существующая обработка ошибок в командах остается без изменений.

## Стратегия тестирования

### Unit тесты

Для каждой измененной команды необходимо добавить или обновить unit тесты, проверяющие:

1. **SearchCommandHandler**:
   - Правильное форматирование разделителей между событиями
   - Отсутствие разделителя после последнего события
   - Правильное количество пустых строк вокруг разделителей

2. **FilterCommandHandler**:
   - Правильное форматирование разделителей между событиями
   - Отсутствие разделителя после последнего события
   - Правильное количество пустых строк вокруг разделителей

3. **WeekCommandHandler**:
   - Правильное форматирование разделителей между днями
   - Отсутствие разделителя перед первым днем
   - Правильное количество пустых строк после разделителей

4. **UpcomingEventsCommandHandler**:
   - Правильное форматирование разделителей между днями
   - Отсутствие разделителя перед первым днем
   - Правильное количество пустых строк после разделителей

### Property-based тесты

Для проверки универсальных свойств необходимо написать property-based тесты:

1. **Property Test 1**: Проверка форматирования разделителей в поиске
   - Генерировать случайные списки событий (2-10 событий)
   - Проверять наличие паттерна `\n\n─────\n\n` между событиями
   - Проверять отсутствие разделителя после последнего события

2. **Property Test 2**: Проверка форматирования разделителей в фильтрации
   - Генерировать случайные списки событий (2-10 событий)
   - Проверять наличие паттерна `\n\n─────\n\n` между событиями
   - Проверять отсутствие разделителя после последнего события

3. **Property Test 3**: Проверка форматирования разделителей между днями
   - Генерировать случайные списки событий на несколько дней (2-7 дней)
   - Проверять наличие паттерна `─────\n\n` между днями
   - Проверять отсутствие разделителя перед первым днем

4. **Property Test 4**: Проверка единообразия разделителей
   - Генерировать случайные списки событий для всех команд
   - Проверять, что все команды используют одинаковый символ разделителя
   - Проверять, что длина разделителя одинакова во всех командах

### Тестовая конфигурация

- Минимум 100 итераций для каждого property-based теста
- Использование библиотеки jqwik для property-based тестирования в Java
- Каждый тест должен быть помечен комментарием с ссылкой на свойство из дизайна

### Ручное тестирование

После внедрения изменений необходимо выполнить ручное тестирование:

1. Выполнить команду `/search` с запросом, возвращающим несколько событий
2. Выполнить команду `/filter` для каждого типа фильтра
3. Выполнить команду `/week` с событиями на несколько дней
4. Выполнить команду `/upcoming_events` с событиями на несколько дней
5. Проверить визуальное восприятие разделителей в Telegram клиенте
