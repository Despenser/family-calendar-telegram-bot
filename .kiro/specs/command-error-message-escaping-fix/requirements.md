# Requirements Document

## Introduction

В Telegram боте обнаружена проблема с экранированием специальных символов MarkdownV2 в сообщениях об ошибках команд. При попытке пользователя ввести некорректную команду (не начинающуюся с '/') или при добавлении заметки к завершенному событию, бот пытается отправить сообщение с неэкранированными специальными символами, что приводит к ошибке парсинга MarkdownV2.

Ошибка проявляется в логах:
```
Bad Request (400): Ошибка парсинга MarkdownV2. 
telegramId=526536667, textPreview='Команда должна начинаться с символа '/'. 
Используйте /help для списка доступных команд.', fullTextLength=87, 
response=Bad Request: can't parse entities: Character '.' is reserved and must be 
escaped with the preceding '\'
```

Проблема возникает в двух местах:
1. `UpdateProcessor.java` (строка 1635-1637)
2. `CommandDispatcher.java` (строка 157)

В обоих случаях используется конкатенация строк с частичным экранированием только команды `/help`, но не статического текста, содержащего точки и апострофы.

## Glossary

- **MarkdownV2**: Формат разметки текста, используемый Telegram Bot API для форматирования сообщений
- **Специальные символы MarkdownV2**: Символы, требующие экранирования: `_`, `*`, `[`, `]`, `(`, `)`, `~`, `` ` ``, `>`, `#`, `+`, `-`, `=`, `|`, `{`, `}`, `.`, `!`, `'`
- **Экранирование**: Добавление обратного слеша (`\`) перед специальным символом
- **MarkdownFormatter**: Утилитный класс для экранирования специальных символов MarkdownV2
- **UpdateProcessor**: Сервис для обработки обновлений от Telegram
- **CommandDispatcher**: Сервис для маршрутизации команд к соответствующим обработчикам

## Requirements

### Requirement 1

**User Story:** Как пользователь бота, я хочу получать корректно отформатированные сообщения об ошибках команд, чтобы понимать, что я сделал неправильно.

#### Acceptance Criteria

1. WHEN пользователь вводит текст, не начинающийся с '/' THEN система SHALL отправить сообщение об ошибке без ошибок парсинга MarkdownV2
2. WHEN система формирует сообщение об ошибке команды THEN система SHALL экранировать все специальные символы MarkdownV2 в тексте сообщения
3. WHEN пользователь получает сообщение об ошибке THEN сообщение SHALL содержать корректно отформатированную ссылку на команду /help
4. WHEN система отправляет сообщение через TelegramMessageService THEN сообщение SHALL быть полностью экранировано

### Requirement 2

**User Story:** Как разработчик бота, я хочу использовать единый метод для формирования всех сообщений, чтобы избежать ошибок экранирования.

#### Acceptance Criteria

1. WHEN разработчик формирует сообщение с переменными THEN система SHALL предоставлять метод `MarkdownFormatter.formatMessage()` для безопасного форматирования
2. WHEN разработчик использует `formatMessage()` THEN система SHALL автоматически экранировать как статический текст, так и переменные части
3. WHEN разработчик заменяет конкатенацию строк на `formatMessage()` THEN код SHALL стать более читаемым и безопасным
4. WHEN в коде используется `String.format()` или конкатенация для формирования сообщений THEN разработчик SHALL заменить их на `MarkdownFormatter.formatMessage()`

### Requirement 3

**User Story:** Как разработчик бота, я хочу иметь тесты для проверки корректности экранирования сообщений об ошибках, чтобы предотвратить регрессии.

#### Acceptance Criteria

1. WHEN выполняются тесты UpdateProcessor THEN система SHALL проверять корректность экранирования сообщения об ошибке команды
2. WHEN выполняются тесты CommandDispatcher THEN система SHALL проверять корректность экранирования сообщения об ошибке команды
3. WHEN добавляется новое сообщение об ошибке THEN разработчик SHALL добавить тест для проверки экранирования
4. WHEN тесты проверяют экранирование THEN система SHALL тестировать все специальные символы MarkdownV2

### Requirement 4

**User Story:** Как администратор системы, я хочу, чтобы в логах не было ошибок парсинга MarkdownV2, чтобы система работала стабильно.

#### Acceptance Criteria

1. WHEN пользователь вводит некорректную команду THEN в логах SHALL отсутствовать ошибки "Bad Request (400): Ошибка парсинга MarkdownV2"
2. WHEN система отправляет любое сообщение THEN в логах SHALL отсутствовать ошибки парсинга MarkdownV2
3. WHEN происходит ошибка отправки сообщения THEN система SHALL логировать детальную информацию для отладки
4. WHEN система работает в production THEN количество ошибок парсинга MarkdownV2 SHALL быть равно нулю
