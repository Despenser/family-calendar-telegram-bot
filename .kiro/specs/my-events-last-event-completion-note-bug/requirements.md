# Requirements Document

## Введение

При завершении последнего события в списке "Мои события" система отправляет сообщение "У вас пока нет созданных событий" **до того**, как пользователь выбрал "Добавить заметку" или "Пропустить". Проблема заключается в том, что метод `completeEventWithReordering` вызывает `updateMyEventsHeaderAfterRemoval` сразу после отправки сообщения с предложением добавить заметку. На этот момент событие уже завершено (статус COMPLETED), поэтому список активных событий пуст, и система преждевременно отправляет сообщение о пустом состоянии.

## Глоссарий

- **EventService**: Сервис для работы с событиями
- **completeEventWithReordering**: Метод завершения события с переупорядочиванием списка
- **ConversationStateService**: Сервис управления состоянием диалогов пользователей
- **CompletionNoteContext**: Контекст добавления заметки к завершенному событию
- **EventCallbackHandler**: Обработчик callback queries для операций с событиями
- **UpdateProcessor**: Процессор обновлений от Telegram Bot API
- **Последнее событие**: Событие, которое находится в конце списка "Мои события" (не требует переупорядочивания)
- **updateMyEventsHeaderAfterRemoval**: Метод обновления шапки /my_events после удаления события из активных

## Требования

### Требование 1

**User Story:** Как пользователь, я хочу чтобы при завершении последнего события в списке "Мои события" мне предлагалось добавить заметку БЕЗ преждевременного сообщения о пустом состоянии, чтобы я мог спокойно выбрать "Добавить заметку" или "Пропустить".

#### Критерии приемки

1. WHEN пользователь завершает последнее событие в списке "Мои события" THEN система SHALL отправить сообщение с предложением добавить заметку
2. WHEN пользователь завершает последнее событие в списке "Мои события" THEN система SHALL установить контекст ожидания заметки через `conversationStateService.setAwaitingCompletionNote`
3. WHEN пользователь завершает последнее событие в списке "Мои события" THEN система SHALL отобразить кнопки "📝 Добавить заметку" и "⏭️ Пропустить"
4. WHEN пользователь завершает последнее событие в списке "Мои события" THEN система SHALL НЕ вызывать `updateMyEventsHeaderAfterRemoval` до выбора пользователя
5. WHEN пользователь завершает НЕ последнее событие в списке "Мои события" THEN система SHALL выполнить переупорядочивание и установить контекст ожидания заметки

### Требование 2

**User Story:** Как пользователь, я хочу чтобы сообщение "У вас пока нет созданных событий" появлялось ТОЛЬКО после того, как я добавил заметку или пропустил её, чтобы я не видел это сообщение преждевременно.

#### Критерии приемки

1. WHEN пользователь завершает последнее событие и добавляет заметку THEN система SHALL вызвать `updateMyEventsHeaderAfterRemoval` ПОСЛЕ сохранения заметки
2. WHEN пользователь завершает последнее событие и пропускает добавление заметки THEN система SHALL вызвать `updateMyEventsHeaderAfterRemoval` ПОСЛЕ пропуска
3. WHEN `updateMyEventsHeaderAfterRemoval` вызван и список активных событий пуст THEN система SHALL отправить сообщение "У вас пока нет созданных событий"
4. WHEN пользователь завершает последнее событие THEN система SHALL НЕ вызывать `updateMyEventsHeaderAfterRemoval` в методе `completeEventWithReordering`

### Требование 3

**User Story:** Как разработчик, я хочу чтобы обновление шапки /my_events происходило в правильный момент, чтобы избежать преждевременных сообщений о пустом состоянии.

#### Критерии приемки

1. WHEN метод `completeEventWithReordering` завершает последнее событие THEN система SHALL НЕ вызывать `updateMyEventsHeaderAfterRemoval`
2. WHEN метод `completeEventWithReordering` завершает НЕ последнее событие THEN система SHALL вызвать `updateMyEventsHeaderAfterRemoval` через `reorderMyEventsList`
3. WHEN пользователь добавляет заметку к завершенному событию THEN система SHALL вызвать `updateMyEventsHeaderAfterRemoval` в `UpdateProcessor`
4. WHEN пользователь пропускает добавление заметки THEN система SHALL вызвать `updateMyEventsHeaderAfterRemoval` в `EventCallbackHandler`
