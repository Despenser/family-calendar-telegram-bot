# Требования: Удаление сообщений событий из чата

## Введение

При выполнении определенных действий с событиями (удаление навсегда, восстановление из корзины, удаление/завершение из списка моих событий) необходимо красиво удалять соответствующие сообщения из чата Telegram, чтобы поддерживать чистоту интерфейса и избежать устаревших сообщений.

## Глоссарий

- **Система** - Telegram-бот семейного календаря
- **Пользователь** - авторизованный пользователь бота
- **Событие** - запись в календаре с датой, временем и описанием
- **Сообщение события** - сообщение в чате Telegram, отображающее информацию о событии
- **Корзина** - временное хранилище удаленных событий
- **Список моих событий** - список событий, отображаемый командой /my_events

## Требования

### Требование 1

**User Story:** Как пользователь, я хочу, чтобы сообщение события автоматически удалялось из чата при удалении события навсегда из корзины, чтобы в чате не оставались устаревшие сообщения.

#### Критерии приемки

1. WHEN пользователь удаляет событие навсегда из корзины THEN Система SHALL удалить соответствующее сообщение события из чата Telegram
2. WHEN сообщение события успешно удалено THEN Система SHALL логировать успешное удаление на уровне DEBUG
3. IF удаление сообщения события завершается ошибкой THEN Система SHALL логировать ошибку на уровне WARN и продолжить выполнение операции удаления события
4. WHEN событие не имеет связанного messageId THEN Система SHALL пропустить попытку удаления сообщения и продолжить выполнение

### Требование 2

**User Story:** Как пользователь, я хочу, чтобы сообщение события автоматически удалялось из чата при восстановлении события из корзины, чтобы старое сообщение не конфликтовало с новым.

#### Критерии приемки

1. WHEN пользователь восстанавливает событие из корзины THEN Система SHALL удалить старое сообщение события из чата Telegram
2. WHEN старое сообщение успешно удалено THEN Система SHALL создать новое сообщение события с актуальной информацией
3. IF удаление старого сообщения завершается ошибкой THEN Система SHALL логировать ошибку на уровне WARN и продолжить создание нового сообщения
4. WHEN восстановленное событие не имеет связанного messageId THEN Система SHALL пропустить попытку удаления и создать новое сообщение

### Требование 3

**User Story:** Как пользователь, я хочу, чтобы сообщение события автоматически удалялось из чата при удалении события из списка /my_events, чтобы в чате не оставались сообщения об удаленных событиях.

#### Критерии приемки

1. WHEN пользователь удаляет событие через список /my_events THEN Система SHALL удалить соответствующее сообщение события из чата Telegram
2. WHEN сообщение события успешно удалено THEN Система SHALL обновить список моих событий без удаленного события
3. IF удаление сообщения события завершается ошибкой THEN Система SHALL логировать ошибку на уровне WARN и продолжить обновление списка
4. WHEN удаленное событие перемещается в корзину THEN Система SHALL сохранить messageId для возможного восстановления

### Требование 4

**User Story:** Как пользователь, я хочу, чтобы сообщение события автоматически удалялось из чата при завершении события из списка /my_events, чтобы в чате отображались только активные события.

#### Критерии приемки

1. WHEN пользователь завершает событие через список /my_events THEN Система SHALL удалить соответствующее сообщение события из чата Telegram
2. WHEN сообщение события успешно удалено THEN Система SHALL обновить список моих событий без завершенного события
3. IF удаление сообщения события завершается ошибкой THEN Система SHALL логировать ошибку на уровне WARN и продолжить обновление списка
4. WHEN событие завершается THEN Система SHALL обновить статус события в базе данных перед удалением сообщения

### Требование 5

**User Story:** Как разработчик, я хочу иметь централизованный механизм удаления сообщений событий, чтобы обеспечить консистентность поведения во всех частях системы.

#### Критерии приемки

1. WHEN любой компонент системы требует удаления сообщения события THEN Система SHALL использовать единый сервисный метод для выполнения операции
2. WHEN метод удаления сообщения вызывается THEN Система SHALL проверять наличие messageId перед попыткой удаления
3. WHEN метод удаления сообщения вызывается THEN Система SHALL обрабатывать все исключения Telegram API и логировать их
4. WHEN удаление сообщения выполняется успешно THEN Система SHALL возвращать признак успешного выполнения операции
5. IF сообщение уже удалено или не существует THEN Система SHALL обрабатывать ситуацию gracefully без выброса исключения
