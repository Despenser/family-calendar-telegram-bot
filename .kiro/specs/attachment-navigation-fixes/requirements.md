# Requirements Document

## Introduction

Данный документ описывает требования к исправлению проблем с навигацией и редактированием сообщений при работе с вложениями событий в Telegram боте семейного календаря. Существующая реализация имеет две критические проблемы: потеря шапки сообщения при возврате к событию и создание отдельного подтверждающего сообщения при загрузке файла вместо редактирования существующего.

## Glossary

- **Event_Message**: Сообщение Telegram, отображающее информацию о событии календаря
- **Event_Header**: Шапка сообщения о событии, содержащая контекстную информацию (например, "📋 Мои события")
- **Attachment_List_Message**: Сообщение Telegram, отображающее список вложений события
- **Confirmation_Message**: Отдельное сообщение с подтверждением успешной операции
- **Message_Edit**: Операция редактирования существующего сообщения Telegram вместо отправки нового
- **Conversation_State**: Состояние диалога пользователя с ботом, хранящее контекст текущего взаимодействия
- **Message_Context**: Контекст сообщения, включающий messageId и chatId для последующего редактирования
- **Back_Button**: Кнопка навигации "Назад", возвращающая пользователя к предыдущему экрану

## Requirements

### Requirement 1: Сохранение шапки сообщения при возврате к событию

**User Story:** Как пользователь, я хочу видеть полную информацию о событии при возврате из списка вложений, чтобы понимать контекст просматриваемого события.

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "Назад к событию" (attach_file_back) THEN система SHALL отобразить сообщение о событии с сохраненной шапкой
2. WHEN событие было первым в списке "Мои события" THEN система SHALL включить шапку "📋 Мои события" в отображаемое сообщение
3. WHEN событие было открыто из другого контекста THEN система SHALL использовать соответствующую шапку для этого контекста
4. WHEN контекст шапки не сохранен в состоянии диалога THEN система SHALL отобразить сообщение о событии без шапки

### Requirement 2: Редактирование сообщения при загрузке вложения

**User Story:** Как пользователь, я хочу видеть обновленный список вложений сразу после загрузки файла в том же сообщении, чтобы избежать загромождения чата множеством сообщений.

#### Acceptance Criteria

1. WHEN пользователь загружает файл в качестве вложения THEN система SHALL редактировать существующее сообщение со списком вложений
2. WHEN файл успешно загружен THEN система SHALL NOT отправлять отдельное подтверждающее сообщение
3. WHEN сообщение со списком вложений не может быть отредактировано THEN система SHALL отправить новое сообщение со списком вложений
4. WHEN редактирование сообщения выполнено успешно THEN система SHALL сохранить новый messageId в состоянии диалога
5. WHEN загрузка файла завершена THEN обновленное сообщение SHALL содержать новый файл в списке вложений

### Requirement 3: Навигация из просмотра файла к списку вложений

**User Story:** Как пользователь, я хочу иметь возможность вернуться к списку вложений после просмотра файла, чтобы продолжить работу с другими вложениями.

#### Acceptance Criteria

1. WHEN пользователь просматривает файл вложения THEN система SHALL отобразить кнопку "Назад к вложениям"
2. WHEN пользователь нажимает кнопку "Назад к вложениям" THEN система SHALL отобразить список всех вложений события
3. WHEN пользователь возвращается к списку вложений THEN система SHALL редактировать текущее сообщение вместо отправки нового
4. WHEN редактирование невозможно THEN система SHALL отправить новое сообщение со списком вложений

### Requirement 4: Сохранение контекста сообщений в состоянии диалога

**User Story:** Как система, я должна сохранять контекст сообщений для корректного редактирования, чтобы обеспечить плавную навигацию пользователя.

#### Acceptance Criteria

1. WHEN система отображает сообщение о событии THEN система SHALL сохранить контекст шапки сообщения в состоянии диалога
2. WHEN система отображает список вложений THEN система SHALL сохранить messageId и chatId в состоянии диалога
3. WHEN пользователь переходит между экранами THEN система SHALL использовать сохраненный контекст для редактирования сообщений
4. WHEN состояние диалога содержит messageId THEN система SHALL попытаться отредактировать это сообщение перед отправкой нового

### Requirement 5: Обработка ошибок редактирования сообщений

**User Story:** Как система, я должна корректно обрабатывать ситуации, когда редактирование сообщения невозможно, чтобы пользователь всегда получал актуальную информацию.

#### Acceptance Criteria

1. WHEN редактирование сообщения невозможно из-за устаревшего messageId THEN система SHALL отправить новое сообщение
2. WHEN редактирование сообщения невозможно из-за ошибки API Telegram THEN система SHALL отправить новое сообщение
3. WHEN отправлено новое сообщение вместо редактирования THEN система SHALL обновить messageId в состоянии диалога
4. WHEN произошла ошибка редактирования THEN система SHALL залогировать ошибку для последующего анализа
5. WHEN система отправляет новое сообщение после ошибки редактирования THEN пользователь SHALL получить корректную информацию без потери данных
