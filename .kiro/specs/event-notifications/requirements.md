# Документ требований

## Введение

Данная спецификация описывает реализацию системы уведомлений о предстоящих событиях для семейного календарь-бота. Система должна позволять пользователям настраивать гибкие напоминания для событий и автоматически отправлять уведомления в заданное время. В настоящее время в проекте полностью отсутствуют уведомления о предстоящих событиях - никакие уведомления не приходят и не настраиваются пользователем, хотя базовая инфраструктура (таблица reminders, модель Reminder, ReminderRepository, ReminderService) уже создана.

## Глоссарий

- **Система**: Существующее Spring Boot приложение семейного календарь-бота
- **Напоминание**: Настройка времени отправки уведомления о событии
- **Уведомление**: Telegram-сообщение, отправляемое пользователю о предстоящем событии
- **ReminderType**: Тип напоминания (morning_of_day, evening_before, one_hour_before, ten_minutes_before, custom)
- **Планировщик напоминаний**: Компонент, проверяющий и отправляющий напоминания по расписанию
- **Reminder**: Сущность, хранящая настройки напоминания для события
- **Event**: Событие в календаре, для которого настраиваются напоминания
- **TelegramMessageService**: Сервис для отправки сообщений через Telegram Bot API
- **ReminderService**: Сервис для управления напоминаниями
- **ReminderRepository**: Репозиторий для работы с напоминаниями в базе данных

## Требования

### Требование 1

**Пользовательская история:** Как член семьи, я хочу настраивать напоминания при создании события, чтобы не забыть о важных планах.

#### Критерии приемки

1. WHEN пользователь создает событие и вводит описание, THEN Система ДОЛЖНА показать inline-кнопку "🔔 Настроить напоминания"
2. WHEN пользователь нажимает кнопку настройки напоминаний, THEN Система ДОЛЖНА показать inline-меню с опциями: "Утром в день события (9:00)", "Вечером накануне (20:00)", "За 1 час до события", "За 10 минут до события", "Свое время"
3. WHEN пользователь выбирает тип напоминания, THEN Система ДОЛЖНА создать запись в таблице reminders с соответствующим reminder_type
4. WHEN пользователь выбирает "Свое время", THEN Система ДОЛЖНА запросить ввод количества минут до события
5. WHEN пользователь вводит количество минут, THEN Система ДОЛЖНА сохранить значение в поле custom_minutes и рассчитать reminder_time
6. WHEN напоминание создано, THEN Система ДОЛЖНА показать подтверждение с указанием времени отправки уведомления

### Требование 2

**Пользовательская история:** Как член семьи, я хочу настраивать несколько напоминаний для одного события, чтобы получать уведомления в разное время.

#### Критерии приемки

1. WHEN пользователь настраивает напоминания для события, THEN Система ДОЛЖНА позволить выбрать несколько типов напоминаний
2. WHEN пользователь выбирает уже выбранный тип напоминания, THEN Система ДОЛЖНА отменить выбор этого типа
3. WHEN пользователь завершает настройку напоминаний, THEN Система ДОЛЖНА создать отдельную запись в таблице reminders для каждого выбранного типа
4. WHEN напоминания сохранены, THEN Система ДОЛЖНА показать список всех настроенных напоминаний с временем отправки
5. WHEN пользователь просматривает событие с напоминаниями, THEN Система ДОЛЖНА отображать список всех настроенных напоминаний

### Требование 3

**Пользовательская история:** Как член семьи, я хочу редактировать напоминания для существующих событий, чтобы изменять настройки уведомлений.

#### Критерии приемки

1. WHEN пользователь просматривает событие с напоминаниями, THEN Система ДОЛЖНА показать inline-кнопку "🔔 Изменить напоминания"
2. WHEN пользователь нажимает кнопку изменения, THEN Система ДОЛЖНА показать текущие настройки с возможностью добавления или удаления напоминаний
3. WHEN пользователь удаляет напоминание, THEN Система ДОЛЖНА удалить соответствующую запись из таблицы reminders
4. WHEN пользователь добавляет новое напоминание, THEN Система ДОЛЖНА создать новую запись в таблице reminders с рассчитанным reminder_time
5. WHEN изменения сохранены, THEN Система ДОЛЖНА показать обновленный список напоминаний

### Требование 4

**Пользовательская история:** Как разработчик, я хочу иметь планировщик для автоматической отправки напоминаний, чтобы уведомления приходили вовремя.

#### Критерии приемки

1. WHEN приложение запускается, THEN Система ДОЛЖНА инициализировать планировщик напоминаний с интервалом проверки 1 минута
2. WHEN планировщик выполняется, THEN Система ДОЛЖНА запрашивать из базы данных все неотправленные напоминания с reminder_time <= текущее время
3. WHEN найдены напоминания для отправки, THEN Система ДОЛЖНА отправить уведомление для каждого напоминания
4. WHEN уведомление отправлено успешно, THEN Система ДОЛЖНА установить sent=true и sent_at=текущее время для напоминания
5. IF отправка уведомления не удалась, THEN Система ДОЛЖНА логировать ошибку и повторить попытку при следующем запуске планировщика

### Требование 5

**Пользовательская история:** Как член семьи, я хочу получать информативные уведомления о предстоящих событиях, чтобы знать все детали.

#### Критерии приемки

1. WHEN Система отправляет уведомление о событии, THEN Система ДОЛЖНА включать эмодзи "🔔" в начале сообщения
2. WHEN уведомление формируется, THEN Система ДОЛЖНА включать название события, дату, время начала и время окончания (если указано)
3. WHEN событие имеет описание, THEN Система ДОЛЖНА включать описание в уведомление
4. WHEN событие является персональным, THEN Система ДОЛЖНА добавить эмодзи "🔒" и текст "Персональное событие"
5. WHEN событие является семейным, THEN Система ДОЛЖНА добавить эмодзи "👨‍👩‍👧‍👦" и имя создателя события
6. WHEN уведомление отправляется, THEN Система ДОЛЖНА использовать Markdown форматирование для улучшения читаемости

### Требование 6

**Пользовательская история:** Как член семьи, я хочу, чтобы уведомления о семейных событиях приходили всем членам семьи, а о персональных - только мне.

#### Критерии приемки

1. WHEN Система отправляет уведомление о семейном событии, THEN Система ДОЛЖНА отправить уведомление всем членам семьи
2. WHEN Система отправляет уведомление о персональном событии, THEN Система ДОЛЖНА отправить уведомление только создателю события
3. WHEN уведомление отправляется члену семьи, THEN Система ДОЛЖНА использовать telegram_id пользователя для отправки
4. WHEN происходит ошибка отправки одному члену семьи, THEN Система ДОЛЖНА продолжить отправку остальным членам семьи
5. WHEN все уведомления отправлены, THEN Система ДОЛЖНА отметить напоминание как отправленное независимо от количества успешных отправок

### Требование 7

**Пользовательская история:** Как член семьи, я хочу, чтобы напоминания автоматически рассчитывались при создании события, чтобы не думать о времени отправки.

#### Критерии приемки

1. WHEN пользователь выбирает тип "Утром в день события", THEN Система ДОЛЖНА установить reminder_time на 9:00 в день события
2. WHEN пользователь выбирает тип "Вечером накануне", THEN Система ДОЛЖНА установить reminder_time на 20:00 предыдущего дня
3. WHEN пользователь выбирает тип "За 1 час до события", THEN Система ДОЛЖНА вычесть 1 час от времени начала события
4. WHEN пользователь выбирает тип "За 10 минут до события", THEN Система ДОЛЖНА вычесть 10 минут от времени начала события
5. WHEN событие не имеет времени начала, THEN Система ДОЛЖНА использовать 9:00 как время по умолчанию для расчета
6. WHEN reminder_time рассчитано, THEN Система ДОЛЖНА сохранить его в базе данных в формате TIMESTAMP

### Требование 8

**Пользовательская история:** Как член семьи, я хочу видеть inline-кнопки в уведомлениях для быстрых действий, чтобы управлять событиями без дополнительных команд.

#### Критерии приемки

1. WHEN Система отправляет уведомление о событии, THEN Система ДОЛЖНА добавить inline-кнопку "📋 Посмотреть детали"
2. WHEN пользователь нажимает "Посмотреть детали", THEN Система ДОЛЖНА показать полную информацию о событии с возможностью редактирования
3. WHEN событие создано пользователем, THEN Система ДОЛЖНА добавить inline-кнопки "✏️ Редактировать" и "🗑️ Удалить"
4. WHEN пользователь нажимает inline-кнопку в уведомлении, THEN Система ДОЛЖНА обработать callback query и выполнить соответствующее действие
5. WHEN действие выполнено, THEN Система ДОЛЖНА отправить answerCallbackQuery с подтверждением

### Требование 9

**Пользовательская история:** Как разработчик, я хочу, чтобы напоминания автоматически удалялись при удалении события, чтобы не отправлять уведомления о несуществующих событиях.

#### Критерии приемки

1. WHEN событие удаляется из базы данных, THEN Система ДОЛЖНА автоматически удалить все связанные напоминания через CASCADE
2. WHEN событие перемещается в корзину, THEN Система ДОЛЖНА сохранить напоминания, но не отправлять их
3. WHEN событие восстанавливается из корзины, THEN Система ДОЛЖНА пересчитать reminder_time для всех напоминаний
4. WHEN событие окончательно удаляется из корзины, THEN Система ДОЛЖНА удалить все связанные напоминания
5. WHEN дата или время события изменяются, THEN Система ДОЛЖНА пересчитать reminder_time для всех напоминаний

### Требование 10

**Пользовательская история:** Как разработчик, я хочу иметь логирование работы планировщика напоминаний, чтобы отслеживать отправку уведомлений и диагностировать проблемы.

#### Критерии приемки

1. WHEN планировщик запускается, THEN Система ДОЛЖНА логировать начало проверки напоминаний с уровнем DEBUG
2. WHEN найдены напоминания для отправки, THEN Система ДОЛЖНА логировать количество найденных напоминаний с уровнем INFO
3. WHEN уведомление отправлено успешно, THEN Система ДОЛЖНА логировать event_id, user_id и reminder_type с уровнем INFO
4. WHEN происходит ошибка отправки, THEN Система ДОЛЖНА логировать полный stack trace с уровнем ERROR
5. WHEN планировщик завершает работу, THEN Система ДОЛЖНА логировать количество отправленных уведомлений с уровнем INFO

### Требование 11

**Пользовательская история:** Как член семьи, я хочу, чтобы напоминания не отправлялись для событий в прошлом, чтобы не получать бесполезные уведомления.

#### Критерии приемки

1. WHEN планировщик проверяет напоминания, THEN Система ДОЛЖНА игнорировать напоминания для событий с event_date < текущая дата
2. WHEN событие с напоминаниями переходит в статус "completed", THEN Система ДОЛЖНА отметить все неотправленные напоминания как отправленные
3. WHEN событие с напоминаниями переходит в статус "deleted", THEN Система ДОЛЖНА игнорировать напоминания при проверке планировщиком
4. WHEN reminder_time находится в прошлом более чем на 1 час, THEN Система ДОЛЖНА пропустить отправку и отметить напоминание как отправленное
5. WHEN событие завершено автоматически, THEN Система ДОЛЖНА обновить статус всех связанных напоминаний

### Требование 12

**Пользовательская история:** Как член семьи, я хочу получать напоминания с учетом часового пояса, чтобы уведомления приходили в правильное время.

#### Критерии приемки

1. WHEN Система рассчитывает reminder_time, THEN Система ДОЛЖНА использовать часовой пояс сервера для всех вычислений
2. WHEN уведомление отправляется, THEN Система ДОЛЖНА форматировать время события в часовом поясе сервера
3. WHEN пользователь просматривает настроенные напоминания, THEN Система ДОЛЖНА показывать время отправки в часовом поясе сервера
4. WHEN событие создается с датой и временем, THEN Система ДОЛЖНА сохранять их в базе данных без преобразования часового пояса
5. WHEN планировщик сравнивает reminder_time с текущим временем, THEN Система ДОЛЖНА использовать одинаковый часовой пояс для обоих значений
