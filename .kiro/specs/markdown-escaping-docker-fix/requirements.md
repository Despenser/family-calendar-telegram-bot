# Requirements Document

## Introduction

Исправление ошибок парсинга MarkdownV2 в Docker-логах приложения. Telegram API возвращает ошибку "Character '.' is reserved and must be escaped with the preceding '\'" при отправке сообщений, что указывает на неправильное экранирование специальных символов в некоторых частях кода.

## Glossary

- **MarkdownV2**: Формат разметки текста, используемый Telegram Bot API для форматирования сообщений
- **Экранирование**: Процесс добавления обратного слеша (\) перед специальными символами
- **MarkdownFormatter**: Утилитный класс для корректного экранирования текста в формате MarkdownV2
- **Специальные символы**: Символы, требующие экранирования в MarkdownV2: _ * [ ] ( ) ~ ` > # + - = | { } . !

## Requirements

### Requirement 1

**User Story:** Как разработчик, я хочу, чтобы все сообщения об удалении событий корректно отправлялись в Telegram, чтобы пользователи получали подтверждения своих действий.

#### Acceptance Criteria

1. WHEN система формирует сообщение об удалении события THEN система SHALL экранировать все специальные символы MarkdownV2 в статическом тексте сообщения
2. WHEN сообщение содержит точки в тексте THEN система SHALL экранировать каждую точку символом обратного слеша
3. WHEN сообщение отправляется в Telegram THEN Telegram API SHALL успешно принять сообщение без ошибок парсинга
4. WHEN пользователь удаляет событие THEN система SHALL отправить сообщение "✅ Событие удалено" с корректно экранированным текстом

### Requirement 2

**User Story:** Как разработчик, я хочу, чтобы сообщения корзины корректно отображались в Telegram, чтобы пользователи могли просматривать удаленные события.

#### Acceptance Criteria

1. WHEN система формирует список удаленных событий THEN система SHALL экранировать все специальные символы в датах и временах
2. WHEN сообщение содержит форматированные даты с точками THEN система SHALL экранировать точки в датах
3. WHEN сообщение содержит текст "Удаленные события хранятся 30 дней" THEN система SHALL корректно экранировать все специальные символы
4. WHEN система отправляет сообщение корзины THEN Telegram API SHALL успешно принять сообщение без ошибок парсинга

### Requirement 3

**User Story:** Как разработчик, я хочу использовать единый подход к форматированию сообщений, чтобы избежать ошибок экранирования в будущем.

#### Acceptance Criteria

1. WHEN код формирует сообщение с динамическими данными THEN код SHALL использовать метод formatMessage из MarkdownFormatter
2. WHEN код использует String.format для MarkdownV2 сообщений THEN код SHALL заменить его на formatMessage
3. WHEN статический текст содержит специальные символы THEN текст SHALL быть обернут в вызов escape()
4. WHEN разработчик добавляет новое сообщение THEN система SHALL обеспечить использование MarkdownFormatter для всех частей сообщения
