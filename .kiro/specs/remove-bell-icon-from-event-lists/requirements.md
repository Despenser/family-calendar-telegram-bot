# Requirements Document

## Introduction

Данная спецификация описывает требования к удалению отображения эмодзи колокольчика (🔔) рядом с названием события в списках команд `/today`, `/week` и `/upcoming_events`. В настоящее время колокольчик отображается, когда для события включены напоминания, что создаёт визуальный шум и не несёт критической информации для пользователя в контексте просмотра списков событий.

## Glossary

- **Event_List**: Список событий, отображаемый в ответ на команды `/today`, `/week` или `/upcoming_events`
- **Bell_Icon**: Эмодзи колокольчика (🔔), отображаемый рядом с названием события
- **Event_Formatter**: Утилитный класс `EventFormatter`, отвечающий за форматирование событий
- **Reminder_Status**: Статус наличия активных напоминаний для события (включены/выключены)

## Requirements

### Requirement 1: Удаление колокольчика из списков событий

**User Story:** Как пользователь, я хочу видеть чистые списки событий без колокольчика, чтобы интерфейс был менее загромождённым и более читаемым.

#### Acceptance Criteria

1. WHEN пользователь вызывает команду `/today`, THE System SHALL отображать события без эмодзи колокольчика (🔔) рядом с названием
2. WHEN пользователь вызывает команду `/week`, THE System SHALL отображать события без эмодзи колокольчика (🔔) рядом с названием
3. WHEN пользователь вызывает команду `/upcoming_events`, THE System SHALL отображать события без эмодзи колокольчика (🔔) рядом с названием
4. WHEN событие имеет активные напоминания, THE System SHALL НЕ отображать колокольчик в списках событий
5. WHEN событие не имеет активных напоминаний, THE System SHALL НЕ отображать колокольчик в списках событий

### Requirement 2: Сохранение колокольчика в других местах

**User Story:** Как пользователь, я хочу видеть индикатор напоминаний в детальном просмотре события, чтобы понимать, настроены ли уведомления.

#### Acceptance Criteria

1. WHEN пользователь просматривает детальную информацию о событии в команде `/my_events`, THE System SHALL продолжать отображать колокольчик (🔔) если есть активные напоминания
2. WHEN пользователь просматривает уведомления о напоминаниях, THE System SHALL продолжать использовать колокольчик (🔔) в сообщениях
3. WHEN пользователь настраивает напоминания, THE System SHALL продолжать использовать колокольчик (🔔) в интерфейсе настройки

### Requirement 3: Обратная совместимость форматирования

**User Story:** Как разработчик, я хочу сохранить существующий API класса EventFormatter, чтобы не нарушить работу других частей системы.

#### Acceptance Criteria

1. WHEN метод `formatEvent(Event, User, boolean)` вызывается с параметром `hasReminders`, THE System SHALL игнорировать значение этого параметра и не отображать колокольчик
2. WHEN существующий код вызывает методы форматирования, THE System SHALL продолжать работать без ошибок
3. WHEN тесты проверяют форматирование событий, THE System SHALL проходить все существующие тесты после удаления колокольчика
