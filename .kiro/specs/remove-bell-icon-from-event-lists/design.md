# Design Document

## Overview

Данный документ описывает проектное решение для удаления отображения эмодзи колокольчика (🔔) рядом с названием события в списках команд `/today`, `/week` и `/upcoming_events`. Решение фокусируется на минимальных изменениях в классе `EventFormatter`, сохраняя обратную совместимость API и не затрагивая другие части системы, где колокольчик используется (уведомления, детальный просмотр событий, настройка напоминаний).

## Architecture

### Текущая архитектура

В настоящее время система использует следующую архитектуру для отображения событий:

1. **Command Handlers** (`TodayCommandHandler`, `WeekCommandHandler`, `UpcomingEventsCommandHandler`) - получают события из `EventService` и проверяют наличие напоминаний через `ReminderService`
2. **EventFormatter** - утилитный класс, который форматирует события в единообразном стиле
3. **ReminderService** - сервис, который проверяет наличие активных напоминаний для события

Текущий поток данных:
```
CommandHandler → EventService.getUpcomingEvents()
              → ReminderService.hasActiveReminders(eventId)
              → EventFormatter.formatEvent(event, user, hasReminders)
              → Отображение с колокольчиком если hasReminders = true
```

### Целевая архитектура

После изменений архитектура останется прежней, но метод `EventFormatter.formatEvent()` будет игнорировать параметр `hasReminders`:

```
CommandHandler → EventService.getUpcomingEvents()
              → ReminderService.hasActiveReminders(eventId) [вызов остаётся, но результат не используется]
              → EventFormatter.formatEvent(event, user, hasReminders)
              → Отображение БЕЗ колокольчика независимо от hasReminders
```

Вызовы `ReminderService.hasActiveReminders()` останутся в коде для обратной совместимости, но их результат не будет влиять на отображение.

## Components and Interfaces

### EventFormatter

**Изменяемый компонент:** `src/main/java/ru/golubyatnikov/family/calendar/bot/util/EventFormatter.java`

**Изменяемый метод:**
```java
public static String formatEvent(Event event, User currentUser, boolean hasReminders)
```

**Текущая реализация (строки 110-115):**
```java
sb.append(bold(event.getTitle()));

// Добавляем эмодзи 🔔 если есть напоминания (Требование 9.1)
if (hasReminders) {
    sb.append(escape(" 🔔"));
}
```

**Новая реализация:**
```java
sb.append(bold(event.getTitle()));

// Колокольчик больше не отображается в списках событий (Требование 1.1, 1.2, 1.3)
// Параметр hasReminders сохранён для обратной совместимости API
```

**Обоснование:**
- Удаляется условие `if (hasReminders)` и строка с добавлением колокольчика
- Параметр `hasReminders` остаётся в сигнатуре метода для обратной совместимости
- Комментарий обновляется для объяснения изменения

### Command Handlers

**Затрагиваемые компоненты:**
- `src/main/java/ru/golubyatnikov/family/calendar/bot/handler/TodayCommandHandler.java`
- `src/main/java/ru/golubyatnikov/family/calendar/bot/handler/WeekCommandHandler.java`
- `src/main/java/ru/golubyatnikov/family/calendar/bot/handler/UpcomingEventsCommandHandler.java`

**Изменения:** НЕ ТРЕБУЮТСЯ

Обработчики команд продолжат вызывать `reminderService.hasActiveReminders(event.getId())` и передавать результат в `EventFormatter.formatEvent()`. Это сохраняет обратную совместимость и не требует изменений в логике обработчиков.

**Обоснование:**
- Минимизация изменений в кодовой базе
- Сохранение существующей структуры кода
- Возможность быстрого возврата функциональности при необходимости

### MyEventsCommandHandler

**Компонент:** `src/main/java/ru/golubyatnikov/family/calendar/bot/handler/MyEventsCommandHandler.java`

**Изменения:** НЕ ТРЕБУЮТСЯ

Этот обработчик использует собственное форматирование для детального просмотра событий (строки 568-574) и должен продолжать отображать колокольчик:

```java
details.append("📌 ").append(bold(event.getTitle()));

// Добавляем эмодзи 🔔 если есть напоминания (Требование 9.1)
boolean hasReminders = reminderService.hasActiveReminders(eventId);
if (hasReminders) {
    details.append(escape(" 🔔"));
}
```

**Обоснование:**
- Требование 2.1 явно указывает, что колокольчик должен сохраниться в детальном просмотре
- `MyEventsCommandHandler` не использует `EventFormatter.formatEvent()`, поэтому не затрагивается изменениями

## Data Models

Изменения в моделях данных не требуются. Все существующие модели (`Event`, `User`, `Reminder`) остаются без изменений.

## Correctness Properties

*Свойство - это характеристика или поведение, которое должно выполняться во всех допустимых выполнениях системы - по сути, формальное утверждение о том, что система должна делать. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Property 1: Отсутствие колокольчика в списках событий

*Для любого* события и любого пользователя, когда событие форматируется для отображения в списках команд `/today`, `/week` или `/upcoming_events`, результат форматирования НЕ должен содержать эмодзи колокольчика (🔔) независимо от наличия активных напоминаний.

**Validates: Requirements 1.1, 1.2, 1.3, 1.4, 1.5**

### Property 2: Сохранение колокольчика в детальном просмотре

*Для любого* события с активными напоминаниями, когда событие отображается в детальном просмотре команды `/my_events`, результат форматирования ДОЛЖЕН содержать эмодзи колокольчика (🔔).

**Validates: Requirements 2.1**

### Property 3: Обратная совместимость API

*Для любого* вызова метода `EventFormatter.formatEvent(Event, User, boolean)` с любыми допустимыми параметрами, метод ДОЛЖЕН выполниться без ошибок и вернуть корректно отформатированную строку.

**Validates: Requirements 3.1, 3.2**

## Error Handling

Изменения не вводят новых сценариев ошибок. Существующая обработка ошибок в `EventFormatter` остаётся без изменений:

- `IllegalArgumentException` при `event == null`
- `IllegalArgumentException` при `currentUser == null`

## Implementation Notes

### Минимальность изменений

Решение спроектировано с фокусом на минимальные изменения:
- Изменяется только 1 файл: `EventFormatter.java`
- Удаляется только 3 строки кода (условие и добавление колокольчика)
- Обновляется комментарий для документирования изменения
- Все остальные компоненты остаются без изменений

### Обратная совместимость

- Сигнатура метода `formatEvent(Event, User, boolean)` не меняется
- Параметр `hasReminders` остаётся, но игнорируется
- Вызовы `reminderService.hasActiveReminders()` остаются в обработчиках команд
- Это позволяет легко вернуть функциональность при необходимости

### Scope изменений

**Изменяется:**
- `EventFormatter.formatEvent()` - удаление отображения колокольчика

**НЕ изменяется:**
- Command handlers (`TodayCommandHandler`, `WeekCommandHandler`, `UpcomingEventsCommandHandler`)
- `MyEventsCommandHandler` - продолжает отображать колокольчик в детальном просмотре
- `ReminderService` - продолжает работать без изменений
- `NotificationService` - продолжает использовать колокольчик в уведомлениях
- `ReminderCallbackHandler` - продолжает использовать колокольчик в настройках
- Модели данных
- Базы данных

## Performance Considerations

Изменения не влияют на производительность:
- Удаление условия `if (hasReminders)` может незначительно улучшить производительность
- Вызовы `reminderService.hasActiveReminders()` остаются, но их результат не используется
- При необходимости оптимизации можно удалить эти вызовы в будущем

## Security Considerations

Изменения не влияют на безопасность системы. Все существующие проверки авторизации и валидации остаются без изменений.
