# Документ требований

## Введение

Данная фича обеспечивает единообразие пользовательского интерфейса в процессе создания события в Telegram боте семейного календаря. Все сообщения, отображаемые пользователю во время создания события, должны иметь единую жирную шапку "📅 Создание нового события" для улучшения визуальной согласованности и пользовательского опыта.

## Глоссарий

- **Система** (System): Telegram бот семейного календаря
- **Процесс_Создания_События** (Event_Creation_Process): Последовательность шагов, через которые проходит пользователь при создании нового события
- **Шапка_Сообщения** (Message_Header): Жирный заголовок "📅 Создание нового события", отображаемый в начале сообщения
- **Сообщение_Создания** (Creation_Message): Любое сообщение, отображаемое пользователю во время процесса создания события

## Требования

### Требование 1: Единообразие шапки в сообщениях

**User Story:** Как пользователь, я хочу видеть единообразную шапку во всех сообщениях при создании события, чтобы понимать, что я нахожусь в процессе создания события.

#### Критерии приемки

1. WHEN Система отображает сообщение в Процессе_Создания_События, THEN Система SHALL включить Шапку_Сообщения в начало сообщения
2. THE Шапка_Сообщения SHALL быть отформатирована жирным шрифтом с использованием Markdown
3. WHEN Шапка_Сообщения добавлена в сообщение, THEN Система SHALL добавить пустую строку после шапки для визуального разделения
4. THE Шапка_Сообщения SHALL содержать текст "📅 Создание нового события"

### Требование 2: Обновление сообщения выбора времени

**User Story:** Как пользователь, я хочу видеть шапку "📅 Создание нового события" после выбора времени, чтобы понимать контекст текущего действия.

#### Критерии приемки

1. WHEN пользователь выбирает время для события, THEN Система SHALL отобразить сообщение с Шапкой_Сообщения
2. WHEN Система отображает сообщение после выбора времени, THEN сообщение SHALL содержать выбранное время и запрос названия события
3. THE сообщение SHALL сохранить существующую функциональность запроса названия события

### Требование 3: Минимальность изменений

**User Story:** Как разработчик, я хочу внести минимальные изменения в код, чтобы не нарушить существующую функциональность.

#### Критерии приемки

1. WHEN изменения применены, THEN существующая функциональность создания события SHALL работать без изменений
2. WHEN изменения применены, THEN Система SHALL использовать существующие методы форматирования (bold())
3. THE изменения SHALL затрагивать только форматирование сообщений, не бизнес-логику
