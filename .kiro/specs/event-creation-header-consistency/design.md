# Документ проектирования

## Обзор

Данная фича обеспечивает единообразие пользовательского интерфейса в процессе создания события путем добавления единой жирной шапки "📅 Создание нового события" во все сообщения процесса создания. Это улучшает визуальную согласованность и помогает пользователю понимать контекст текущего действия.

## Архитектура

### Текущее состояние

В настоящее время шапка "📅 Создание нового события" используется непоследовательно:

1. **AddEventCommandHandler** - использует шапку при начале создания события:
   ```java
   formatMessage("📅 %s\n\nВыберите тип события:", "Создание нового события")
   ```

2. **UpdateProcessor.handleConversationMessage()** - использует шапку при обработке названия:
   ```java
   bold("📅 Создание нового события") + "\n\n" + "✅ Название: " + ...
   ```

3. **BotMessageBuilder.buildTimeSelectedMessage()** - НЕ использует шапку:
   ```java
   "✅ Время выбрано: %s\n\nТеперь отправьте название события:"
   ```

### Целевое состояние

Все сообщения в процессе создания события должны начинаться с единой шапки, отформатированной через метод `bold()` из `MarkdownFormatter`.

## Компоненты и интерфейсы

### BotMessageBuilder

Класс `BotMessageBuilder` является централизованным компонентом для формирования сообщений бота. Он находится в пакете `ru.golubyatnikov.family.calendar.bot.util`.

**Изменяемые методы:**

1. `buildTimeSelectedMessage(LocalTime time)` - добавить шапку
2. `buildTimeSelectedMessage(String formattedTime)` - добавить шапку

**Формат шапки:**
```java
bold("📅 Создание нового события") + "\n\n"
```

### Константа для шапки

Для обеспечения единообразия и упрощения поддержки рекомендуется вынести шапку в константу:

```java
private static final String EVENT_CREATION_HEADER = "📅 Создание нового события";
```

Затем использовать её во всех методах:
```java
bold(EVENT_CREATION_HEADER) + "\n\n"
```

## Модели данных

Изменения в моделях данных не требуются. Все изменения касаются только форматирования сообщений.

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться во всех допустимых выполнениях системы - по сути, формальное утверждение о том, что система должна делать. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Свойство 1: Все сообщения создания события содержат шапку

*Для любого* сообщения, формируемого в процессе создания события, это сообщение должно начинаться с жирной шапки "📅 Создание нового события"

**Валидирует: Требования 1.1**

### Свойство 2: Шапка отформатирована жирным шрифтом

*Для любого* сообщения с шапкой создания события, шапка должна быть обернута в метод `bold()` для Markdown форматирования

**Валидирует: Требования 1.2**

### Свойство 3: После шапки следует пустая строка

*Для любого* сообщения с шапкой создания события, после шапки должна следовать пустая строка (две новые строки "\n\n") для визуального разделения

**Валидирует: Требования 1.3**

### Свойство 4: Сообщение после выбора времени содержит время и запрос названия

*Для любого* времени события, сообщение после выбора времени должно содержать выбранное время и текст запроса названия события

**Валидирует: Требования 2.2**

## Стратегия тестирования

### Двойной подход к тестированию

Для обеспечения корректности используются как unit-тесты, так и property-based тесты:

- **Unit-тесты**: Проверяют конкретные примеры и граничные случаи
- **Property-тесты**: Проверяют универсальные свойства на множестве входных данных

### Unit-тесты

Unit-тесты должны проверить:

1. **Конкретный пример**: Метод `buildTimeSelectedMessage()` возвращает сообщение с шапкой
2. **Формат шапки**: Шапка содержит правильный текст "📅 Создание нового события"
3. **Форматирование**: Шапка обернута в `bold()` и за ней следует "\n\n"
4. **Содержимое**: Сообщение содержит выбранное время и запрос названия

### Property-based тесты

Property-based тесты должны проверить:

1. **Свойство 1**: Для любого времени, `buildTimeSelectedMessage()` возвращает сообщение, начинающееся с шапки
2. **Свойство 2**: Для любого времени, шапка в сообщении отформатирована через `bold()`
3. **Свойство 3**: Для любого времени, после шапки следует "\n\n"
4. **Свойство 4**: Для любого времени, сообщение содержит отформатированное время и текст запроса

**Конфигурация property-тестов:**
- Минимум 100 итераций на тест
- Использование библиотеки jqwik для Java
- Каждый тест помечен комментарием с ссылкой на свойство из дизайна

**Формат тега:**
```java
// Feature: event-creation-header-consistency, Property 1: Все сообщения создания события содержат шапку
```

### Регрессионное тестирование

Необходимо убедиться, что существующие тесты для `BotMessageBuilder` продолжают проходить после внесения изменений. Если существующие тесты проверяют точное содержимое сообщений, их нужно обновить с учетом добавленной шапки.

## Детали реализации

### Шаг 1: Добавление константы

В класс `BotMessageBuilder` добавить константу:

```java
private static final String EVENT_CREATION_HEADER = "📅 Создание нового события";
```

### Шаг 2: Обновление метода buildTimeSelectedMessage(LocalTime)

**Было:**
```java
public String buildTimeSelectedMessage(LocalTime time) {
    return formatMessage("✅ Время выбрано: %s\n\nТеперь отправьте название события:", 
            formatTime(time));
}
```

**Стало:**
```java
public String buildTimeSelectedMessage(LocalTime time) {
    return bold(EVENT_CREATION_HEADER) + "\n\n" +
           formatMessage("✅ Время выбрано: %s\n\nТеперь отправьте название события:", 
                   formatTime(time));
}
```

### Шаг 3: Обновление метода buildTimeSelectedMessage(String)

**Было:**
```java
public String buildTimeSelectedMessage(String formattedTime) {
    return formatMessage("✅ Время выбрано: %s\n\nТеперь отправьте название события:", 
            formattedTime);
}
```

**Стало:**
```java
public String buildTimeSelectedMessage(String formattedTime) {
    return bold(EVENT_CREATION_HEADER) + "\n\n" +
           formatMessage("✅ Время выбрано: %s\n\nТеперь отправьте название события:", 
                   formattedTime);
}
```

### Шаг 4: Рефакторинг существующего использования (опционально)

Для улучшения консистентности можно обновить существующие места, где шапка используется напрямую, чтобы они также использовали константу `EVENT_CREATION_HEADER`. Однако это не является обязательным для данной фичи.
