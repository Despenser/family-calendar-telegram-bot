# Дизайн: Исправление экранирования MarkdownV2 в командах /stats и /trash

## Обзор

Исправление ошибок парсинга MarkdownV2 в командах `/stats` и `/trash`, вызванных неправильным использованием методов `MarkdownFormatter`. Проблема заключается в смешивании `formatMessage()` с уже отформатированными частями (`bold()`, `italic()`), что приводит к неправильному экранированию специальных символов.

## Архитектура

Решение не требует изменения архитектуры. Изменения затрагивают только два обработчика команд:
- `StatsCommandHandler` - исправление форматирования сообщения со статистикой
- `TrashCommandHandler` - исправление форматирования сообщения о пустой корзине

## Компоненты и интерфейсы

### StatsCommandHandler

**Текущая проблема:**
```java
messageBuilder.append(formatMessage("📋 %s\n", bold("Общая статистика:")));
messageBuilder.append(formatMessage("• Всего событий: %s\n", bold(String.valueOf(stats.getTotalEvents()))));
```

Проблема: `formatMessage` получает уже отформатированный текст с `*` и пытается его экранировать, что приводит к двойному экранированию.

**Решение:**
Использовать прямую конкатенацию методов `escape()`, `bold()`, `italic()` вместо `formatMessage()` с отформатированными частями.

```java
messageBuilder.append(escape("📋 ")).append(bold("Общая статистика:")).append(escape("\n"));
messageBuilder.append(escape("• Всего событий: ")).append(bold(String.valueOf(stats.getTotalEvents()))).append(escape("\n"));
```

### TrashCommandHandler

**Текущая проблема:**
```java
String responseMessage = formatMessage("🗑️ %s\n\nКорзина пуста.\n\n%s",
        bold("Корзина"),
        italic("Удаленные события хранятся здесь 30 дней, после чего автоматически удаляются навсегда."));
```

Проблема: Точки в "Корзина пуста." находятся вне форматированных частей, но `formatMessage` экранирует их неправильно при наличии форматированных аргументов.

**Решение:**
Разделить сообщение на части и использовать прямую конкатенацию:

```java
String responseMessage = escape("🗑️ ") + bold("Корзина") + escape("\n\n") +
                        escape("Корзина пуста.") + escape("\n\n") +
                        italic("Удаленные события хранятся здесь 30 дней, после чего автоматически удаляются навсегда.");
```

Изменения в моделях данных не требуются.

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться во всех допустимых выполнениях системы - по сути, формальное утверждение о том, что система должна делать. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

Для данного исправления свойства корректности не требуются, так как:
- Экранирование точек и других символов уже протестировано в существующих тестах `MarkdownFormatter`
- Проблема специфична для конкретных сообщений в `/stats` и `/trash`
- Исправление заключается в правильном использовании существующих методов форматирования

Вместо этого будут написаны unit-тесты для проверки конкретных сообщений.

## Обработка ошибок

Обработка ошибок не изменяется. Существующие try-catch блоки в обработчиках команд остаются без изменений.

## Стратегия тестирования

### Подход к тестированию

Для данного исправления используется **только unit-тестирование**, так как:
- Проблема специфична для конкретных сообщений в `/stats` и `/trash`
- Общие свойства форматирования уже протестированы в существующих тестах `MarkdownFormatter`
- Property-based тесты не добавят дополнительной ценности

### Unit-тесты

1. **Тест форматирования сообщения /stats**
   - Проверить, что сообщение со статистикой не содержит неэкранированных точек
   - Проверить, что форматирование (жирный, курсив) применяется корректно
   - Проверить различные значения статистики (0, 1, 100+)
   - **Проверяет: Требования 1.1, 1.3, 1.4**

2. **Тест форматирования сообщения /trash**
   - Проверить, что сообщение о пустой корзине не содержит неэкранированных точек
   - Проверить, что курсив применяется корректно
   - Проверить, что точки внутри курсива экранированы
   - **Проверяет: Требования 2.1, 2.2, 2.4**

3. **Интеграционный тест отправки сообщений**
   - Проверить, что сообщения успешно отправляются через mock Telegram API
   - Проверить, что не возникает ошибок парсинга MarkdownV2
   - **Проверяет: Требования 1.1, 2.1**

## Правила использования MarkdownFormatter

### Правило 1: Использование formatMessage

`formatMessage()` следует использовать ТОЛЬКО когда:
- Все аргументы являются простыми значениями (строки, числа)
- НЕТ уже отформатированных частей (результатов `bold()`, `italic()`)

**Правильно:**
```java
formatMessage("Дата: %s, Время: %s", date, time)
formatMessage("Всего событий: %d", count)
```

**Неправильно:**
```java
formatMessage("Заголовок: %s", bold("Текст"))  // ❌ bold() уже отформатирован
```

### Правило 2: Комбинирование форматирования

Для комбинирования форматированных и неформатированных частей используйте прямую конкатенацию:

**Правильно:**
```java
escape("Заголовок: ") + bold("Текст") + escape("\n")
```

### Правило 3: Только статический текст

Для статического текста без плейсхолдеров используйте `escape()`:

**Правильно:**
```java
escape("Корзина пуста.")
```

**До:**
