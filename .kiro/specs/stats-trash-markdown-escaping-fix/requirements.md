# Требования: Исправление экранирования MarkdownV2 в командах /stats и /trash

## Введение

Команды `/stats` и `/trash` падают с ошибкой парсинга MarkdownV2 из-за неправильного экранирования специальных символов (точек) в сообщениях. Telegram API возвращает ошибку "Character '.' is reserved and must be escaped with the preceding '\'".

## Глоссарий

- **System**: Telegram-бот семейного календаря
- **MarkdownV2**: Формат разметки текста Telegram, требующий экранирования специальных символов
- **formatMessage**: Метод MarkdownFormatter для форматирования сообщений с автоматическим экранированием
- **bold/italic**: Методы MarkdownFormatter для применения жирного/курсивного форматирования

## Требования

### Требование 1: Исправление команды /stats

**User Story:** Как пользователь, я хочу видеть статистику событий по команде /stats, чтобы отслеживать свою активность в календаре.

#### Критерии приемки

1. WHEN пользователь отправляет команду /stats THEN система SHALL отправить корректно отформатированное сообщение со статистикой без ошибок парсинга MarkdownV2
2. WHEN сообщение содержит точки в тексте THEN система SHALL корректно экранировать все точки в обычном тексте
3. WHEN сообщение содержит форматированные части (жирный, курсив) THEN система SHALL применять форматирование без двойного экранирования
4. WHEN сообщение содержит числовые значения THEN система SHALL корректно отображать числа без ошибок экранирования

### Требование 2: Исправление команды /trash

**User Story:** Как пользователь, я хочу просматривать корзину удаленных событий по команде /trash, чтобы при необходимости восстановить случайно удаленные события.

#### Критерии приемки

1. WHEN пользователь отправляет команду /trash THEN система SHALL отправить корректно отформатированное сообщение о корзине без ошибок парсинга MarkdownV2
2. WHEN корзина пуста THEN система SHALL отправить сообщение "Корзина пуста." с корректно экранированной точкой
3. WHEN сообщение содержит текст с точками внутри курсива THEN система SHALL корректно экранировать точки внутри форматированного текста
4. WHEN сообщение содержит смешанное форматирование THEN система SHALL применять форматирование без конфликтов экранирования

### Требование 3: Правильное использование MarkdownFormatter

**User Story:** Как разработчик, я хочу иметь четкие правила использования MarkdownFormatter, чтобы избежать ошибок экранирования в будущем.

#### Критерии приемки

1. WHEN разработчик форматирует сообщение THEN он SHALL использовать либо formatMessage с плейсхолдерами для неформатированного текста, либо прямую конкатенацию escape/bold/italic
2. WHEN разработчик использует formatMessage THEN он SHALL NOT передавать в него уже отформатированные части (результаты bold/italic)
3. WHEN разработчик комбинирует форматирование THEN он SHALL использовать прямую конкатенацию методов escape, bold, italic
4. WHEN сообщение содержит только статический текст THEN разработчик SHALL использовать formatMessage или escape для экранирования
