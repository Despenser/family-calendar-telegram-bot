# Документ проектирования

## Обзор

Данный документ описывает проектное решение для унификации формата сообщений в командах `/today` и `/upcoming_events` в соответствии с форматом команды `/week`. Цель - обеспечить единообразный пользовательский опыт во всех командах списка событий путем использования единых методов форматирования из класса `EventFormatter`.

Текущая ситуация:
- Команда `/week` использует улучшенный формат с заголовками дней, разделителями между днями и единообразным форматированием событий
- Команда `/today` использует устаревший формат без заголовка дня
- Команда `/upcoming_events` не группирует события по дням и не использует разделители

Целевое состояние:
- Все три команды используют единые методы форматирования из `EventFormatter`
- Команда `/today` отображает заголовок дня для текущей даты
- Команда `/upcoming_events` группирует события по дням с заголовками и разделителями
- Все команды используют единообразный формат для заголовков, событий, счетчиков и сообщений об отсутствии событий

## Архитектура

### Текущая архитектура

```
TodayCommandHandler
├── EventService (получение событий)
├── EventFormatter.formatEvent() (форматирование событий)
├── EventFormatter.formatCommandHeader() (заголовок команды)
├── EventFormatter.formatNoEventsMessage() (сообщение об отсутствии)
└── EventFormatter.formatEventCounter() (счетчик событий)

UpcomingEventsCommandHandler
├── EventService (получение событий)
├── EventFormatter.formatEvent() (форматирование событий)
├── EventFormatter.formatCommandHeader() (заголовок команды)
├── EventFormatter.formatNoEventsMessage() (сообщение об отсутствии)
└── EventFormatter.formatEventCounter() (счетчик событий)

WeekCommandHandler
├── EventService (получение событий)
├── EventFormatter.formatEvent() (форматирование событий)
├── EventFormatter.formatCommandHeader() (заголовок команды)
├── EventFormatter.formatDayHeader() (заголовок дня)
├── EventFormatter.formatDaySeparator() (разделитель дней)
├── EventFormatter.formatNoEventsMessage() (сообщение об отсутствии)
└── EventFormatter.formatEventCounter() (счетчик событий)
```

### Целевая архитектура

Архитектура остается той же, но обработчики команд `/today` и `/upcoming_events` будут использовать дополнительные методы из `EventFormatter`:

```
TodayCommandHandler
├── EventService (получение событий)
├── EventFormatter.formatEvent() (форматирование событий)
├── EventFormatter.formatCommandHeader() (заголовок команды)
├── EventFormatter.formatDayHeader() (НОВОЕ: заголовок дня)
├── EventFormatter.formatNoEventsMessage() (сообщение об отсутствии)
└── EventFormatter.formatEventCounter() (счетчик событий)

UpcomingEventsCommandHandler
├── EventService (получение событий)
├── EventFormatter.formatEvent() (форматирование событий)
├── EventFormatter.formatCommandHeader() (заголовок команды)
├── EventFormatter.formatDayHeader() (НОВОЕ: заголовок дня)
├── EventFormatter.formatDaySeparator() (НОВОЕ: разделитель дней)
├── EventFormatter.formatNoEventsMessage() (сообщение об отсутствии)
└── EventFormatter.formatEventCounter() (счетчик событий)
```

## Компоненты и интерфейсы

### TodayCommandHandler

**Изменения:**
- Добавить вызов `EventFormatter.formatDayHeader()` для отображения заголовка текущего дня
- Обновить формат заголовка команды для соответствия спецификации

**Новая структура вывода:**
```
📅 **События на сегодня** (ДД.ММ.ГГГГ (День недели))

📍 ДД.ММ (сегодня - день_недели)
[событие 1]
[событие 2]
...
_Всего событий: N_
```

### UpcomingEventsCommandHandler

**Изменения:**
- Добавить группировку событий по датам
- Добавить вызов `EventFormatter.formatDayHeader()` для каждой группы событий
- Добавить вызов `EventFormatter.formatDaySeparator()` между группами разных дней
- Обновить логику формирования сообщения для поддержки группировки

**Новая структура вывода:**
```
📅 **Предстоящие события** (30 дней)

📍 ДД.ММ (сегодня - день_недели)
[событие 1]
[событие 2]
─────────────────────
🔜 ДД.ММ (завтра - день_недели)
[событие 3]
─────────────────────
📆 ДД.ММ (День недели)
[событие 4]
[событие 5]
...
_Всего событий: N_
```

### EventFormatter

**Изменения:** Не требуются. Все необходимые методы уже существуют:
- `formatCommandHeader(String commandName, String additionalInfo)` - форматирование заголовка команды
- `formatDayHeader(LocalDate date, LocalDate today)` - форматирование заголовка дня
- `formatDaySeparator()` - форматирование разделителя между днями
- `formatEvent(Event event, User currentUser)` - форматирование события
- `formatEventCounter(int count)` - форматирование счетчика событий
- `formatNoEventsMessage(String commandName, String message)` - форматирование сообщения об отсутствии событий

## Модели данных

Изменения в моделях данных не требуются. Используются существующие модели:
- `Event` - модель события
- `User` - модель пользователя
- `Message` - модель сообщения Telegram

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться во всех допустимых выполнениях системы - по сути, формальное утверждение о том, что должна делать система. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Свойство 1: Заголовок дня в команде /today

*Для любого* выполнения команды `/today`, вывод должен содержать заголовок дня в формате "📍 ДД.ММ (сегодня - день_недели)" с правильной текущей датой.

**Проверяет: Требование 1.1**

### Свойство 2: Единообразие форматирования событий

*Для любого* события, отформатированного командами `/today`, `/week` или `/upcoming_events`, формат вывода должен быть идентичным (использование одного метода `EventFormatter.formatEvent()`).

**Проверяет: Требование 1.2**

### Свойство 3: Отсутствие разделителей в команде /today

*Для любого* набора событий на один день в команде `/today`, вывод не должен содержать символы разделителя "─────────────────────".

**Проверяет: Требование 1.3**

### Свойство 4: Счетчик событий в команде /today

*Для любого* ненулевого количества событий в команде `/today`, вывод должен содержать счетчик в формате "_Всего событий: N_" с правильным количеством.

**Проверяет: Требование 1.4**

### Свойство 5: Группировка по датам в команде /upcoming_events

*Для любого* набора событий с разными датами в команде `/upcoming_events`, события с одинаковой датой должны идти последовательно в выводе, а события с разными датами должны быть разделены заголовками дней.

**Проверяет: Требование 2.1**

### Свойство 6: Заголовки дней в команде /upcoming_events

*Для любого* набора событий в команде `/upcoming_events`, для каждой уникальной даты в списке событий должен присутствовать соответствующий заголовок дня.

**Проверяет: Требование 2.2**

### Свойство 7: Формат заголовков дней в команде /upcoming_events

*Для любого* заголовка дня в команде `/upcoming_events`, формат должен быть "📍 ДД.ММ (сегодня - день_недели)" для сегодняшнего дня, "🔜 ДД.ММ (завтра - день_недели)" для завтрашнего дня и "📆 ДД.ММ (День недели)" для остальных дней.

**Проверяет: Требование 2.3**

### Свойство 8: Разделители между днями в команде /upcoming_events

*Для любого* набора событий нескольких дней в команде `/upcoming_events`, между группами событий разных дней должен присутствовать разделитель "─────────────────────", но не внутри группы одного дня.

**Проверяет: Требование 2.4**

### Свойство 9: Счетчик событий в команде /upcoming_events

*Для любого* ненулевого количества событий в команде `/upcoming_events`, вывод должен содержать счетчик в формате "_Всего событий: N_" с правильным количеством.

**Проверяет: Требование 2.5**

### Свойство 10: Заголовок команды /today

*Для любого* выполнения команды `/today`, вывод должен содержать заголовок в формате "📅 **События на сегодня** (ДД.ММ.ГГГГ (День недели))" с правильной текущей датой.

**Проверяет: Требование 3.1**

### Свойство 11: Заголовок команды /upcoming_events

*Для любого* выполнения команды `/upcoming_events`, вывод должен содержать заголовок в формате "📅 **Предстоящие события** (30 дней)".

**Проверяет: Требование 3.2**

## Обработка ошибок

Обработка ошибок остается без изменений:
- Все исключения при обработке команд логируются и возвращают пользователю понятное сообщение об ошибке
- Используется существующая инфраструктура обработки ошибок в обработчиках команд
- При отсутствии событий возвращается информационное сообщение через `EventFormatter.formatNoEventsMessage()`
