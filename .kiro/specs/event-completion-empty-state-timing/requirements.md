# Requirements Document

## Introduction

Данная спецификация описывает исправление проблемы с преждевременным отображением сообщения "У вас пока нет созданных событий" при завершении последнего события в списке с добавлением заметки о завершении.

## Glossary

- **Event_Completion_Handler**: Обработчик завершения событий
- **Completion_Note**: Заметка о завершении события
- **Empty_State_Message**: Сообщение "У вас пока нет созданных событий"
- **Event_List**: Список событий пользователя
- **Conversation_State**: Состояние диалога с пользователем

## Requirements

### Requirement 1: Отложенное отображение пустого состояния

**User Story:** Как пользователь, я хочу видеть сообщение о пустом списке событий только после полного завершения процесса завершения события с заметкой, чтобы не видеть преждевременные уведомления.

#### Acceptance Criteria

1. WHEN пользователь завершает последнее событие в списке И требуется ввод заметки о завершении, THEN THE System SHALL НЕ отправлять Empty_State_Message до завершения ввода заметки
2. WHEN пользователь отправляет Completion_Note для последнего события, THEN THE System SHALL отправить сообщение о завершении события с заметкой
3. WHEN пользователь завершает ввод Completion_Note для последнего события, THEN THE System SHALL отправить Empty_State_Message после сообщения о завершении
4. WHEN пользователь завершает последнее событие без заметки о завершении, THEN THE System SHALL отправить Empty_State_Message сразу после завершения
5. WHEN пользователь завершает событие И в Event_List остаются другие события, THEN THE System SHALL НЕ отправлять Empty_State_Message

### Requirement 2: Проверка состояния списка событий

**User Story:** Как система, я должна корректно определять момент, когда список событий становится пустым, чтобы отправлять уведомления в правильное время.

#### Acceptance Criteria

1. WHEN система проверяет Event_List после завершения события, THEN THE System SHALL учитывать текущий Conversation_State пользователя
2. WHEN пользователь находится в состоянии ввода Completion_Note, THEN THE System SHALL считать процесс завершения события незавершенным
3. WHEN пользователь завершает ввод Completion_Note, THEN THE System SHALL проверить Event_List и определить необходимость отправки Empty_State_Message
4. WHEN система определяет пустоту Event_List, THEN THE System SHALL исключать события в процессе завершения с заметкой

### Requirement 3: Последовательность сообщений

**User Story:** Как пользователь, я хочу видеть сообщения в логичной последовательности, чтобы понимать результат моих действий.

#### Acceptance Criteria

1. WHEN пользователь завершает последнее событие с заметкой, THEN THE System SHALL отправить сообщения в следующем порядке: подтверждение завершения, затем Empty_State_Message
2. WHEN пользователь отменяет ввод Completion_Note, THEN THE System SHALL проверить Event_List и отправить Empty_State_Message если список пуст
3. WHEN происходит ошибка при сохранении Completion_Note, THEN THE System SHALL НЕ отправлять Empty_State_Message до успешного завершения операции
