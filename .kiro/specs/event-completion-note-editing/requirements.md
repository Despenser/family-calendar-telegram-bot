# Requirements Document

## Introduction

Данная спецификация описывает улучшение функциональности добавления заметок к завершенным событиям. Текущая реализация создает множество новых сообщений при добавлении заметки, что загромождает чат. Требуется изменить поведение так, чтобы все взаимодействие происходило путем редактирования одного сообщения.

## Glossary

- **Event**: Событие в календаре семьи
- **Completion_Note**: Заметка, которую пользователь может добавить к завершенному событию
- **Message_Editing**: Редактирование существующего сообщения в Telegram вместо создания нового
- **Manual_Completion**: Завершение события пользователем вручную через кнопку "✅ Завершить"
- **Automatic_Completion**: Автоматическое завершение события по расписанию
- **Event_Message**: Сообщение бота, отображающее информацию о событии

## Requirements

### Requirement 1: Редактирование сообщения при добавлении заметки

**User Story:** Как пользователь, я хочу добавлять заметки к завершенным событиям путем редактирования одного сообщения, чтобы не загромождать чат множеством сообщений.

#### Acceptance Criteria

1. WHEN пользователь завершает событие вручную, THEN THE System SHALL отредактировать сообщение события, показав статус завершения и кнопки для добавления заметки
2. WHEN пользователь нажимает кнопку "📝 Добавить заметку", THEN THE System SHALL отредактировать то же сообщение с просьбой ввести текст заметки
3. WHEN пользователь вводит текст заметки, THEN THE System SHALL отредактировать то же сообщение, показав событие с добавленной заметкой
4. WHEN пользователь нажимает кнопку "⏭️ Пропустить", THEN THE System SHALL отредактировать сообщение, показав событие как завершенное без заметки
5. THE System SHALL сохранять messageId события на протяжении всего процесса добавления заметки

### Requirement 2: Заметка при ручном завершении события

**User Story:** Как пользователь, я хочу иметь возможность добавить заметку при ручном завершении события, чтобы сразу зафиксировать результаты или впечатления.

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "✅ Завершить" на активном событии, THEN THE System SHALL завершить событие и предложить добавить заметку
2. WHEN пользователь выбирает добавление заметки, THEN THE System SHALL перевести его в режим ожидания ввода текста заметки
3. WHEN пользователь вводит текст заметки после ручного завершения, THEN THE System SHALL сохранить заметку к событию
4. WHEN пользователь пропускает добавление заметки, THEN THE System SHALL завершить процесс без заметки

### Requirement 3: Сохранение контекста сообщения

**User Story:** Как система, я должна сохранять контекст сообщения события, чтобы корректно редактировать его на всех этапах добавления заметки.

#### Acceptance Criteria

1. WHEN событие завершается, THE System SHALL сохранить messageId события в контексте добавления заметки
2. WHEN пользователь находится в режиме ожидания заметки, THE System SHALL иметь доступ к messageId для редактирования
3. WHEN заметка добавлена или пропущена, THE System SHALL очистить контекст добавления заметки
4. WHEN происходит ошибка при редактировании сообщения, THE System SHALL корректно обработать ошибку и очистить контекст

### Requirement 4: Отображение завершенного события с заметкой

**User Story:** Как пользователь, я хочу видеть заметку в сообщении о завершенном событии, чтобы понимать, что было зафиксировано.

#### Acceptance Criteria

1. WHEN событие завершено с заметкой, THE System SHALL отобразить заметку в сообщении события
2. WHEN событие завершено без заметки, THE System SHALL отобразить только статус завершения
3. THE System SHALL использовать эмодзи "📝" для обозначения заметки
4. THE System SHALL корректно экранировать текст заметки для Telegram Markdown

### Requirement 5: Обратная совместимость

**User Story:** Как система, я должна поддерживать существующую функциональность автоматического завершения событий, чтобы не нарушить работу планировщика.

#### Acceptance Criteria

1. WHEN событие завершается автоматически по расписанию, THE System SHALL работать как раньше
2. WHEN событие завершается вручную, THE System SHALL использовать новую логику с редактированием сообщения
3. THE System SHALL корректно обрабатывать события, у которых нет messageId
4. THE System SHALL поддерживать добавление заметок к уже завершенным событиям
