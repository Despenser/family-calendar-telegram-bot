# Design Document

## Overview

Изменение формата сообщения о количестве активных событий в команде /stats. Текущий формат "У вас {count} активных событий в этом месяце" будет заменен на более лаконичный "Активных событий в этом месяце - {count}".

## Architecture

Изменение затрагивает только класс `StatsCommandHandler`, который отвечает за формирование и отправку статистики пользователю. Архитектура приложения остается неизменной.

## Components and Interfaces

### StatsCommandHandler

**Изменяемый метод:**
- `handle(Message message, User user)` - метод формирования сообщения со статистикой

**Изменяемая логика:**
В блоке формирования дополнительной информации (после основной статистики) необходимо изменить строку:
```java
// Было:
messageBuilder.append(italic(String.format("У вас %d активных событий в этом месяце", stats.getActiveEvents())));

// Станет:
messageBuilder.append(italic(String.format("Активных событий в этом месяце - %d", stats.getActiveEvents())));
```

## Data Models

Изменения в моделях данных не требуются. Используются существующие классы:
- `StatisticsService.EventStatistics` - содержит статистику событий
- `User` - модель пользователя
- `Message` - Telegram сообщение

## Correctness Properties

*Свойство (property) - это характеристика или поведение, которое должно выполняться во всех корректных выполнениях системы - по сути, формальное утверждение о том, что система должна делать. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Property 1: Формат сообщения для активных событий

*Для любого* количества активных событий больше 0, сообщение должно иметь формат "Активных событий в этом месяце - {count}", где {count} - это количество активных событий.

**Validates: Requirements 1.1**

### Property 2: Сообщение при отсутствии активных событий

*Для любого* случая, когда количество активных событий равно 0 и общее количество событий больше 0, сообщение должно быть "Все события этого месяца завершены! 🎉".

**Validates: Requirements 1.2**

### Property 3: Сообщение при отсутствии событий

*Для любого* случая, когда общее количество событий равно 0, сообщение должно быть "В этом месяце нет событий. Создайте первое событие с помощью /add_event".

**Validates: Requirements 1.3**

### Property 4: Форматирование сообщения

*Для любого* сформированного дополнительного сообщения, оно должно быть обернуто в italic форматирование.

**Validates: Requirements 1.4**

## Error Handling

Обработка ошибок остается без изменений:
- При возникновении исключения в методе `handle` возвращается сообщение об ошибке
- Логирование ошибок выполняется через SLF4J

## Testing Strategy

### Unit Tests

Необходимо обновить существующие unit-тесты в `StatsCommandHandlerTest`:
- Проверить новый формат сообщения для случая с активными событиями
- Убедиться, что сообщения для других случаев (нет событий, все завершены) остаются корректными
- Проверить корректность форматирования (italic)

### Property-Based Tests

Property-based тесты не требуются для данного изменения, так как:
- Изменение касается только формата строки
- Логика определения количества событий не меняется
- Достаточно unit-тестов для проверки корректности форматирования

### Test Configuration

- Использовать JUnit 5 для unit-тестов
- Использовать Mockito для мокирования зависимостей
- Минимум 3 тестовых сценария:
  1. Есть активные события (проверка нового формата)
  2. Нет активных событий, но есть завершенные
  3. Нет событий вообще
