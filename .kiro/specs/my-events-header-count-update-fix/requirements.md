# Требования: Обновление счетчика событий в шапке при удалении

## Введение

Данный документ описывает требования к исправлению бага, при котором счетчик активных событий в шапке первого сообщения команды /my_events не обновляется при удалении события посередине списка. Шапка обновляется только когда она передается новому первому событию, но если удаляется событие не из начала списка, счетчик остается неактуальным.

## Глоссарий

- **Система** - Telegram бот семейного календаря
- **Пользователь** - авторизованный пользователь бота
- **Событие** - запись в календаре с датой, временем и описанием
- **Шапка** - заголовочное сообщение со счетчиком событий в команде /my_events
- **Первое событие** - событие с флагом isMyEventsHeader=true, к которому прикреплена шапка
- **Счетчик событий** - число активных событий пользователя, отображаемое в шапке
- **Активное событие** - событие со статусом ACTIVE

## Требования

### Требование 1

**User Story:** Как пользователь, я хочу видеть актуальный счетчик событий в шапке, чтобы понимать сколько у меня активных событий после любых операций удаления.

#### Критерии приемки

1. WHEN пользователь удаляет событие посередине списка THEN система SHALL обновить счетчик событий в шапке первого сообщения
2. WHEN пользователь удаляет последнее событие в списке THEN система SHALL обновить счетчик событий в шапке первого сообщения
3. WHEN пользователь удаляет первое событие в списке THEN система SHALL передать шапку следующему событию с актуальным счетчиком
4. WHEN система обновляет счетчик событий THEN система SHALL сохранить все остальные элементы шапки без изменений
5. WHEN система обновляет сообщение с шапкой THEN система SHALL сохранить inline-кнопки первого события

### Требование 2

**User Story:** Как разработчик, я хочу иметь централизованный метод обновления шапки, чтобы обеспечить консистентность при любых изменениях списка событий.

#### Критерии приемки

1. WHEN система обновляет счетчик событий THEN система SHALL использовать единый метод для всех сценариев обновления
2. WHEN метод обновления вызывается THEN система SHALL получить актуальное количество активных событий из базы данных
3. WHEN метод обновления вызывается THEN система SHALL найти событие с флагом isMyEventsHeader=true
4. WHEN событие с шапкой найдено THEN система SHALL обновить текст сообщения через Telegram API
5. WHEN обновление не удается THEN система SHALL залогировать ошибку и продолжить работу

### Требование 3

**User Story:** Как пользователь, я хочу чтобы обновление шапки происходило автоматически, чтобы не видеть устаревшую информацию.

#### Критерии приемки

1. WHEN пользователь удаляет событие через callback THEN система SHALL автоматически обновить счетчик в шапке
2. WHEN пользователь удаляет событие через команду THEN система SHALL автоматически обновить счетчик в шапке
3. WHEN система завершает событие автоматически THEN система SHALL автоматически обновить счетчик в шапке
4. WHEN пользователь восстанавливает событие из корзины THEN система SHALL автоматически обновить счетчик в шапке
5. WHEN обновление счетчика происходит THEN пользователь SHALL видеть изменения немедленно
