# Документ требований

## Введение

Данная спецификация описывает исправление ошибки при возврате из просмотра вложения к списку вложений в Telegram боте. Проблема возникает из-за попытки редактирования медиа-сообщения методом EditMessageText, что не поддерживается Telegram API.

## Глоссарий

- **System**: Telegram бот для семейного календаря
- **Attachment_Handler**: Обработчик callback-запросов для работы с вложениями
- **Message_Service**: Сервис для отправки и редактирования сообщений в Telegram
- **Media_Message**: Сообщение, содержащее медиа-контент (фото, документ, видео)
- **Text_Message**: Сообщение, содержащее только текст и inline-клавиатуру
- **Attachment_List**: Список вложений события, отображаемый пользователю

## Требования

### Требование 1: Определение типа сообщения

**User Story:** Как система, я хочу определять тип текущего сообщения перед его редактированием, чтобы выбрать правильный метод обработки.

#### Критерии приемки

1. WHEN система обрабатывает callback возврата к списку вложений, THE System SHALL определить, является ли текущее сообщение медиа-сообщением
2. WHEN текущее сообщение содержит фото, THE System SHALL классифицировать его как Media_Message
3. WHEN текущее сообщение содержит документ, THE System SHALL классифицировать его как Media_Message
4. WHEN текущее сообщение содержит только текст, THE System SHALL классифицировать его как Text_Message

### Требование 2: Обработка возврата из медиа-сообщения

**User Story:** Как пользователь, я хочу вернуться из просмотра вложения к списку вложений, чтобы выбрать другое вложение для просмотра.

#### Критерии приемки

1. WHEN пользователь нажимает кнопку "Назад к списку вложений" в Media_Message, THEN THE Attachment_Handler SHALL удалить текущее медиа-сообщение
2. WHEN медиа-сообщение удалено, THEN THE Message_Service SHALL отправить новое текстовое сообщение со списком вложений
3. WHEN новое сообщение отправлено, THEN THE System SHALL отобразить все вложения события с inline-клавиатурой
4. WHEN операция завершена успешно, THEN THE System SHALL не генерировать ошибок Telegram API

### Требование 3: Обработка возврата из текстового сообщения

**User Story:** Как система, я хочу сохранить текущее поведение для текстовых сообщений, чтобы не нарушить существующую функциональность.

#### Критерии приемки

1. WHEN пользователь нажимает кнопку "Назад к списку вложений" в Text_Message, THEN THE Attachment_Handler SHALL отредактировать текущее сообщение
2. WHEN сообщение редактируется, THEN THE Message_Service SHALL использовать метод EditMessageText
3. WHEN редактирование завершено, THEN THE System SHALL обновить текст и клавиатуру сообщения

### Требование 4: Обработка ошибок

**User Story:** Как система, я хочу корректно обрабатывать ошибки при работе с сообщениями, чтобы предоставить пользователю понятную обратную связь.

#### Критерии приемки

1. IF удаление медиа-сообщения не удалось, THEN THE System SHALL логировать ошибку и попытаться отправить новое сообщение
2. IF отправка нового сообщения не удалась, THEN THE System SHALL логировать ошибку и уведомить пользователя
3. WHEN возникает ошибка Telegram API, THEN THE System SHALL предоставить информативное сообщение об ошибке в логах
4. WHEN операция не может быть выполнена, THEN THE System SHALL сохранить стабильность работы бота

### Требование 5: Сохранение контекста навигации

**User Story:** Как пользователь, я хочу, чтобы при возврате к списку вложений сохранялся контекст моей навигации, чтобы я мог продолжить работу с того же места.

#### Критерии приемки

1. WHEN система отправляет новое сообщение со списком вложений, THEN THE System SHALL сохранить идентификатор события в callback-данных
2. WHEN отображается список вложений, THEN THE System SHALL включить все необходимые кнопки навигации
3. WHEN пользователь возвращается к списку, THEN THE System SHALL отобразить актуальный список вложений события
