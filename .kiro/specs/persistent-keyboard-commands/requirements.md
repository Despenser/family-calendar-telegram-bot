# Требования: Постоянная клавиатура с основными командами

## Введение

Система семейного календаря имеет ограниченный набор кнопок в постоянной клавиатуре (ReplyKeyboardMarkup). Пользователи вынуждены вводить многие команды вручную (например, `/week`, `/trash`, `/stats`, `/today`, `/search`, `/filter`), что снижает удобство использования. Необходимо вынести все основные команды в постоянную клавиатуру под полем ввода сообщений.

## Глоссарий

- **System** - система семейного календаря Telegram бота
- **ReplyKeyboardMarkup** - постоянная клавиатура с кнопками, отображаемая под полем ввода сообщений
- **InlineKeyboardMarkup** - inline клавиатура с кнопками, отображаемая под конкретным сообщением
- **Command** - команда бота, начинающаяся с символа "/"
- **Authorized User** - авторизованный пользователь, зарегистрированный в системе
- **Unauthorized User** - неавторизованный пользователь, не зарегистрированный в системе
- **KeyboardService** - сервис для создания клавиатур
- **Main Commands** - основные команды бота для повседневного использования

## Требования

### Требование 1

**User Story:** Как пользователь, я хочу видеть все основные команды в виде кнопок под клавиатурой, чтобы быстро получать доступ к функциям бота без необходимости вводить команды вручную.

#### Критерии приемки

1. WHEN пользователь авторизован THEN THE System SHALL отображать постоянную клавиатуру со всеми основными командами
2. WHEN пользователь нажимает на кнопку команды THEN THE System SHALL выполнять соответствующую команду
3. WHEN постоянная клавиатура отображается THEN THE System SHALL группировать команды логически для удобства использования
4. WHEN постоянная клавиатура отображается THEN THE System SHALL использовать эмодзи для визуального различия команд

### Требование 2

**User Story:** Как пользователь, я хочу иметь доступ к командам просмотра событий через кнопки, чтобы быстро переключаться между разными временными периодами.

#### Критерии приемки

1. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /today
2. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /week
3. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /upcoming_events
4. WHEN пользователь нажимает кнопку просмотра событий THEN THE System SHALL отображать события для соответствующего периода

### Требование 3

**User Story:** Как пользователь, я хочу иметь доступ к командам управления событиями через кнопки, чтобы быстро создавать и управлять своими событиями.

#### Критерии приемки

1. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /add_event
2. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /my_events
3. WHEN пользователь нажимает кнопку управления событиями THEN THE System SHALL выполнять соответствующее действие

### Требование 4

**User Story:** Как пользователь, я хочу иметь доступ к дополнительным функциям через кнопки, чтобы использовать все возможности бота без запоминания команд.

#### Критерии приемки

1. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /trash
2. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /stats
3. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /search
4. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /filter
5. WHEN постоянная клавиатура отображается THEN THE System SHALL включать кнопку для команды /help

### Требование 5

**User Story:** Как пользователь, я хочу чтобы клавиатура была компактной и удобной, чтобы она не занимала слишком много места на экране.

#### Критерии приемки

1. WHEN постоянная клавиатура отображается THEN THE System SHALL размещать кнопки в несколько рядов для оптимального использования пространства
2. WHEN постоянная клавиатура отображается THEN THE System SHALL использовать параметр resize_keyboard для автоматической подстройки под размер экрана
3. WHEN постоянная клавиатура отображается THEN THE System SHALL размещать не более 3 кнопок в одном ряду для удобства нажатия
4. WHEN постоянная клавиатура отображается THEN THE System SHALL группировать связанные команды в одном ряду

### Требование 6

**User Story:** Как разработчик, я хочу иметь централизованную логику создания постоянной клавиатуры, чтобы обеспечить консистентность интерфейса во всех частях системы.

#### Критерии приемки

1. WHEN метод создания клавиатуры вызывается THEN THE System SHALL использовать единый метод KeyboardService для создания постоянной клавиатуры
2. WHEN текст кнопки преобразуется в команду THEN THE System SHALL использовать метод buttonTextToCommand для всех новых кнопок
3. WHEN постоянная клавиатура обновляется THEN THE System SHALL обновлять маппинг кнопок в методе buttonTextToCommand
4. WHEN новая команда добавляется в систему THEN THE System SHALL добавлять соответствующую кнопку в постоянную клавиатуру

### Требование 7

**User Story:** Как неавторизованный пользователь, я хочу видеть упрощенную клавиатуру, чтобы не видеть недоступные мне команды.

#### Критерии приемки

1. WHEN пользователь не авторизован THEN THE System SHALL отображать только кнопки /start и /help
2. WHEN пользователь авторизуется THEN THE System SHALL заменять клавиатуру на полную версию со всеми командами
3. WHEN неавторизованный пользователь нажимает кнопку THEN THE System SHALL выполнять только доступные команды
