# Проектирование: Постоянная клавиатура с основными командами

## Обзор

Данный документ описывает проектное решение для расширения постоянной клавиатуры (ReplyKeyboardMarkup) с добавлением всех основных команд бота. Текущая реализация содержит только 4 кнопки для авторизованных пользователей, что заставляет пользователей вводить многие команды вручную. Новая клавиатура будет включать все 10 основных команд, организованных логически и компактно.

## Архитектура

### Текущая архитектура

```
KeyboardService.createAuthorizedUserKeyboard()
    ↓
Создает клавиатуру с 4 кнопками:
- 📅 Предстоящие события (/upcoming_events)
- ➕ Добавить событие (/add_event)
- 📋 Мои события (/my_events)
- ❓ Помощь (/help)

Расположение: 2 ряда по 2 кнопки
```

### Целевая архитектура

```
KeyboardService.createAuthorizedUserKeyboard()
    ↓
Создает клавиатуру с 10 кнопками:

Ряд 1: 📝 Мои события | ➕ Добавить
Ряд 2: 📅 Сегодня | 📆 Неделя | 📋 Предстоящие
Ряд 3: 🔍 Поиск | 🎯 Фильтр | 📊 Статистика
Ряд 4: 🗑️ Корзина | ❓ Помощь

Расположение: 4 ряда (2+3+3+2 кнопки)
```

### Логическая группировка команд

- ➕ Добавить - создание нового события

**Группа 2: Просмотр событий (Ряд 2)**
- 📅 Сегодня - события на текущий день
- 📆 Неделя - события на текущую неделю

- 🔍 Поиск - поиск событий

## Модели данных

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться для всех допустимых выполнений системы - по сути, формальное утверждение о том, что должна делать система. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Свойство 1: Полнота клавиатуры

*Для любого* вызова метода createAuthorizedUserKeyboard(), возвращаемая клавиатура должна содержать ровно 10 кнопок с текстами, соответствующими всем основным командам

**Проверяет: Требования 1.1**

### Свойство 2: Корректность маппинга кнопок

*Для любой* кнопки из клавиатуры, созданной методом createAuthorizedUserKeyboard(), метод buttonTextToCommand должен возвращать строку, начинающуюся с символа "/"

**Проверяет: Требования 1.2, 6.2, 6.3**

### Свойство 3: Наличие эмодзи в кнопках

*Для любой* кнопки из клавиатуры, созданной методом createAuthorizedUserKeyboard(), текст кнопки должен содержать хотя бы один эмодзи символ

**Проверяет: Требования 1.4**

### Свойство 4: Компактность клавиатуры

*Для любого* ряда в клавиатуре, созданной методом createAuthorizedUserKeyboard(), количество кнопок не должно превышать 3

**Проверяет: Требования 5.3**

### Свойство 5: Многорядность клавиатуры

*Для любого* вызова метода createAuthorizedUserKeyboard(), возвращаемая клавиатура должна содержать более одного ряда кнопок

**Проверяет: Требования 5.1**

### Свойство 6: Упрощенная клавиатура для неавторизованных

*Для любого* вызова метода createUnauthorizedUserKeyboard(), возвращаемая клавиатура должна содержать ровно 2 кнопки

**Проверяет: Требования 7.1**

## Обработка ошибок

### Существующая обработка

Метод `buttonTextToCommand()` уже содержит валидацию:
- Проверка `buttonText == null` с выбросом `IllegalArgumentException`
- Возврат исходного текста, если кнопка не распознана

### Дополнительная обработка

Не требуется, так как:
- Все новые кнопки будут добавлены в switch statement
- Логирование уже присутствует в методе
- Валидация параметров уже реализована

## Стратегия тестирования

### Unit-тесты

**Тест 1: Проверка количества кнопок в авторизованной клавиатуре**
- Вызвать `keyboardService.createAuthorizedUserKeyboard()`
- Проверить, что клавиатура содержит 4 ряда
- Проверить, что общее количество кнопок равно 10

**Тест 2: Проверка маппинга новых кнопок**
- Для каждой новой кнопки вызвать `buttonTextToCommand()`
- Проверить, что возвращается правильная команда

**Тест 3: Проверка группировки команд**
- Вызвать `createAuthorizedUserKeyboard()`
- Проверить, что ряд 1 содержит команды просмотра событий
- Проверить, что ряд 2 содержит команды управления событиями
- Проверить, что ряд 3 содержит дополнительные функции
- Проверить, что ряд 4 содержит утилиты

**Тест 4: Проверка компактности**
- Вызвать `createAuthorizedUserKeyboard()`
- Для каждого ряда проверить, что количество кнопок <= 3

### Property-Based тесты

Для тестирования будет использоваться библиотека **jqwik**.

**Property Test 1: Все кнопки имеют корректный маппинг**
- Генерировать случайные кнопки из клавиатуры
- Вызывать `buttonTextToCommand()` для каждой кнопки
- Проверять, что результат начинается с "/"
- Минимум 100 итераций

**Property Test 2: Клавиатура всегда содержит 10 кнопок**
- Генерировать случайные вызовы `createAuthorizedUserKeyboard()`

- Проверять, что количество всегда равно 10
- Минимум 100 итераций

**Property Test 3: Неавторизованная клавиатура всегда содержит 2 кнопки**

- Подсчитывать общее количество кнопок

### Интеграционные тесты

**Интеграционный тест: Проверка работы новых команд через кнопки**
- Создать тестового пользователя

  - Преобразовать текст в команду через `buttonTextToCommand()`
  - Симулировать выполнение команды
  - Проверить, что команда выполняется корректно

## Влияние на UX

### Преимущества

1. **Быстрый доступ к командам**: Все основные команды доступны одним нажатием
2. **Не нужно запоминать команды**: Пользователи видят все доступные функции
3. **Визуальная организация**: Логическая группировка помогает быстро найти нужную команду
4. **Эмодзи для различия**: Каждая команда имеет уникальный эмодзи для быстрого распознавания

### Потенциальные недостатки

1. **Больше места на экране**: Клавиатура займет больше места (4 ряда вместо 2)
2. **Возможная перегруженность**: 10 кнопок могут показаться слишком много для новых пользователей

### Решения для недостатков

1. **Параметр resize_keyboard=true**: Клавиатура автоматически подстраивается под размер экрана
2. **Логическая группировка**: Команды сгруппированы по функциональности, что упрощает навигацию
3. **Компактное размещение**: Не более 3 кнопок в ряду для удобства нажатия

## Обратная совместимость

### Изменения в API

Публичный API `KeyboardService` не изменяется:
- Сигнатуры методов остаются прежними
- Возвращаемые типы не меняются
- Параметры не меняются

### Изменения в поведении

**Изменение:** Метод `createAuthorizedUserKeyboard()` теперь возвращает клавиатуру с 10 кнопками вместо 4.

**Влияние:** Это улучшение UX, а не breaking change. Все существующие кнопки сохраняются, добавляются только новые. Пользователи получат доступ к дополнительным функциям без необходимости изменения привычек.

### Миграция пользователей

Миграция не требуется. При следующем взаимодействии с ботом пользователи автоматически получат обновленную клавиатуру.

## Альтернативные решения

### Альтернатива 1: Многоуровневая клавиатура

**Описание:** Создать основную клавиатуру с категориями (Просмотр, Управление, Утилиты), и при нажатии на категорию показывать подменю с командами.

**Недостатки:**
- Требует дополнительного нажатия для доступа к командам
- Усложняет навигацию
- Требует состояния для отслеживания текущего меню

**Вывод:** Отклонено в пользу одноуровневой клавиатуры

### Альтернатива 2: Inline меню команд

**Описание:** Оставить постоянную клавиатуру минимальной, но добавить кнопку "Меню", которая показывает inline клавиатуру со всеми командами.

**Недостатки:**
- Inline клавиатуры привязаны к конкретным сообщениям
- Требует дополнительного нажатия
- Меню может "потеряться" в истории сообщений

**Вывод:** Отклонено, так как постоянная клавиатура всегда доступна

### Альтернатива 3: Настраиваемая клавиатура

**Описание:** Позволить пользователям выбирать, какие команды отображать в постоянной клавиатуре.

**Недостатки:**
- Требует дополнительной логики для хранения настроек
- Усложняет систему
- Большинство пользователей не будут настраивать

**Вывод:** Отклонено для первой версии, может быть рассмотрено в будущем

## Выбранное решение

Расширить существующий метод `createAuthorizedUserKeyboard()` для включения всех 10 основных команд, организованных в 4 логических ряда.

**Преимущества:**
- Минимальные изменения кода (один метод)
- Все команды доступны одним нажатием
- Логическая группировка упрощает навигацию
- Компактное размещение (не более 3 кнопок в ряду)
- Автоматическая подстройка под размер экрана
- Обратная совместимость (все старые кнопки сохраняются)

### Обоснование группировки

**Ряд 1 (Управление событиями):**
- Самые часто используемые команды для работы с событиями
- Логически связаны (просмотр своих событий → создание нового)
- Размещены в первом ряду для быстрого доступа

**Ряд 2 (Просмотр событий):**
- Команды для просмотра событий по временным периодам
- Упорядочены по временному периоду (день → неделя → месяц)
- Часто используются для планирования

**Ряд 3 (Утилиты поиска и анализа):**
- Инструменты для работы с данными
- Связаны функционально (поиск → фильтрация → анализ)
- Используются для детального изучения событий

**Ряд 4 (Дополнительные функции):**
- Менее частые, но важные функции
- Корзина для восстановления удаленных событий
- Помощь для получения справки

## Мониторинг и метрики

### Метрики для отслеживания

1. **Частота использования кнопок**: Какие кнопки используются чаще всего
2. **Соотношение кнопки/команды**: Сколько пользователей используют кнопки vs вводят команды вручную
3. **Время до первого действия**: Как быстро пользователи находят нужную команду

### Логирование

Добавить логирование в метод `buttonTextToCommand()`:
```java
log.info("Кнопка '{}' преобразована в команду '{}' для пользователя {}", 
    buttonText, command, userId);
```

Это поможет отслеживать популярность различных команд и оптимизировать расположение кнопок в будущем.
