# Требования: Фильтрация завершенных и удаленных событий

## Введение

Система семейного календаря отображает завершенные (COMPLETED) и удаленные (DELETED) события в списках команд `/upcoming_events`, `/today` и `/week`, хотя эти события не должны быть видны пользователям в данных контекстах. Это приводит к путанице и загромождению интерфейса неактуальной информацией.

## Глоссарий

- **System** - система семейного календаря Telegram бота
- **Event** - событие в календаре с определенным статусом
- **EventStatus** - статус события (DRAFT, ACTIVE, COMPLETED, DELETED)
- **Active Event** - событие со статусом ACTIVE
- **Completed Event** - событие со статусом COMPLETED (время события прошло)
- **Deleted Event** - событие со статусом DELETED (находится в корзине)
- **Upcoming Events List** - список предстоящих событий, отображаемый командой /upcoming_events
- **Today Events List** - список событий на сегодня, отображаемый командой /today
- **Week Events List** - список событий на неделю, отображаемый командой /week

## Требования

### Требование 1

**User Story:** Как пользователь, я хочу видеть только активные события в списке предстоящих событий, чтобы не отвлекаться на завершенные или удаленные события.

#### Критерии приемки

1. WHEN пользователь выполняет команду /upcoming_events THEN THE System SHALL отображать только события со статусом ACTIVE
2. WHEN пользователь выполняет команду /upcoming_events THEN THE System SHALL исключать события со статусом COMPLETED из результатов
3. WHEN пользователь выполняет команду /upcoming_events THEN THE System SHALL исключать события со статусом DELETED из результатов
4. WHEN пользователь выполняет команду /upcoming_events THEN THE System SHALL исключать события со статусом DRAFT из результатов

### Требование 2

**User Story:** Как пользователь, я хочу видеть только активные события в списке событий на сегодня, чтобы планировать свой день без учета завершенных или удаленных событий.

#### Критерии приемки

1. WHEN пользователь выполняет команду /today THEN THE System SHALL отображать только события со статусом ACTIVE
2. WHEN пользователь выполняет команду /today THEN THE System SHALL исключать события со статусом COMPLETED из результатов
3. WHEN пользователь выполняет команду /today THEN THE System SHALL исключать события со статусом DELETED из результатов
4. WHEN пользователь выполняет команду /today THEN THE System SHALL исключать события со статусом DRAFT из результатов

### Требование 3

**User Story:** Как пользователь, я хочу видеть только активные события в списке событий на неделю, чтобы планировать свою неделю без учета завершенных или удаленных событий.

#### Критерии приемки

1. WHEN пользователь выполняет команду /week THEN THE System SHALL отображать только события со статусом ACTIVE
2. WHEN пользователь выполняет команду /week THEN THE System SHALL исключать события со статусом COMPLETED из результатов
3. WHEN пользователь выполняет команду /week THEN THE System SHALL исключать события со статусом DELETED из результатов
4. WHEN пользователь выполняет команду /week THEN THE System SHALL исключать события со статусом DRAFT из результатов

### Требование 4

**User Story:** Как разработчик, я хочу иметь централизованную логику фильтрации событий по статусу, чтобы обеспечить консистентность поведения системы.

#### Критерии приемки

1. WHEN метод получения событий вызывается THEN THE System SHALL применять фильтрацию по статусу на уровне запроса к базе данных
2. WHEN фильтрация по статусу применяется THEN THE System SHALL использовать единую логику для всех команд просмотра событий
3. WHEN события запрашиваются из базы данных THEN THE System SHALL включать условие фильтрации статуса в SQL запрос для оптимизации производительности
