# Документ требований

## Введение

Команда `/stats` отображает некорректную статистику событий. При наличии 2 активных событий система показывает "Всего событий: 5", включая в подсчет завершенные события, которые не отображаются в `/my_events`. Это создает несоответствие между статистикой и фактическим списком событий пользователя.

## Глоссарий

- **Система** - Telegram-бот семейного календаря
- **Активное событие** - событие со статусом ACTIVE
- **Завершенное событие** - событие со статусом COMPLETED
- **Удаленное событие** - событие со статусом DELETED
- **Черновик** - событие со статусом DRAFT
- **Команда /stats** - команда для отображения статистики событий за текущий месяц
- **Команда /my_events** - команда для отображения списка активных событий пользователя

## Требования

### Требование 1

**Пользовательская история:** Как пользователь, я хочу видеть в статистике только те события, которые отображаются в моем списке событий, чтобы данные были согласованными.

#### Критерии приемки

1. WHEN пользователь вызывает команду /stats THEN система SHALL подсчитывать в "Всего событий" только события со статусом ACTIVE
2. WHEN пользователь вызывает команду /stats THEN система SHALL исключать из подсчета "Всего событий" события со статусами COMPLETED, DELETED и DRAFT
3. WHEN пользователь вызывает команду /stats THEN значение "Всего событий" SHALL быть равно сумме "Завершено" и "Активных"
4. WHEN пользователь вызывает команду /stats THEN количество событий в статистике SHALL соответствовать количеству событий в /my_events
5. WHEN в месяце есть только завершенные события THEN система SHALL показывать "Всего событий: 0"

### Требование 2

**Пользовательская история:** Как пользователь, я хочу видеть корректную статистику по типам событий, чтобы понимать распределение моих активных задач.

#### Критерии приемки

1. WHEN пользователь вызывает команду /stats THEN система SHALL подсчитывать семейные события только со статусом ACTIVE
2. WHEN пользователь вызывает команду /stats THEN система SHALL подсчитывать персональные события только со статусом ACTIVE
3. WHEN пользователь вызывает команду /stats THEN сумма семейных и персональных событий SHALL быть равна "Всего событий"
4. WHEN пользователь вызывает команду /stats THEN система SHALL исключать из подсчета по типам события со статусами COMPLETED, DELETED и DRAFT

### Требование 3

**Пользовательская история:** Как пользователь, я хочу видеть корректный процент завершения, чтобы оценивать свою продуктивность.

#### Критерии приемки

1. WHEN пользователь вызывает команду /stats THEN система SHALL рассчитывать процент завершения как отношение завершенных событий к сумме активных и завершенных событий
2. WHEN в месяце нет активных и завершенных событий THEN система SHALL показывать процент завершения 0%
3. WHEN все события месяца завершены THEN система SHALL показывать процент завершения 100%
4. WHEN пользователь вызывает команду /stats THEN система SHALL исключать из расчета процента события со статусами DELETED и DRAFT
