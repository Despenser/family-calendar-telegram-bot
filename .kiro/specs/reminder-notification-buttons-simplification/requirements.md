# Requirements Document

## Introduction

Данная спецификация описывает упрощение кнопок в уведомлениях о напоминаниях в Telegram боте семейного календаря. В текущей реализации при получении уведомления о напоминании пользователь видит три ряда кнопок: "Посмотреть детали", "Редактировать" и "Удалить". Необходимо упростить интерфейс, оставив только одну кнопку "Посмотреть детали", которая будет открывать детали события в том же сообщении без возможности редактирования или удаления. После просмотра деталей пользователь сможет вернуться к минималистичному виду напоминания с помощью кнопки "Назад к напоминанию".

## Glossary

- **Reminder_Notification**: Уведомление о напоминании, отправляемое пользователю в Telegram
- **Reminder_Keyboard**: Inline-клавиатура, прикрепленная к уведомлению о напоминании
- **View_Details_Button**: Кнопка "Посмотреть детали" для просмотра информации о событии
- **Back_To_Reminder_Button**: Кнопка "Назад к напоминанию" для возврата к минималистичному виду уведомления
- **ReminderService**: Сервис для управления напоминаниями и отправки уведомлений
- **EventCallbackHandler**: Обработчик callback-запросов для просмотра деталей события
- **Message_Update**: Операция редактирования существующего сообщения в Telegram чате
- **Event_Details**: Полная информация о событии, включая название, дату, время, описание и тип

## Requirements

### Requirement 1: Упрощение клавиатуры уведомления о напоминании

**User Story:** Как пользователь, я хочу видеть простую клавиатуру с одной кнопкой в уведомлении о напоминании, чтобы интерфейс был понятным и не перегруженным.

#### Acceptance Criteria

1. WHEN система отправляет уведомление о напоминании THEN THE System SHALL прикрепить клавиатуру с одной кнопкой "📋 Посмотреть детали"
2. WHEN формируется клавиатура уведомления о напоминании THEN THE System SHALL создать только один ряд с одной кнопкой
3. WHEN формируется клавиатура уведомления о напоминании THEN THE System SHALL использовать callback data формата "view_event_{eventId}"

### Requirement 2: Отображение деталей события в том же сообщении

**User Story:** Как пользователь, я хочу видеть детали события в том же сообщении после нажатия кнопки "Посмотреть детали", чтобы не переключаться между сообщениями.

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "📋 Посмотреть детали" в уведомлении о напоминании THEN THE System SHALL обновить текст сообщения с полной информацией о событии
2. WHEN обновляется сообщение с деталями события THEN THE System SHALL сохранить исходный messageId
3. WHEN обновляется сообщение с деталями события THEN THE System SHALL заменить клавиатуру на клавиатуру с действиями над событием
4. WHEN обновляется сообщение с деталями события THEN THE System SHALL включить в текст название события, дату, время, описание и тип события
5. WHEN обновляется сообщение с деталями события THEN THE System SHALL использовать форматирование Markdown для читаемости

### Requirement 3: Клавиатура после просмотра деталей

**User Story:** Как пользователь, я хочу видеть только информацию о событии после просмотра деталей, чтобы не выполнять случайные действия из уведомления о напоминании.

#### Acceptance Criteria

1. WHEN отображаются детали события после нажатия "Посмотреть детали" THEN THE System SHALL показать только кнопку "◀️ Назад к напоминанию"
2. WHEN формируется клавиатура после просмотра деталей THEN THE System SHALL не включать кнопки "✏️ Редактировать" и "🗑️ Удалить"
3. WHEN формируется клавиатура после просмотра деталей THEN THE System SHALL не включать кнопку "✅ Завершить"
4. WHEN формируется клавиатура после просмотра деталей THEN THE System SHALL не включать кнопку "📎 Вложения"
5. WHEN формируется клавиатура после просмотра деталей THEN THE System SHALL создать один ряд с одной кнопкой "◀️ Назад к напоминанию"

### Requirement 4: Возврат к минималистичному виду напоминания

**User Story:** Как пользователь, я хочу иметь возможность свернуть детали события и вернуться к минималистичному виду напоминания, чтобы не загромождать чат подробной информацией.

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "◀️ Назад к напоминанию" THEN THE System SHALL обновить сообщение с исходным текстом напоминания
2. WHEN обновляется сообщение при возврате к напоминанию THEN THE System SHALL восстановить исходный текст уведомления о напоминании
3. WHEN обновляется сообщение при возврате к напоминанию THEN THE System SHALL заменить клавиатуру на упрощенную клавиатуру с одной кнопкой "📋 Посмотреть детали"
4. WHEN обновляется сообщение при возврате к напоминанию THEN THE System SHALL сохранить исходный messageId
5. WHEN обновление сообщения завершено THEN THE System SHALL отправить callback query answer с подтверждением

### Requirement 5: Обработка callback-запроса view_event

**User Story:** Как разработчик, я хочу, чтобы обработчик callback-запроса view_event корректно обрабатывал запросы из уведомлений о напоминаниях, чтобы пользователь мог просматривать детали события.

#### Acceptance Criteria

1. WHEN обрабатывается callback-запрос "view_event_{eventId}" из уведомления о напоминании THEN THE System SHALL извлечь eventId из callback data
2. WHEN извлечен eventId THEN THE System SHALL загрузить событие из базы данных
3. IF событие не найдено THEN THE System SHALL отправить callback query answer с сообщением об ошибке
4. WHEN событие найдено THEN THE System SHALL обновить сообщение с полной информацией о событии
5. WHEN обновление сообщения завершено THEN THE System SHALL отправить callback query answer с подтверждением

### Requirement 6: Обработка callback-запроса back_to_reminder

**User Story:** Как разработчик, я хочу, чтобы обработчик callback-запроса back_to_reminder корректно восстанавливал исходное уведомление о напоминании, чтобы пользователь мог вернуться к минималистичному виду.

#### Acceptance Criteria

1. WHEN обрабатывается callback-запрос "back_to_reminder_{eventId}_{reminderId}" THEN THE System SHALL извлечь eventId и reminderId из callback data
2. WHEN извлечены eventId и reminderId THEN THE System SHALL загрузить событие и напоминание из базы данных
3. IF событие или напоминание не найдены THEN THE System SHALL отправить callback query answer с сообщением об ошибке
4. WHEN событие и напоминание найдены THEN THE System SHALL восстановить исходный текст уведомления о напоминании
5. WHEN обновление сообщения завершено THEN THE System SHALL отправить callback query answer с подтверждением

### Requirement 7: Единообразие клавиатур уведомлений

**User Story:** Как пользователь, я хочу видеть одинаковые клавиатуры во всех уведомлениях о напоминаниях, чтобы интерфейс был предсказуемым.

#### Acceptance Criteria

1. WHEN отправляется уведомление о напоминании типа MORNING_OF_DAY THEN THE System SHALL использовать упрощенную клавиатуру с одной кнопкой
2. WHEN отправляется уведомление о напоминании типа EVENING_BEFORE THEN THE System SHALL использовать упрощенную клавиатуру с одной кнопкой
3. WHEN отправляется уведомление о напоминании типа ONE_HOUR_BEFORE THEN THE System SHALL использовать упрощенную клавиатуру с одной кнопкой
4. WHEN отправляется уведомление о напоминании типа FIFTEEN_MINUTES_BEFORE THEN THE System SHALL использовать упрощенную клавиатуру с одной кнопкой
5. WHEN отправляется уведомление о напоминании типа CUSTOM THEN THE System SHALL использовать упрощенную клавиатуру с одной кнопкой

### Requirement 8: Обратная совместимость

**User Story:** Как разработчик, я хочу, чтобы изменения не сломали существующую функциональность просмотра событий, чтобы пользователи могли продолжать использовать бота без проблем.

#### Acceptance Criteria

1. WHEN обрабатывается callback-запрос "view_event_{eventId}" из других частей приложения THEN THE System SHALL продолжать работать корректно
2. WHEN обновляется сообщение с деталями события THEN THE System SHALL использовать существующий метод форматирования события
3. WHEN обрабатывается ошибка при обновлении сообщения THEN THE System SHALL залогировать предупреждение и продолжить выполнение
4. WHEN пользователь открывает событие из других частей приложения THEN THE System SHALL показывать стандартную клавиатуру с действиями
5. WHEN пользователь открывает событие из уведомления о напоминании THEN THE System SHALL показывать упрощенную клавиатуру только с кнопкой "Назад к напоминанию"

### Requirement 9: Логирование операций

**User Story:** Как разработчик, я хочу иметь детальное логирование операций просмотра деталей события, чтобы легко диагностировать проблемы в production.

#### Acceptance Criteria

1. WHEN создается упрощенная клавиатура уведомления THEN THE System SHALL залогировать debug сообщение с eventId
2. WHEN обрабатывается callback-запрос view_event THEN THE System SHALL залогировать debug сообщение с eventId и userId
3. WHEN обновляется сообщение с деталями события THEN THE System SHALL залогировать debug сообщение с eventId и messageId
4. IF обновление сообщения не удается THEN THE System SHALL залогировать warning с eventId, messageId и деталями ошибки
5. WHEN операция завершается успешно THEN THE System SHALL залогировать info сообщение с eventId
