# Design Document

## Overview

Данный дизайн описывает упрощение интерфейса уведомлений о напоминаниях в Telegram боте семейного календаря. Основная цель - создать минималистичный и интуитивно понятный интерфейс, который позволяет пользователю просматривать детали события прямо в уведомлении о напоминании без возможности случайного редактирования или удаления.

### Ключевые изменения

1. **Упрощение клавиатуры напоминания**: вместо трех рядов кнопок ("Посмотреть детали", "Редактировать", "Удалить") останется только одна кнопка "📋 Посмотреть детали"

2. **Inline просмотр деталей**: при нажатии на "Посмотреть детали" сообщение обновляется (editMessageText) с полной информацией о событии, сохраняя тот же messageId

3. **Минималистичная клавиатура деталей**: после просмотра деталей показывается только кнопка "◀️ Назад к напоминанию" без кнопок редактирования, удаления или завершения

4. **Возврат к напоминанию**: кнопка "◀️ Назад к напоминанию" восстанавливает исходный текст уведомления и упрощенную клавиатуру

5. **Обратная совместимость**: просмотр событий из других частей приложения (например, /my_events) продолжит работать со стандартной клавиатурой с действиями

## Architecture

### Компоненты системы

```
┌─────────────────────────────────────────────────────────────┐
│                    ReminderScheduler                         │
│  (отправляет уведомления о напоминаниях)                    │
└────────────────────┬────────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────────┐
│                    ReminderService                           │
│  - sendReminderNotification()                               │
│  - createSimplifiedReminderKeyboard()  [NEW]                │
│  - formatReminderMessageByType()                            │
└────────────────────┬────────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────────┐
│              TelegramMessageService                          │
│  - sendMessageWithInlineKeyboard()                          │
│  - editMessageText()                                        │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│              CallbackQueryDispatcher                         │
│  (маршрутизирует callback queries)                          │
└────────────────────┬────────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────────┐
│              EventCallbackHandler                            │
│  - handleViewEvent() [MODIFIED]                             │
│  - handleBackToReminder() [NEW]                             │
│  - createDetailsKeyboard() [NEW]                            │
└─────────────────────────────────────────────────────────────┘
```

### Поток данных

#### 1. Отправка уведомления о напоминании

```
ReminderScheduler
  └─> ReminderService.sendReminderNotification()
       ├─> formatReminderMessageByType()  // Форматирует текст
       ├─> createSimplifiedReminderKeyboard()  // Создает упрощенную клавиатуру
       └─> TelegramMessageService.sendMessageWithInlineKeyboard()
```

#### 2. Просмотр деталей события

```
User clicks "📋 Посмотреть детали"
  └─> CallbackQueryDispatcher
       └─> EventCallbackHandler.handleViewEvent()
            ├─> EventService.getEventById()
            ├─> BotMessageBuilder.buildEventMessage()
            ├─> createDetailsKeyboard()  // Создает клавиатуру с кнопкой "Назад"
            ├─> TelegramMessageService.editMessageText()  // Обновляет сообщение
            └─> TelegramMessageService.answerCallbackQuery()
```

#### 3. Возврат к напоминанию

```
User clicks "◀️ Назад к напоминанию"
  └─> CallbackQueryDispatcher
       └─> EventCallbackHandler.handleBackToReminder()
            ├─> ReminderService.getReminderById()
            ├─> ReminderService.formatReminderMessageByType()
            ├─> ReminderService.createSimplifiedReminderKeyboard()
            ├─> TelegramMessageService.editMessageText()  // Восстанавливает напоминание
            └─> TelegramMessageService.answerCallbackQuery()
```

## Components and Interfaces

### 1. ReminderService (Modified)

**Новый метод:**

```java
/**
 * Создает упрощенную клавиатуру для уведомления о напоминании.
 * 
 * <p>Клавиатура содержит только одну кнопку "📋 Посмотреть детали",
 * которая открывает детали события в том же сообщении.</p>
 * 
 * @param event событие для создания клавиатуры
 * @return inline-клавиатура с одной кнопкой
 */
private InlineKeyboardMarkup createSimplifiedReminderKeyboard(Event event)
```

**Изменения в существующем методе:**

```java
/**
 * Создает клавиатуру для уведомления о напоминании.
 * 
 * БЫЛО: 3 ряда кнопок (Посмотреть детали, Редактировать, Удалить)
 * СТАЛО: 1 ряд с 1 кнопкой (Посмотреть детали)
 * 
 * @param event событие
 * @param userId идентификатор пользователя
 * @return inline-клавиатура
 */
private InlineKeyboardMarkup createReminderKeyboard(Event event, Long userId)
```

### 2. EventCallbackHandler (Modified)

**Изменения в существующем методе:**

```java
/**
 * Обрабатывает просмотр деталей события.
 * 
 * БЫЛО: Отправляет новое сообщение с деталями
 * СТАЛО: Обновляет текущее сообщение с деталями
 * 
 * @param callbackData данные callback (формат: view_event_{eventId})
 * @param userId идентификатор пользователя
 * @param chatId идентификатор чата
 * @param messageId идентификатор сообщения для обновления [NEW]
 * @param callbackQueryId идентификатор callback query
 */
private void handleViewEvent(String callbackData, Long userId, Long chatId,
                             Integer messageId, String callbackQueryId)
```

**Новый метод:**

```java
/**
 * Обрабатывает возврат к минималистичному виду напоминания.
 * 
 * <p>Восстанавливает исходный текст уведомления о напоминании
 * и упрощенную клавиатуру с одной кнопкой.</p>
 * 
 * @param callbackData данные callback (формат: back_to_reminder_{eventId}_{reminderId})
 * @param userId идентификатор пользователя
 * @param chatId идентификатор чата
 * @param messageId идентификатор сообщения для обновления
 * @param callbackQueryId идентификатор callback query
 */
private void handleBackToReminder(String callbackData, Long userId, Long chatId,
                                  Integer messageId, String callbackQueryId)
```

**Новый метод:**

```java
/**
 * Создает клавиатуру для просмотра деталей события из напоминания.
 * 
 * <p>Клавиатура содержит только одну кнопку "◀️ Назад к напоминанию"
 * без кнопок редактирования, удаления или завершения.</p>
 * 
 * @param eventId идентификатор события
 * @param reminderId идентификатор напоминания
 * @return inline-клавиатура с кнопкой "Назад"
 */
private InlineKeyboardMarkup createDetailsKeyboard(Long eventId, Long reminderId)
```

## Correctness Properties

*Свойство (property) - это характеристика или поведение, которое должно выполняться для всех допустимых входных данных системы. Свойства служат мостом между человекочитаемыми спецификациями и машинопроверяемыми гарантиями корректности.*

### Property 1: Структура клавиатуры напоминания

*Для любого* события и напоминания, клавиатура уведомления о напоминании должна содержать ровно один ряд с одной кнопкой "📋 Посмотреть детали" с callback data формата "view_event_{eventId}"

**Validates: Requirements 1.1, 1.2, 1.3**

### Property 2: Обновление сообщения при просмотре деталей

*Для любого* события, при нажатии кнопки "Посмотреть детали" сообщение должно обновиться (а не создаться новое), содержать полную информацию о событии (название, дату, время, описание, тип) с Markdown форматированием, и иметь клавиатуру только с кнопкой "Назад к напоминанию"

**Validates: Requirements 2.1, 2.3, 2.4, 2.5**

### Property 3: Отсутствие кнопок действий в деталях

*Для любого* события, клавиатура после просмотра деталей из напоминания не должна содержать кнопки "✏️ Редактировать", "🗑️ Удалить", "✅ Завершить" или "📎 Вложения", а только кнопку "◀️ Назад к напоминанию"

**Validates: Requirements 3.1, 3.2, 3.3, 3.4, 3.5**

### Property 4: Round-trip восстановление напоминания

*Для любого* события и напоминания, последовательность действий "просмотр деталей" → "назад к напоминанию" должна восстановить исходный текст уведомления и упрощенную клавиатуру с одной кнопкой

**Validates: Requirements 4.1, 4.2, 4.3**

### Property 5: Сохранение messageId

*Для любого* события, messageId должен оставаться неизменным при всех обновлениях сообщения (просмотр деталей, возврат к напоминанию)

**Validates: Requirements 2.2, 4.4**

### Property 6: Единообразие клавиатур для всех типов напоминаний

*Для любого* типа напоминания (MORNING_OF_DAY, EVENING_BEFORE, ONE_HOUR_BEFORE, FIFTEEN_MINUTES_BEFORE, CUSTOM), клавиатура уведомления должна иметь одинаковую структуру - один ряд с одной кнопкой "Посмотреть детали"

**Validates: Requirements 7.1, 7.2, 7.3, 7.4, 7.5**

### Property 7: Обратная совместимость просмотра событий

*Для любого* события, при просмотре из других частей приложения (не из напоминания), клавиатура должна содержать стандартные кнопки действий (редактирование, удаление, завершение), а при просмотре из напоминания - только кнопку "Назад к напоминанию"

**Validates: Requirements 8.1, 8.4, 8.5**

## Error Handling

### 1. Событие не найдено

**Сценарий:** Пользователь нажимает "Посмотреть детали", но событие было удалено

**Обработка:**
- Отправить callback query answer с сообщением "❌ Событие не найдено"
- Залогировать warning с eventId и userId
- Не обновлять сообщение

### 2. Напоминание не найдено

**Сценарий:** Пользователь нажимает "Назад к напоминанию", но напоминание было удалено

**Обработка:**
- Отправить callback query answer с сообщением "❌ Напоминание не найдено"
- Залогировать warning с eventId, reminderId и userId
- Не обновлять сообщение

### 3. Ошибка обновления сообщения

**Сценарий:** Telegram API возвращает ошибку при попытке обновить сообщение

**Обработка:**
- Залогировать warning с eventId, messageId и деталями ошибки
- Отправить callback query answer с сообщением "❌ Произошла ошибка"
- Продолжить выполнение (не прерывать)

### 4. Некорректный формат callback data

**Сценарий:** Callback data имеет неправильный формат

**Обработка:**
- Залогировать error с callback data и userId
- Отправить callback query answer с сообщением "❌ Некорректный запрос"
- Не обновлять сообщение

## Testing Strategy

### Dual Testing Approach

Для обеспечения комплексного покрытия будут использоваться два типа тестов:

1. **Unit tests**: Проверяют конкретные примеры, граничные случаи и обработку ошибок
2. **Property tests**: Проверяют универсальные свойства на множестве сгенерированных входных данных

Оба типа тестов дополняют друг друга и необходимы для полного покрытия.

### Property-Based Testing Configuration

- **Библиотека**: jqwik (уже используется в проекте)
- **Минимум итераций**: 100 на каждый property test
- **Теги**: Каждый property test должен быть помечен комментарием с ссылкой на свойство из дизайна

Формат тега:
```java
/**
 * Feature: reminder-notification-buttons-simplification, Property 1: Структура клавиатуры напоминания
 * Validates: Requirements 1.1, 1.2, 1.3
 */
```

### Unit Testing Focus

Unit tests должны фокусироваться на:
- Конкретных примерах корректного поведения
- Граничных случаях (пустые поля, специальные символы)
- Обработке ошибок (событие не найдено, ошибка API)
- Интеграционных точках между компонентами

### Property Testing Focus

Property tests должны фокусироваться на:
- Универсальных свойствах, которые должны выполняться для всех входных данных
- Структурных инвариантах (формат клавиатур, callback data)
- Round-trip свойствах (просмотр деталей → возврат к напоминанию)
- Сохранении состояния (messageId не изменяется)

### Test Coverage Goals

- **Минимальное покрытие кода**: 80%
- **Покрытие требований**: 100% (каждое требование должно быть покрыто хотя бы одним тестом)
- **Покрытие свойств**: 100% (каждое свойство должно иметь property test)

### Testing Priorities

1. **Высокий приоритет**:
   - Property 1-5 (основная функциональность)
   - Обработка ошибок (событие/напоминание не найдено)
   - Round-trip тесты

2. **Средний приоритет**:
   - Property 6-7 (единообразие и обратная совместимость)
   - Граничные случаи
   - Интеграционные тесты

3. **Низкий приоритет**:
   - Логирование
   - Форматирование сообщений
   - Callback query answers
