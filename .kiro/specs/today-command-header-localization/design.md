# Документ проектирования

## Обзор

Данный документ описывает проектное решение для исправления формата заголовка команды `/today` с целью обеспечения корректной локализации дня недели на русский язык и использования дефиса вместо вложенных скобок.

Текущая ситуация:
- Команда `/today` использует `DateTimeFormatter` с паттерном `"dd.MM.yyyy (EEEE)"` без указания локали
- Это приводит к выводу дня недели на английском языке (например, "Sunday")
- Формат использует вложенные скобки: "📅 События на сегодня (25.01.2026 (Sunday))"

Целевое состояние:
- Команда `/today` использует `DateTimeFormatter` с паттерном `"dd.MM.yyyy - EEEE"` и русской локалью
- День недели выводится на русском языке (например, "воскресенье")
- Формат использует дефис: "📅 События на сегодня (25.01.2026 - Воскресенье)"

## Архитектура

### Текущая реализация

```java
private static final DateTimeFormatter DATE_FORMATTER = 
    DateTimeFormatter.ofPattern("dd.MM.yyyy (EEEE)");
```

Проблемы:
1. Не указана локаль, используется системная локаль по умолчанию
2. Паттерн использует скобки вокруг дня недели
3. День недели выводится на английском языке

### Целевая реализация

```java
private static final DateTimeFormatter DATE_FORMATTER = 
    DateTimeFormatter.ofPattern("dd.MM.yyyy - EEEE", Locale.forLanguageTag("ru"));
```

Улучшения:
1. Явно указана русская локаль
2. Паттерн использует дефис для разделения даты и дня недели
3. День недели будет выводиться на русском языке с правильным склонением

## Компоненты и интерфейсы

### TodayCommandHandler

**Изменения:**
- Обновить константу `DATE_FORMATTER` для использования русской локали и нового паттерна

**Было:**
```java
private static final DateTimeFormatter DATE_FORMATTER = 
    DateTimeFormatter.ofPattern("dd.MM.yyyy (EEEE)");
```

**Стало:**
```java
private static final DateTimeFormatter DATE_FORMATTER = 
    DateTimeFormatter.ofPattern("dd.MM.yyyy - EEEE", Locale.forLanguageTag("ru"));
```

**Пример вывода:**

Было:
```
📅 События на сегодня (25.01.2026 (Sunday))
```

Стало:
```
📅 События на сегодня (25.01.2026 - воскресенье)
```

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться во всех допустимых выполнениях системы - по сути, формальное утверждение о том, что должна делать система. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Свойство 1: Русская локализация дня недели

*Для любого* выполнения команды `/today`, заголовок должен содержать день недели на русском языке (один из: понедельник, вторник, среда, четверг, пятница, суббота, воскресенье).

**Проверяет: Требование 1.1, 1.2**

### Свойство 2: Формат с дефисом

*Для любого* выполнения команды `/today`, заголовок должен содержать дату в формате "ДД.ММ.ГГГГ - День_недели" с дефисом в качестве разделителя.

**Проверяет: Требование 1.3**

### Свойство 3: Полный формат заголовка

*Для любого* выполнения команды `/today`, полный заголовок должен соответствовать формату "📅 События на сегодня (ДД.ММ.ГГГГ - День_недели)".

**Проверяет: Требование 1.4**

## Обработка ошибок

Обработка ошибок остается без изменений. Изменение затрагивает только форматирование даты, которое не может привести к ошибкам при корректной реализации.

## Стратегия тестирования

### Unit-тесты

1. **TodayCommandHandlerTest**
   - Тест на корректное отображение дня недели на русском языке
   - Тест на использование дефиса в формате даты
   - Тест на полный формат заголовка команды

### Property-based тесты

Property-based тесты будут использовать библиотеку **jqwik** для Java.

1. **Свойство 1: Русская локализация дня недели**
   - Генерировать случайные даты
   - Проверять, что день недели в заголовке является одним из русских названий дней недели

2. **Свойство 2: Формат с дефисом**
   - Генерировать случайные даты
   - Проверять, что заголовок содержит дефис между датой и днем недели

3. **Свойство 3: Полный формат заголовка**
   - Генерировать случайные даты
   - Проверять, что заголовок соответствует ожидаемому формату с эмодзи, текстом и датой

### Конфигурация property-based тестов

- Каждый property-based тест должен выполнять минимум 100 итераций
- Каждый тест должен быть помечен комментарием с ссылкой на свойство корректности
- Формат комментария: `**Feature: today-command-header-localization, Property {number}: {property_text}**`
