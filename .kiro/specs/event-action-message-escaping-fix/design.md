# Design Document: Исправление экранирования в сообщениях о действиях с событиями

## Overview

Данный дизайн описывает исправление ошибок экранирования MarkdownV2 во всех сообщениях бота, где используется ручное экранирование специальных символов. Проблема заключается в неправильном использовании методов MarkdownFormatter - смешивании ручного экранирования с методами форматирования, что приводит к двойному экранированию или пропуску специальных символов.

Найдено 8 проблемных мест:
- MyEventsCommandHandler: 4 места (строки 407, 436, 456, 460)
- UpdateProcessor: 4 места (строки 988, 1890, 1963, 2093)

## Architecture

Исправление затрагивает два компонента:
1. **MyEventsCommandHandler** - обработчик команды просмотра событий с функциями загрузки деталей и удаления
2. **UpdateProcessor** - процессор обновлений с функциями редактирования событий

Оба компонента используют **MarkdownFormatter** для форматирования сообщений, но в некоторых местах делают это неправильно, добавляя ручное экранирование точек (`\\.`) в строковые литералы, передаваемые в `formatMessage()`.

## Components and Interfaces

### MyEventsCommandHandler

#### Проблема 1: Ошибка загрузки деталей события (строка ~407)

**Текущая реализация (неправильная):**
```java
return formatMessage("❌ %s\n\n%s",
       bold("Ошибка"),
       "Не удалось загрузить детали события\\. Возможно, событие было удалено\\.");
```

**Проблема:** 
- Ручное экранирование точек (`\\.`) в строковом литерале
- formatMessage уже экранирует все специальные символы, включая точки
- Результат: двойное экранирование точек (`\\\\.`)

**Правильная реализация:**
```java
return formatMessage("❌ %s\n\n%s",
       bold("Ошибка"),
       "Не удалось загрузить детали события. Возможно, событие было удалено.");
```

#### Проблема 2: Событие не найдено при удалении (строка ~456)

**Текущая реализация (неправильная):**
```java
return formatMessage("❌ %s\n\nСобытие не найдено\\. Возможно, оно было удалено\\.",
       bold("Ошибка"));
```

**Проблема:** 
- Ручное экранирование точек (`\\.`) в строковом литерале
- formatMessage уже экранирует все специальные символы
- Результат: двойное экранирование точек

**Правильная реализация:**
```java
return formatMessage("❌ %s\n\nСобытие не найдено. Возможно, оно было удалено.",
       bold("Ошибка"));
```

#### Проблема 3: Доступ запрещен (строка ~436)

### UpdateProcessor

#### Проблема 5: Общая ошибка (строка ~988)

**Текущая реализация (неправильная):**
```java
messageService.answerCallbackQuery(callbackQueryId, 
    formatMessage("❌ Произошла ошибка\\. Попробуйте еще раз\\."));
```

**Проблема:** 
- Ручное экранирование точек (`\\.`) в строковом литерале
- formatMessage уже экранирует все специальные символы
- Результат: двойное экранирование точек

**Правильная реализация:**
```java
messageService.answerCallbackQuery(callbackQueryId, 
    formatMessage("❌ Произошла ошибка. Попробуйте еще раз."));
```

#### Проблема 6: Событие не найдено при редактировании (строка ~1890)

**Текущая реализация (неправильная):**

```java
String response = formatMessage(
    "❌ %s\n\n%s",
    bold("Событие не найдено"),
    "Возможно, событие было удалено\\."
);
```

**Проблема:** 
- Ручное экранирование точки (`\\.`) в строковом литерале
- formatMessage уже экранирует все специальные символы
- Результат: двойное экранирование точки

**Правильная реализация:**
```java
String response = formatMessage(
    "❌ %s\n\n%s",
    bold("Событие не найдено"),
    "Возможно, событие было удалено."
);
```

#### Проблема 7: Событие не найдено при редактировании (строка ~1963)

**Текущая реализация (неправильная):**
```java
String response = formatMessage(
    "❌ %s\n\n%s",
    bold("Событие не найдено"),
    "Возможно, событие было удалено\\."
);
```

**Проблема:** 
- Ручное экранирование точки (`\\.`) в строковом литерале
- Аналогично проблеме 3

**Правильная реализация:**
```java
String response = formatMessage(
    "❌ %s\n\n%s",
    bold("Событие не найдено"),
    "Возможно, событие было удалено."
);
```

#### Проблема 8: Отмена редактирования (строка ~2093)

**Текущая реализация (неправильная):**
```java
String response = formatMessage(
    "❌ %s\n\n%s",
    bold("Редактирование отменено"),
    italic("Изменения не сохранены\\.")
);
```

**Проблема:** 
- Ручное экранирование точки (`\\.`) внутри вызова italic()
- italic() уже экранирует специальные символы
- formatMessage затем пытается экранировать результат
- Результат: двойное экранирование точки

**Правильная реализация:**
```java
String response = formatMessage(
    "❌ %s\n\n%s",
    bold("Редактирование отменено"),
    italic("Изменения не сохранены.")
);
```

## Data Models

Изменения в моделях данных не требуются.

## Correctness Properties

*Свойство (property) - это характеристика или поведение, которое должно выполняться для всех допустимых выполнений системы. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Property 1: Корректное экранирование в сообщениях об ошибках MyEventsCommandHandler

*Для любого* события, когда происходит ошибка загрузки деталей или событие не найдено при удалении, отправленное сообщение должно быть успешно распарсено Telegram API без ошибок 400.

**Validates: Requirements 1.1, 1.2, 1.3**

### Property 2: Корректное экранирование в сообщениях об ошибках UpdateProcessor

*Для любого* события, когда событие не найдено при редактировании или пользователь отменяет редактирование, отправленное сообщение должно быть успешно распарсено Telegram API без ошибок 400.

**Validates: Requirements 2.1, 2.2, 2.3**

### Property 3: Отсутствие ручного экранирования в шаблонах formatMessage

*Для любого* вызова formatMessage, bold() или italic(), шаблон не должен содержать ручного экранирования специальных символов (например, `\\.` или `\\!`), так как эти методы автоматически экранируют все специальные символы.

**Validates: Requirements 3.1, 3.2, 3.3, 3.4, 3.5**

## Error Handling

Обработка ошибок не изменяется. TelegramMessageService уже имеет механизм retry и детальное логирование ошибок 400.

## Testing Strategy

### Unit Tests

1. **Тест форматирования сообщения об удалении**
   - Проверить, что сообщение не содержит двойного экранирования
   - Проверить, что все специальные символы экранированы правильно
   - Проверить, что bold() и code() применены корректно

2. **Тест форматирования сообщения о завершении редактирования**
   - Проверить, что сообщение не содержит двойного экранирования
   - Проверить, что все специальные символы экранированы правильно
   - Проверить, что bold() применен корректно

### Integration Tests

1. **Интеграционный тест удаления события**
   - Создать событие
   - Удалить его через MyEventsCommandHandler
   - Проверить, что TelegramMessageService не выбросил TelegramApiException с кодом 400

2. **Интеграционный тест завершения редактирования**
   - Создать событие
   - Начать редактирование
   - Завершить редактирование через UpdateProcessor
   - Проверить, что TelegramMessageService не выбросил TelegramApiException с кодом 400

### Property-Based Tests

Для данного исправления property-based тесты не требуются, так как проблема специфична для конкретных сообщений, а не для общих свойств форматирования.
