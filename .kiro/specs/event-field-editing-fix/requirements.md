# Документ требований

## Введение

Данный документ описывает требования к улучшению процесса редактирования событий в Telegram боте семейного календаря. В настоящее время при редактировании события (название, описание, дата, время) бот создаёт новые сообщения для каждого шага редактирования, что засоряет чат и ухудшает пользовательский опыт. Требуется изменить поведение так, чтобы все операции редактирования происходили в рамках одного сообщения - того, которое отображает редактируемое событие.

## Глоссарий

- **Event**: Событие в календаре, содержащее название, дату, время, описание и другие атрибуты
- **Message**: Сообщение в Telegram чате, содержащее информацию о событии
- **Edit_Mode**: Режим редактирования, когда сообщение о событии показывает интерфейс для изменения конкретного поля
- **Inline_Keyboard**: Клавиатура с кнопками, прикреплённая к сообщению
- **Callback_Query**: Запрос, отправляемый при нажатии на inline кнопку
- **EventCallbackHandler**: Обработчик callback queries для операций с событиями
- **ConversationState**: Состояние диалога с пользователем, хранящее контекст текущей операции

## Требования

### Требование 1: Редактирование в одном сообщении

**User Story:** Как пользователь, я хочу редактировать событие в том же сообщении, где оно отображается, чтобы чат не засорялся множеством промежуточных сообщений.

#### Критерии приёмки

1. WHEN пользователь нажимает кнопку "Редактировать" на сообщении с событием THEN система SHALL обновить текущее сообщение, показав меню выбора поля для редактирования
2. WHEN пользователь нажимает кнопку "Редактировать название" THEN система SHALL обновить текущее сообщение, показав инструкцию для ввода нового названия
3. WHEN пользователь нажимает кнопку "Редактировать описание" THEN система SHALL обновить текущее сообщение, показав инструкцию для ввода нового описания
4. WHEN пользователь нажимает кнопку "Редактировать дату" THEN система SHALL обновить текущее сообщение, показав календарь для выбора даты
5. WHEN пользователь нажимает кнопку "Редактировать время" THEN система SHALL обновить текущее сообщение, показав интерфейс выбора времени
6. WHEN пользователь завершает редактирование поля THEN система SHALL вернуть сообщение к отображению полной информации о событии

### Требование 2: Кнопка отмены в режиме редактирования

**User Story:** Как пользователь, я хочу иметь возможность отменить редактирование и вернуться к просмотру события, чтобы не быть вынужденным завершать начатое редактирование.

#### Критерии приёмки

1. WHEN сообщение находится в режиме редактирования поля THEN система SHALL отобразить кнопку "Отменить"
2. WHEN пользователь нажимает кнопку "Отменить" в режиме редактирования THEN система SHALL вернуть сообщение к отображению полной информации о событии
3. WHEN пользователь нажимает кнопку "Отменить" THEN система SHALL сохранить все ранее внесённые изменения в событие
4. WHEN пользователь нажимает кнопку "Отменить" THEN система SHALL очистить состояние ожидания ввода для данного пользователя
5. WHEN пользователь нажимает кнопку "Отменить" THEN система SHALL обновить клавиатуру на стандартную для просмотра события

### Требование 3: Редактирование даты в одном сообщении

**User Story:** Как пользователь, я хочу выбирать дату события через календарь в том же сообщении, чтобы процесс редактирования был быстрым и удобным.

#### Критерии приёмки

1. WHEN пользователь нажимает кнопку "Редактировать дату" THEN система SHALL показать календарь в текущем сообщении
2. WHEN пользователь выбирает дату в календаре THEN система SHALL обновить событие с новой датой
3. WHEN дата выбрана THEN система SHALL вернуть сообщение к отображению полной информации о событии с обновлённой датой
4. WHEN пользователь нажимает кнопку навигации по месяцам в календаре THEN система SHALL обновить календарь в том же сообщении
5. WHEN пользователь нажимает "Отменить" в календаре THEN система SHALL вернуть сообщение к отображению события без изменения даты

### Требование 4: Редактирование времени в одном сообщении

**User Story:** Как пользователь, я хочу выбирать время события через интерфейс выбора в том же сообщении, чтобы не переключаться между разными сообщениями.

#### Критерии приёмки

1. WHEN пользователь нажимает кнопку "Редактировать время" THEN система SHALL показать интерфейс выбора времени в текущем сообщении
2. WHEN пользователь выбирает временной интервал THEN система SHALL обновить событие с новым временем
3. WHEN время выбрано THEN система SHALL вернуть сообщение к отображению полной информации о событии с обновлённым временем
4. WHEN пользователь нажимает кнопки навигации по часам THEN система SHALL обновить интерфейс выбора времени в том же сообщении
5. WHEN пользователь нажимает "Отменить" в интерфейсе выбора времени THEN система SHALL вернуть сообщение к отображению события без изменения времени

### Требование 5: Редактирование текстовых полей через состояние диалога

**User Story:** Как пользователь, я хочу вводить новое название или описание события через обычное текстовое сообщение, а затем видеть обновлённое событие в исходном сообщении.

#### Критерии приёмки

1. WHEN пользователь нажимает кнопку "Редактировать название" THEN система SHALL сохранить состояние ожидания ввода названия для данного пользователя
2. WHEN пользователь отправляет текстовое сообщение в состоянии ожидания ввода THEN система SHALL обновить соответствующее поле события
3. WHEN поле события обновлено THEN система SHALL обновить исходное сообщение с новыми данными
4. WHEN поле события обновлено THEN система SHALL удалить текстовое сообщение пользователя
5. WHEN поле события обновлено THEN система SHALL очистить состояние ожидания ввода

### Требование 6: Сохранение контекста редактируемого события

**User Story:** Как система, я хочу отслеживать, какое событие редактируется пользователем, чтобы корректно применять изменения к нужному событию.

#### Критерии приёмки

1. WHEN пользователь начинает редактирование события THEN система SHALL сохранить ID события в состоянии диалога
2. WHEN пользователь начинает редактирование события THEN система SHALL сохранить ID сообщения в состоянии диалога
3. WHEN пользователь вводит новое значение поля THEN система SHALL применить изменение к событию из сохранённого контекста
4. WHEN пользователь завершает или отменяет редактирование THEN система SHALL очистить сохранённый контекст
5. WHEN пользователь начинает редактирование другого события THEN система SHALL заменить контекст на новый

### Требование 7: Обновление клавиатуры в зависимости от режима

**User Story:** Как пользователь, я хочу видеть разные кнопки в зависимости от того, просматриваю я событие или редактирую его поле, чтобы интерфейс был понятным и соответствовал текущему действию.

#### Критерии приёмки

1. WHEN сообщение показывает полную информацию о событии THEN система SHALL отобразить кнопки для редактирования полей и управления событием
2. WHEN сообщение находится в режиме редактирования даты THEN система SHALL отобразить календарь и кнопку "Отменить"
3. WHEN сообщение находится в режиме редактирования времени THEN система SHALL отобразить интерфейс выбора времени и кнопку "Отменить"
4. WHEN сообщение находится в режиме ожидания ввода текста THEN система SHALL отобразить только кнопку "Отменить"
5. WHEN пользователь завершает редактирование THEN система SHALL вернуть стандартную клавиатуру для просмотра события

### Требование 8: Удаление промежуточных сообщений

**User Story:** Как пользователь, я хочу, чтобы мои текстовые сообщения с новыми значениями полей автоматически удалялись после применения, чтобы чат оставался чистым.

#### Критерии приёмки

1. WHEN пользователь отправляет текстовое сообщение с новым названием события THEN система SHALL удалить это сообщение после применения изменений
2. WHEN пользователь отправляет текстовое сообщение с новым описанием события THEN система SHALL удалить это сообщение после применения изменений
3. WHEN система не может удалить сообщение пользователя THEN система SHALL записать предупреждение в лог
4. WHEN система не может удалить сообщение пользователя THEN система SHALL продолжить работу без ошибки
5. WHEN пользователь отменяет редактирование THEN система SHALL не удалять никакие сообщения
