# Документ требований: Исправление утечки черновиков событий

## Введение

В системе обнаружена проблема, при которой в таблице `events` базы данных создаются записи со статусом `DRAFT` и NULL значениями в обязательных полях (`title`, `event_date`, `event_time`). Эти "осиротевшие" черновики возникают, когда процесс создания события прерывается из-за ошибки, но созданный черновик не удаляется. Это приводит к нарушению работы всех команд бота, так как система пытается обработать некорректные записи.

## Глоссарий

- **Система** - Telegram-бот для управления семейным календарем
- **Черновик** - запись события со статусом `DRAFT` в процессе создания
- **Осиротевший черновик** - черновик с NULL значениями, оставшийся после ошибки
- **Транзакция** - атомарная операция с базой данных
- **Откат** - отмена изменений в базе данных при ошибке

## Требования

### Требование 1

**Пользовательская история:** Как пользователь, я хочу, чтобы при ошибке создания события не оставались некорректные записи в базе данных, чтобы бот продолжал корректно работать.

#### Критерии приемки

1. WHEN создание события из текста завершается ошибкой THEN Система SHALL удалить созданный черновик из базы данных
2. WHEN создание события через команду /add_event завершается ошибкой THEN Система SHALL удалить созданный черновик из базы данных
3. WHEN пользователь отменяет создание события THEN Система SHALL удалить все черновики пользователя
4. WHEN в базе данных обнаружены осиротевшие черновики THEN Система SHALL автоматически удалить их при запуске
5. WHEN происходит ошибка при обновлении полей черновика THEN Система SHALL откатить всю транзакцию создания события

### Требование 2

**Пользовательская история:** Как разработчик, я хочу, чтобы операции с черновиками были атомарными, чтобы избежать несогласованного состояния базы данных.

#### Критерии приемки

1. WHEN Система создает черновик и обновляет его поля THEN все операции SHALL выполняться в одной транзакции
2. WHEN транзакция создания события откатывается THEN Система SHALL гарантировать, что черновик не сохранен в базе данных
3. WHEN Система обрабатывает подтверждение создания события из текста THEN все операции от создания черновика до завершения SHALL выполняться атомарно
4. WHEN возникает исключение в процессе создания события THEN Система SHALL автоматически откатить все изменения в базе данных

### Требование 3

**Пользовательская история:** Как администратор системы, я хочу иметь механизм очистки осиротевших черновиков, чтобы поддерживать базу данных в чистом состоянии.

#### Критерии приемки

1. WHEN Система запускается THEN она SHALL проверить наличие осиротевших черновиков старше 1 часа
2. WHEN обнаружены осиротевшие черновики THEN Система SHALL удалить их и записать информацию в лог
3. WHEN Система выполняет периодическую очистку THEN она SHALL удалять черновики старше 24 часов
4. WHEN черновик имеет статус DRAFT и все обязательные поля NULL THEN Система SHALL считать его осиротевшим
