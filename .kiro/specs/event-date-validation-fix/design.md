# Документ проектирования

## Обзор

Исправление логики валидации даты события в `EventService`. Текущая реализация метода `updateEventDate` некорректно сравнивает дату с текущим моментом времени, что приводит к ошибочному отклонению текущей даты как прошедшей.

## Архитектура

Изменения затрагивают только класс `EventService` в слое бизнес-логики. Никакие другие компоненты системы не требуют модификации.

### Текущая проблема

В методе `updateEventDate` (строка 600):

```java
LocalDateTime newDateTime = LocalDateTime.of(newDate, LocalTime.now());
if (newDateTime.isBefore(LocalDateTime.now())) {
    throw new InvalidDateException("Дата события не может быть в прошлом");
}
```

Проблема: метод создаёт `LocalDateTime` с текущим временем и сравнивает его с текущим моментом. Между вызовами `LocalTime.now()` и `LocalDateTime.now()` проходит несколько миллисекунд, что может привести к тому, что `newDateTime` окажется раньше второго вызова `now()`.

### Решение

Сравнивать только даты без учёта времени:

```java
if (newDate.isBefore(LocalDate.now())) {
    throw new InvalidDateException("Дата события не может быть в прошлом");
}
```

## Компоненты и интерфейсы

### EventService

**Изменяемые методы:**

1. `updateEventDate(Long eventId, Long userId, LocalDate newDate)` - основной метод, требующий исправления
2. `createEvent(Long userId, String title, String description, LocalDateTime eventDateTime, LocalTime endTime, Boolean isPersonal)` - требует проверки согласованности
3. `updateEvent(Long eventId, Long userId, String title, String description, LocalDateTime eventDateTime, LocalTime endTime)` - требует проверки согласованности

**Сигнатуры методов остаются без изменений.**

## Модели данных

Изменения в моделях данных не требуются.

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться во всех валидных выполнениях системы - по сути, формальное утверждение о том, что система должна делать. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Свойство 1: Текущая дата всегда валидна

*Для любой* даты, если эта дата равна текущей дате, то валидация должна пройти успешно без выброса исключения.

**Проверяет: Требования 1.1**

### Свойство 2: Будущие даты всегда валидны

*Для любой* даты, если эта дата находится в будущем (после текущей даты), то валидация должна пройти успешно без выброса исключения.

**Проверяет: Требования 1.2**

### Свойство 3: Прошедшие даты всегда отклоняются

*Для любой* даты, если эта дата находится в прошлом (до текущей даты), то валидация должна выбросить `InvalidDateException`.

**Проверяет: Требования 1.3**

### Свойство 4: Валидация сравнивает только даты

*Для любой* даты и любого времени в течение дня, если дата валидна, то результат валидации не должен зависеть от времени суток.

**Проверяет: Требования 1.4**

### Свойство 5: Согласованность валидации между методами

*Для любой* даты, результат валидации должен быть одинаковым во всех методах `EventService`, которые выполняют валидацию даты.

**Проверяет: Требования 2.1, 2.2, 2.3, 2.4**

## Обработка ошибок

Обработка ошибок остаётся без изменений:
- `InvalidDateException` выбрасывается при попытке установить прошедшую дату
- Сообщение об ошибке: "Дата события не может быть в прошлом"

## Стратегия тестирования

### Unit-тесты

Необходимо создать или обновить следующие тесты:

1. **Тест текущей даты**: Проверить, что установка текущей даты проходит успешно
2. **Тест будущей даты**: Проверить, что установка будущей даты проходит успешно
3. **Тест прошедшей даты**: Проверить, что установка прошедшей даты выбрасывает исключение
4. **Тест граничных условий**: Проверить поведение на границе дней (23:59:59)

### Property-based тесты

Каждый property-based тест должен выполняться минимум 100 итераций и быть помечен комментарием в формате:
**Feature: event-date-validation-fix, Property {номер}: {текст свойства}**

1. **Property 1**: Генерировать случайные даты, равные текущей дате, и проверять успешную валидацию
2. **Property 2**: Генерировать случайные будущие даты и проверять успешную валидацию
3. **Property 3**: Генерировать случайные прошедшие даты и проверять выброс исключения
4. **Property 4**: Генерировать случайные валидные даты с разным временем суток и проверять согласованность результата

### Библиотека для property-based тестирования

Для Java Spring Boot рекомендуется использовать **jqwik** - современную библиотеку для property-based тестирования в Java.

Зависимость Maven:
```xml
<dependency>
    <groupId>net.jqwik</groupId>
    <artifactId>jqwik</artifactId>
    <version>1.8.2</version>
    <scope>test</scope>
</dependency>
```

### Конфигурация тестов

- Минимум 100 итераций для каждого property-теста
- Использование `@Property` аннотации из jqwik
- Генераторы дат: `@ForAll LocalDate date` с ограничениями через `@DateRange`
