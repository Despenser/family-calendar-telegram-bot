# Документ требований

## Введение

Исправление ошибки валидации даты события при обновлении. В настоящее время при выборе текущей даты (сегодня) система ошибочно считает её прошедшей и отклоняет обновление события.

## Глоссарий

- **EventService**: Сервис для управления событиями в семейном календаре
- **Event**: Событие в календаре с датой и временем
- **LocalDate**: Дата без времени (год-месяц-день)
- **LocalDateTime**: Дата и время (год-месяц-день-час-минута-секунда)

## Требования

### Требование 1: Валидация даты события

**Пользовательская история:** Как пользователь, я хочу иметь возможность устанавливать текущую дату для события, чтобы создавать события на сегодня.

#### Критерии приёмки

1. WHEN пользователь выбирает текущую дату (сегодня) для события, THEN система SHALL принять эту дату как валидную
2. WHEN пользователь выбирает будущую дату для события, THEN система SHALL принять эту дату как валидную
3. WHEN пользователь выбирает прошедшую дату для события, THEN система SHALL отклонить эту дату с сообщением об ошибке
4. WHEN система проверяет дату события, THEN система SHALL сравнивать только даты без учёта времени
5. WHEN пользователь обновляет дату существующего события на текущую дату, THEN система SHALL успешно обновить событие

### Требование 2: Согласованность валидации

**Пользовательская история:** Как разработчик, я хочу иметь согласованную логику валидации дат во всех методах сервиса, чтобы избежать противоречивого поведения.

#### Критерии приёмки

1. WHEN валидация даты выполняется в методе создания события, THEN система SHALL использовать сравнение только дат
2. WHEN валидация даты выполняется в методе обновления даты события, THEN система SHALL использовать сравнение только дат
3. WHEN валидация даты выполняется в методе полного обновления события, THEN система SHALL использовать сравнение только дат
4. THE система SHALL использовать единый подход к валидации дат во всех методах EventService
