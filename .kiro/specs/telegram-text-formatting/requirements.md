# Документ требований

## Введение

Данная спецификация описывает исправление форматирования текста в Telegram-боте семейного календаря. В настоящее время все сообщения бота отображаются без форматирования - символы Markdown (*_) отображаются как обычный текст, что делает сообщения нечитаемыми. Проблема затрагивает все типы сообщений: уведомления о событиях, результаты поиска, еженедельные сводки и другие.

## Глоссарий

- **Система**: Существующее Spring Boot приложение семейного календарь-бота
- **TelegramMessageService**: Сервис для отправки сообщений через Telegram Bot API
- **ParseMode**: Режим парсинга текста в Telegram API (Markdown, MarkdownV2, HTML)
- **SendMessage**: Объект Telegram Bot API для отправки текстовых сообщений
- **Форматирование**: Визуальное оформление текста (жирный, курсив, моноширинный)
- **Экранирование**: Добавление escape-символов для специальных символов Markdown
- **Handler**: Обработчик команд бота (StartCommandHandler, TodayCommandHandler и т.д.)
- **Scheduler**: Планировщик задач (WeeklySummaryScheduler, EventCompletionScheduler)

## Требования

### Требование 1

**Пользовательская история:** Как член семьи, я хочу видеть форматированный текст в сообщениях бота, чтобы информация была читаемой и структурированной.

#### Критерии приемки

1. WHEN Система отправляет любое сообщение пользователю, THEN Система ДОЛЖНА устанавливать parseMode в значение "MarkdownV2" для объекта SendMessage
2. WHEN сообщение содержит жирный текст, THEN Система ДОЛЖНА использовать синтаксис `*текст*` и корректно экранировать специальные символы
3. WHEN сообщение содержит курсив, THEN Система ДОЛЖНА использовать синтаксис `_текст_` и корректно экранировать специальные символы
4. WHEN сообщение содержит моноширинный текст, THEN Система ДОЛЖНА использовать синтаксис `` `текст` `` и корректно экранировать специальные символы
5. WHEN сообщение отправлено, THEN Система ДОЛЖНА отображать форматирование в Telegram-клиенте пользователя

### Требование 2

**Пользовательская история:** Как разработчик, я хочу иметь централизованный метод для экранирования специальных символов MarkdownV2, чтобы избежать ошибок форматирования.

#### Критерии приемки

1. WHEN Система формирует текст сообщения, THEN Система ДОЛЖНА экранировать символы: `_`, `*`, `[`, `]`, `(`, `)`, `~`, `` ` ``, `>`, `#`, `+`, `-`, `=`, `|`, `{`, `}`, `.`, `!`
2. WHEN текст содержит специальный символ, THEN Система ДОЛЖНА добавить обратный слеш `\` перед символом
3. WHEN текст уже содержит экранированные символы, THEN Система НЕ ДОЛЖНА экранировать их повторно
4. WHEN текст находится внутри форматирующих тегов, THEN Система ДОЛЖНА экранировать только необходимые символы
5. WHEN метод экранирования вызывается с null или пустой строкой, THEN Система ДОЛЖНА вернуть пустую строку без ошибок

### Требование 3

**Пользовательская история:** Как член семьи, я хочу видеть корректное форматирование в уведомлениях о событиях, чтобы легко читать детали.

#### Критерии приемки

1. WHEN Система отправляет уведомление о событии, THEN Система ДОЛЖНА форматировать название события жирным шрифтом
2. WHEN уведомление содержит дату и время, THEN Система ДОЛЖНА форматировать их жирным шрифтом
3. WHEN уведомление содержит описание события, THEN Система ДОЛЖНА экранировать все специальные символы в описании
4. WHEN уведомление содержит эмодзи, THEN Система НЕ ДОЛЖНА экранировать эмодзи
5. WHEN уведомление отправлено, THEN Система ДОЛЖНА отображать все элементы с корректным форматированием

### Требование 4

**Пользовательская история:** Как член семьи, я хочу видеть корректное форматирование в результатах поиска событий, чтобы быстро находить нужную информацию.

#### Критерии приемки

1. WHEN Система отправляет результаты поиска, THEN Система ДОЛЖНА форматировать заголовки разделов жирным шрифтом
2. WHEN результат содержит название события, THEN Система ДОЛЖНА форматировать его жирным шрифтом
3. WHEN результат содержит дату и время, THEN Система ДОЛЖНА форматировать их жирным шрифтом
4. WHEN результат содержит описание, THEN Система ДОЛЖНА экранировать специальные символы в описании
5. WHEN найдено несколько событий, THEN Система ДОЛЖНА разделять их пустыми строками для читаемости

### Требование 5

**Пользовательская история:** Как член семьи, я хочу видеть корректное форматирование в еженедельных сводках, чтобы планировать свою неделю.

#### Критерии приемки

1. WHEN Система отправляет еженедельную сводку, THEN Система ДОЛЖНА форматировать заголовок жирным шрифтом
2. WHEN сводка содержит диапазон дат, THEN Система ДОЛЖНА форматировать даты жирным шрифтом
3. WHEN сводка содержит список событий, THEN Система ДОЛЖНА форматировать название каждого события жирным шрифтом
4. WHEN сводка содержит время событий, THEN Система ДОЛЖНА форматировать время жирным шрифтом
5. WHEN сводка не содержит событий, THEN Система ДОЛЖНА корректно форматировать сообщение об отсутствии событий

### Требование 6

**Пользовательская история:** Как член семьи, я хочу видеть корректное форматирование в списке событий на сегодня, чтобы знать свои планы.

#### Критерии приемки

1. WHEN Система отправляет список событий на сегодня, THEN Система ДОЛЖНА форматировать заголовок с датой жирным шрифтом
2. WHEN список содержит время события, THEN Система ДОЛЖНА форматировать время жирным шрифтом
3. WHEN список содержит название события, THEN Система ДОЛЖНА форматировать его жирным шрифтом
4. WHEN событие имеет описание, THEN Система ДОЛЖНА экранировать специальные символы в описании
5. WHEN список содержит счетчик событий, THEN Система ДОЛЖНА форматировать его курсивом

### Требование 7

**Пользовательская история:** Как член семьи, я хочу видеть корректное форматирование в списке событий на неделю, чтобы планировать свое время.

#### Критерии приемки

1. WHEN Система отправляет список событий на неделю, THEN Система ДОЛЖНА форматировать заголовок с диапазоном дат жирным шрифтом
2. WHEN список группирует события по дням, THEN Система ДОЛЖНА форматировать дату каждого дня жирным шрифтом
3. WHEN событие отображается в списке, THEN Система ДОЛЖНА форматировать время и название жирным шрифтом
4. WHEN неделя не содержит событий, THEN Система ДОЛЖНА корректно форматировать сообщение с рекомендацией
5. WHEN список содержит итоговый счетчик, THEN Система ДОЛЖНА форматировать его курсивом

#### Критерии приемки

2. WHEN создается утилитный класс, THEN Система ДОЛЖНА предоставить метод для создания курсива
3. WHEN создается утилитный класс, THEN Система ДОЛЖНА предоставить метод для создания моноширинного текста
4. WHEN создается утилитный класс, THEN Система ДОЛЖНА предоставить метод для экранирования специальных символов
5. WHEN методы форматирования вызываются, THEN Система ДОЛЖНА автоматически экранировать специальные символы внутри форматируемого текста

### Требование 10

**Пользовательская история:** Как разработчик, я хочу обновить TelegramMessageService для поддержки MarkdownV2, чтобы все сообщения использовали корректное форматирование.

#### Критерии приемки

1. WHEN TelegramMessageService отправляет сообщение, THEN Система ДОЛЖНА устанавливать parseMode="MarkdownV2" для всех SendMessage объектов
2. WHEN метод sendMessage вызывается с текстом, THEN Система ДОЛЖНА проверять корректность форматирования перед отправкой
3. WHEN отправка сообщения не удается из-за ошибки парсинга, THEN Система ДОЛЖНА логировать текст сообщения для отладки
4. WHEN TelegramMessageService отправляет сообщение с inline-кнопками, THEN Система ДОЛЖНА применять форматирование к тексту сообщения
5. WHEN метод sendMessage вызывается, THEN Система ДОЛЖНА возвращать успешный результат при корректной отправке

5. WHEN сообщение об ошибке отправлено, THEN Система ДОЛЖНА отображать его с корректным форматированием

3. WHEN сообщение содержит список элементов, THEN Система ДОЛЖНА форматировать каждый элемент с новой строки
4. WHEN текст содержит пустые строки, THEN Система ДОЛЖНА сохранять их для визуального разделения
5. WHEN многострочное сообщение отправлено, THEN Система ДОЛЖНА отображать его с корректной структурой

1. WHEN создается тест для утилитного класса форматирования, THEN Система ДОЛЖНА проверять корректность экранирования всех специальных символов

5. WHEN создается тест для TelegramMessageService, THEN Система ДОЛЖНА проверять установку parseMode="MarkdownV2"
