# Requirements Document: Исправление учета таймзоны при отправке напоминаний

## Introduction

Система отправки напоминаний о событиях имеет критические проблемы с учетом часового пояса пользователя:

1. **Неправильное время отправки**: Напоминания приходят в неправильное время. Например, событие запланировано на 22:15 по местному времени пользователя, но напоминание приходит в 00:14.

2. **Дублирование напоминаний**: Некоторые напоминания (например, за 1 час) отправляются дважды.

3. **Пропуск напоминаний**: Некоторые напоминания (например, за 15 минут) не отправляются вообще.

Текущая реализация:
- Время напоминания рассчитывается с учетом таймзоны пользователя (метод `calculateReminderTimeWithTimezone`)
- Время напоминания сохраняется в БД как `LocalDateTime` (без информации о таймзоне)
- При отправке напоминаний используется `LocalDateTime.now()` для сравнения, что не учитывает таймзону
- Окно проверки напоминаний (`now` до `now + 1 минута`) может захватывать одно и то же напоминание несколько раз или пропускать его
- Это приводит к смещению времени отправки, дублированию и пропуску напоминаний

## Glossary

- **System**: Система отправки напоминаний о событиях
- **Reminder_Scheduler**: Планировщик, который проверяет и отправляет напоминания каждую минуту
- **User_Timezone**: Часовой пояс пользователя в формате IANA (например, "Europe/Moscow")
- **Reminder_Time**: Время отправки напоминания, сохраненное в БД
- **Server_Time**: Текущее время на сервере (может быть в любой таймзоне)
- **Local_Time**: Локальное время пользователя в его часовом поясе

## Requirements

### Requirement 1: Корректное сравнение времени при отправке напоминаний

**User Story:** Как пользователь, я хочу получать напоминания в правильное время согласно моему часовому поясу, чтобы быть вовремя уведомленным о событиях.

#### Acceptance Criteria

1. WHEN THE Reminder_Scheduler проверяет напоминания для отправки, THE System SHALL использовать одинаковую таймзону для сравнения текущего времени и времени напоминания
2. WHEN THE System сравнивает время напоминания с текущим временем, THE System SHALL конвертировать оба времени в UTC перед сравнением
3. WHEN THE System определяет окно времени для отправки напоминаний, THE System SHALL учитывать, что напоминания могут быть в разных таймзонах
4. WHEN напоминание должно быть отправлено, THE System SHALL отправить его в момент, когда Server_Time соответствует Reminder_Time в UTC
5. WHEN напоминание отправлено, THE System SHALL немедленно отметить его как sent=true, чтобы избежать повторной отправки

### Requirement 2: Предотвращение дублирования напоминаний

**User Story:** Как пользователь, я хочу получать каждое напоминание только один раз, чтобы не получать избыточные уведомления.

#### Acceptance Criteria

1. WHEN THE System отправляет напоминание, THE System SHALL атомарно обновить флаг sent=true в той же транзакции
2. WHEN THE System проверяет напоминания для отправки, THE System SHALL исключать напоминания с sent=true
3. WHEN THE System обрабатывает напоминание, THE System SHALL использовать пессимистическую блокировку для предотвращения одновременной обработки
4. WHEN окно проверки захватывает одно и то же напоминание несколько раз, THE System SHALL отправить его только один раз

### Requirement 3: Предотвращение пропуска напоминаний

**User Story:** Как пользователь, я хочу получать все запланированные напоминания, чтобы не пропустить важные события.

#### Acceptance Criteria

1. WHEN THE System проверяет напоминания для отправки, THE System SHALL использовать окно времени, которое гарантирует захват всех напоминаний
2. WHEN время напоминания находится между проверками планировщика, THE System SHALL все равно отправить его при следующей проверке
3. WHEN THE System определяет окно проверки, THE System SHALL использовать reminder_time <= now вместо reminder_time BETWEEN now AND now+1min
4. WHEN напоминание пропущено из-за остановки сервера, THE System SHALL отправить его при следующем запуске, если оно не старше 1 часа

### Requirement 3: Предотвращение пропуска напоминаний

2. WHEN время напоминания находится между проверками планировщика, THE System SHALL все равно отправить его при следующей проверке

### Requirement 4: Консистентное хранение времени напоминаний

**User Story:** Как разработчик, я хочу, чтобы время напоминаний хранилось консистентно, чтобы избежать проблем с конвертацией таймзон.

#### Acceptance Criteria

1. WHEN THE System сохраняет время напоминания в БД, THE System SHALL сохранять его в UTC
2. WHEN THE System рассчитывает время напоминания с учетом User_Timezone, THE System SHALL конвертировать результат в UTC перед сохранением
3. WHEN THE System читает время напоминания из БД, THE System SHALL интерпретировать его как UTC
4. WHEN THE System отображает время напоминания пользователю, THE System SHALL конвертировать его из UTC в User_Timezone

### Requirement 5: Логирование для отладки проблем с таймзонами

**User Story:** Как разработчик, я хочу видеть подробные логи работы с таймзонами, чтобы быстро диагностировать проблемы.

#### Acceptance Criteria

1. WHEN THE System рассчитывает время напоминания, THE System SHALL логировать исходное время события, User_Timezone и результат в UTC
2. WHEN THE System проверяет напоминания для отправки, THE System SHALL логировать текущее время в UTC и окно проверки
3. WHEN THE System отправляет напоминание, THE System SHALL логировать время отправки в UTC и в User_Timezone получателя
4. WHEN происходит ошибка конвертации таймзоны, THE System SHALL логировать детали ошибки и использованный fallback

### Requirement 6: Обратная совместимость с существующими напоминаниями

**User Story:** Как администратор системы, я хочу, чтобы существующие напоминания продолжали работать после обновления, чтобы не потерять запланированные уведомления.

#### Acceptance Criteria

1. WHEN THE System обновляется, THE System SHALL корректно обработать существующие напоминания с временем в неопределенной таймзоне
2. WHEN THE System находит напоминание без явной таймзоны, THE System SHALL интерпретировать его как UTC
3. WHEN THE System мигрирует существующие данные, THE System SHALL конвертировать времена напоминаний в UTC с учетом таймзоны создателя события
4. WHEN миграция завершена, THE System SHALL логировать количество обработанных напоминаний и возможные проблемы

### Requirement 7: Тестирование работы с разными таймзонами

**User Story:** Как разработчик, я хочу иметь тесты для проверки работы с разными таймзонами, чтобы гарантировать корректность системы.

#### Acceptance Criteria

1. WHEN выполняются тесты, THE System SHALL проверять корректность отправки напоминаний для пользователей в разных таймзонах
2. WHEN выполняются тесты, THE System SHALL проверять корректность расчета времени напоминаний для событий в разных таймзонах
3. WHEN выполняются тесты, THE System SHALL проверять корректность конвертации времени между UTC и User_Timezone
4. WHEN выполняются тесты, THE System SHALL проверять обработку edge cases (переход через полночь, летнее/зимнее время)
5. WHEN выполняются тесты, THE System SHALL проверять отсутствие дублирования напоминаний
6. WHEN выполняются тесты, THE System SHALL проверять отсутствие пропуска напоминаний
