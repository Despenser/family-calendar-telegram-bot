# Требования: Поддержка числовых плейсхолдеров в MarkdownFormatter

## Введение

Метод `MarkdownFormatter.formatMessage()` в настоящее время поддерживает только строковые плейсхолдеры `%s`, что приводит к ошибкам при использовании числовых форматов типа `%02d`, `%d`, `%f` и других. Это ограничение вызывает сбои в работе приложения, когда требуется форматирование чисел с определёнными параметрами (ведущие нули, количество знаков после запятой и т.д.).

В текущей кодовой базе обнаружено использование `formatMessage("✅ Час выбран: %02d:00\n\nТеперь выберите минуты:", hour)` в `UpdateProcessor.handleHourSelection()`, которое вызывает ошибку `IllegalArgumentException` из-за несоответствия плейсхолдера.

Важно отметить, что в других местах кода (например, при форматировании дат) числа форматируются **заранее** с помощью `DateTimeFormatter` и передаются как готовые строки. Однако для обеспечения гибкости и удобства использования, метод `formatMessage()` должен поддерживать прямое форматирование чисел.

## Глоссарий

- **MarkdownFormatter**: Утилитный класс для форматирования текста в MarkdownV2 формате Telegram
- **Плейсхолдер**: Специальный символ в строке-шаблоне, который заменяется на значение аргумента (например, `%s`, `%d`, `%02d`)
- **MarkdownV2**: Формат разметки текста в Telegram, требующий экранирования специальных символов
- **Экранирование**: Добавление обратного слеша перед специальными символами для их корректной обработки

## Требования

### Требование 1: Поддержка числовых плейсхолдеров

**User Story:** Как разработчик, я хочу использовать числовые плейсхолдеры в методе `formatMessage()`, чтобы форматировать числа с определёнными параметрами (ведущие нули, точность и т.д.)

#### Критерии приёмки

1. WHEN метод `formatMessage()` вызывается с шаблоном содержащим `%d`, THEN система SHALL корректно подставить целочисленное значение
2. WHEN метод `formatMessage()` вызывается с шаблоном содержащим `%02d`, THEN система SHALL корректно подставить целочисленное значение с ведущим нулём
3. WHEN метод `formatMessage()` вызывается с шаблоном содержащим `%f`, THEN система SHALL корректно подставить значение с плавающей точкой
4. WHEN метод `formatMessage()` вызывается с шаблоном содержащим `%.2f`, THEN система SHALL корректно подставить значение с плавающей точкой с двумя знаками после запятой
5. WHEN метод `formatMessage()` вызывается с шаблоном содержащим смешанные плейсхолдеры (`%s`, `%d`, `%f`), THEN система SHALL корректно подставить все значения в правильном порядке

### Требование 2: Корректное экранирование результатов форматирования

**User Story:** Как разработчик, я хочу чтобы результаты числового форматирования автоматически экранировались, чтобы избежать ошибок парсинга MarkdownV2

#### Критерии приёмки

1. WHEN числовое значение форматируется и содержит специальные символы MarkdownV2 (например, точка в `3.14`), THEN система SHALL экранировать эти символы
2. WHEN шаблон содержит специальные символы MarkdownV2 вне плейсхолдеров, THEN система SHALL экранировать эти символы
3. WHEN отформатированное сообщение содержит эмодзи, THEN система SHALL NOT экранировать эмодзи

### Требование 3: Валидация соответствия плейсхолдеров и аргументов

**User Story:** Как разработчик, я хочу получать понятные сообщения об ошибках при несоответствии плейсхолдеров и аргументов, чтобы быстро находить и исправлять проблемы

#### Критерии приёмки

1. WHEN количество плейсхолдеров не совпадает с количеством аргументов, THEN система SHALL выбросить `IllegalArgumentException` с описанием проблемы
2. WHEN тип аргумента не соответствует типу плейсхолдера (например, строка для `%d`), THEN система SHALL выбросить `IllegalArgumentException` с описанием проблемы
3. WHEN плейсхолдер имеет некорректный формат, THEN система SHALL выбросить `IllegalArgumentException` с описанием проблемы

### Требование 4: Обратная совместимость

**User Story:** Как разработчик, я хочу чтобы существующий код продолжал работать после обновления, чтобы не нарушать функциональность приложения

#### Критерии приёмки

1. WHEN метод `formatMessage()` вызывается с шаблоном содержащим только `%s` плейсхолдеры, THEN система SHALL работать так же как и до изменений
2. WHEN метод `formatMessage()` вызывается без аргументов, THEN система SHALL просто экранировать шаблон
3. WHEN существующие тесты запускаются после изменений, THEN все тесты SHALL пройти успешно

### Требование 5: Производительность

**User Story:** Как пользователь системы, я хочу чтобы форматирование сообщений выполнялось быстро, чтобы не замедлять работу бота

#### Критерии приёмки

1. WHEN метод `formatMessage()` вызывается с любым количеством плейсхолдеров, THEN время выполнения SHALL быть линейным относительно длины шаблона и количества аргументов
2. WHEN метод `formatMessage()` вызывается многократно, THEN система SHALL NOT создавать избыточные временные объекты
