# Дизайн: Поддержка числовых плейсхолдеров в MarkdownFormatter

## Обзор

Расширение метода `MarkdownFormatter.formatMessage()` для поддержки всех стандартных плейсхолдеров Java (`%d`, `%02d`, `%f`, `%.2f` и т.д.) в дополнение к существующей поддержке `%s`. Решение должно обеспечить корректное экранирование специальных символов MarkdownV2 как в шаблоне, так и в отформатированных значениях, сохраняя при этом обратную совместимость с существующим кодом.

## Архитектура

Решение основано на модификации единственного метода `formatMessage()` в классе `MarkdownFormatter`. Архитектура остаётся неизменной - утилитный класс со статическими методами.

### Текущая реализация

```java
public static String formatMessage(String template, Object... args) {
    // 1. Проверка на null
    // 2. Подсчёт плейсхолдеров %s
    // 3. Валидация количества аргументов
    // 4. Экранирование аргументов
    // 5. Разбиение шаблона по %s
    // 6. Сборка результата с экранированием частей шаблона
}
```

**Проблема:** Метод ищет только `%s` плейсхолдеры и не поддерживает другие форматы.

### Новая реализация

```java
public static String formatMessage(String template, Object... args) {
    // 1. Проверка на null
    // 2. Если нет аргументов - просто экранировать шаблон
    // 3. Использовать String.format() для форматирования
    // 4. Экранировать результат, сохраняя уже экранированные части
}
```

**Ключевое изменение:** Делегирование форматирования стандартному `String.format()`, который поддерживает все типы плейсхолдеров.

## Компоненты и интерфейсы

### MarkdownFormatter (модифицируется)

**Изменяемый метод:**
```java
/**
 * Форматирует сообщение с автоматическим экранированием всех частей.
 * 
 * <p>Метод работает аналогично String.format(), но автоматически экранирует
 * все специальные символы MarkdownV2 в результате форматирования.
 * Поддерживает все стандартные плейсхолдеры Java: %s, %d, %02d, %f, %.2f и т.д.</p>
 * 
 * @param template шаблон сообщения с плейсхолдерами (например, "Час: %02d:00")
 * @param args аргументы для подстановки
 * @return полностью экранированное сообщение, готовое для отправки в Telegram
 * @throws IllegalArgumentException если template равен null, или если форматирование
 *         не удалось (несоответствие типов, некорректный формат плейсхолдера)
 */
public static String formatMessage(String template, Object... args)
```

**Новая логика:**

1. **Валидация входных данных**
   - Проверка template на null
   - Если args пустой - возврат экранированного шаблона

2. **Форматирование**
   - Использование `String.format(template, args)` для подстановки значений
   - Обработка `IllegalFormatException` с понятным сообщением об ошибке

3. **Экранирование**
   - Применение `escape()` к результату форматирования
   - Сохранение эмодзи без экранирования

4. **Обработка ошибок**
   - Перехват `IllegalFormatException` от `String.format()`
   - Преобразование в `IllegalArgumentException` с понятным сообщением

### Алгоритм экранирования

**Текущий подход (сложный):**
```
1. Разбить шаблон по %s
2. Экранировать каждую часть шаблона
3. Экранировать каждый аргумент
4. Собрать результат
```

**Новый подход (простой):**
```
1. Отформатировать сообщение через String.format()
2. Экранировать весь результат
```

**Преимущества нового подхода:**
- Проще и понятнее
- Меньше кода
- Меньше вероятность ошибок
- Поддержка всех плейсхолдеров "из коробки"

## Модели данных

Изменений в моделях данных не требуется. Метод работает с примитивными типами и строками.

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться во всех допустимых выполнениях системы - по сути, формальное утверждение о том, что система должна делать. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*


### Property 1: Форматирование целых чисел с экранированием

*For any* целое число и любой спецификатор формата целых чисел (%d, %02d, %03d и т.д.), форматирование через formatMessage() должно корректно подставить значение с правильным форматом и экранировать все специальные символы MarkdownV2 в результате.

**Validates: Requirements 1.1, 1.2**

### Property 2: Форматирование чисел с плавающей точкой с экранированием

*For any* число с плавающей точкой и любой спецификатор формата float (%f, %.2f, %.4f и т.д.), форматирование через formatMessage() должно корректно подставить значение с правильной точностью, и точка в результате должна быть экранирована (например, "3.14" -> "3\\.14").

**Validates: Requirements 1.3, 1.4, 2.1**

### Property 3: Смешанные плейсхолдеры сохраняют порядок

*For any* комбинации различных типов плейсхолдеров (%s, %d, %f) и соответствующих аргументов, форматирование через formatMessage() должно подставить все значения в правильном порядке с корректным форматированием и экранированием.

**Validates: Requirements 1.5**

### Property 4: Экранирование статического текста в шаблоне

*For any* шаблон содержащий специальные символы MarkdownV2 вне плейсхолдеров, форматирование через formatMessage() должно экранировать эти символы в итоговом результате.

**Validates: Requirements 2.2**

### Property 5: Сохранение эмодзи без экранирования

*For any* сообщение содержащее эмодзи (в шаблоне или аргументах), форматирование через formatMessage() должно сохранить эмодзи без изменений (не экранировать их).

**Validates: Requirements 2.3**

### Property 6: Корректная обработка ошибок форматирования

*For any* некорректная комбинация шаблона и аргументов (несоответствие количества, несоответствие типов, некорректный формат плейсхолдера), formatMessage() должен выбросить IllegalArgumentException с понятным описанием проблемы.

**Validates: Requirements 3.1, 3.2, 3.3**

## Обработка ошибок

### Типы ошибок

1. **IllegalArgumentException** - выбрасывается в следующих случаях:
   - template равен null
   - Ошибка форматирования от String.format() (несоответствие типов, количества аргументов, некорректный формат)

### Стратегия обработки

```java
public static String formatMessage(String template, Object... args) {
    if (template == null) {
        throw new IllegalArgumentException("Шаблон сообщения не может быть null");
    }
    
    if (args == null || args.length == 0) {
        return escape(template);
    }
    
    try {
        // Форматирование через String.format()
        String formatted = String.format(template, args);
        // Экранирование результата
        return escape(formatted);
    } catch (IllegalFormatException e) {
        // Преобразование в понятное сообщение
        throw new IllegalArgumentException(
            String.format("Ошибка форматирования сообщения. Шаблон: '%s', " +
                         "количество аргументов: %d. Причина: %s",
                         template, args.length, e.getMessage()),
            e
        );
    }
}
```

### Сообщения об ошибках

Все сообщения об ошибках должны быть на русском языке и содержать:
- Описание проблемы
- Шаблон, вызвавший ошибку
- Количество переданных аргументов
- Оригинальное сообщение от String.format()

## Стратегия тестирования

### Двойной подход к тестированию

**Unit-тесты** - проверка конкретных примеров и граничных случаев:
- Конкретные примеры форматирования (%d, %02d, %f, %.2f)
- Граничные случаи (пустой шаблон, без аргументов, null)
- Обратная совместимость (существующие тесты с %s)
- Обработка ошибок (конкретные примеры некорректных вызовов)

**Property-тесты** - проверка универсальных свойств на множестве входных данных:
- Минимум 100 итераций на каждое свойство
- Генерация случайных чисел, строк, комбинаций
- Проверка корректности экранирования на разных входных данных
- Проверка обработки ошибок на случайных некорректных комбинациях

### Библиотека для Property-Based Testing

Для Java используем **jqwik** - современная библиотека для property-based тестирования:

```xml
<dependency>
    <groupId>net.jqwik</groupId>
    <artifactId>jqwik</artifactId>
    <version>1.8.2</version>
    <scope>test</scope>
</dependency>
```

### Конфигурация тестов

Каждый property-тест должен:
- Запускаться минимум 100 раз (`@Property(tries = 100)`)
- Иметь комментарий с ссылкой на свойство из дизайна:
  ```java
  // Feature: markdown-formatter-numeric-placeholders, Property 1: Форматирование целых чисел с экранированием
  @Property(tries = 100)
  void integerFormattingWithEscaping(...) { ... }
  ```

### Генераторы для тестов

**Для целых чисел:**
```java
@Provide
Arbitrary<Integer> integers() {
    return Arbitraries.integers().between(-1000, 1000);
}
```

**Для чисел с плавающей точкой:**
```java
@Provide
Arbitrary<Double> doubles() {
    return Arbitraries.doubles()
        .between(-1000.0, 1000.0)
        .ofScale(2); // до 2 знаков после запятой
}
```

**Для строк со специальными символами:**
```java
@Provide
Arbitrary<String> stringsWithSpecialChars() {
    return Arbitraries.strings()
        .withCharRange('a', 'z')
        .withChars('_', '*', '[', ']', '(', ')', '!', '.')
        .ofMinLength(1)
        .ofMaxLength(50);
}
```

**Для эмодзи:**
```java
@Provide
Arbitrary<String> emoji() {
    return Arbitraries.of("👋", "✅", "❌", "🔔", "📅", "🕐", "📝");
}
```

### Примеры тестов

**Unit-тест для обратной совместимости:**
```java
@Test
void formatMessage_withStringPlaceholder_worksAsBeforeChanges() {
    // Given
    String template = "Дата: %s";
    String date = "12.01.2026";
    
    // When
    String result = MarkdownFormatter.formatMessage(template, date);
    
    // Then
    assertEquals("Дата: 12\\.01\\.2026", result);
}
```

**Property-тест для целых чисел:**
```java
// Feature: markdown-formatter-numeric-placeholders, Property 1: Форматирование целых чисел с экранированием
@Property(tries = 100)
void integerFormatting_escapesSpecialChars(@ForAll("integers") int value) {
    // Given
    String template = "Значение: %d";
    
    // When
    String result = MarkdownFormatter.formatMessage(template, value);
    
    // Then
    String expected = "Значение: " + MarkdownFormatter.escape(String.valueOf(value));
    assertEquals(expected, result);
}
```

**Property-тест для чисел с плавающей точкой:**
```java
// Feature: markdown-formatter-numeric-placeholders, Property 2: Форматирование чисел с плавающей точкой с экранированием
@Property(tries = 100)
void floatFormatting_escapesDot(@ForAll("doubles") double value) {
    // Given
    String template = "Цена: %.2f";
    
    // When
    String result = MarkdownFormatter.formatMessage(template, value);
    
    // Then
    assertTrue(result.contains("\\."), "Точка должна быть экранирована");
    String formatted = String.format("%.2f", value);
    String expected = "Цена: " + MarkdownFormatter.escape(formatted);
    assertEquals(expected, result);
}
```
