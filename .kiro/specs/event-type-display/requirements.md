# Документ требований: Отображение типа события

## Введение

Данная функция добавляет визуальное отображение типа события (семейное или персональное) в сообщениях о событиях в Telegram-боте семейного календаря. Это улучшит понимание пользователями видимости и назначения каждого события.

## Глоссарий

- **System** (Система): Telegram-бот семейного календаря
- **Event** (Событие): Запись в календаре с датой, временем и описанием
- **Personal_Event** (Персональное событие): Событие с флагом isPersonal=true, видимое только создателю
- **Family_Event** (Семейное событие): Событие с флагом isPersonal=false, видимое всем членам семьи
- **Event_Message** (Сообщение о событии): Форматированное текстовое сообщение в Telegram с информацией о событии
- **BotMessageBuilder**: Компонент системы, отвечающий за формирование текстовых сообщений
- **MarkdownV2**: Формат разметки текста в Telegram API

## Требования

### Требование 1: Отображение типа события в сообщении

**User Story:** Как пользователь бота, я хочу видеть тип события в сообщении о событии, чтобы понимать, является ли событие семейным или персональным.

#### Критерии приемки

1. WHEN THE System формирует сообщение о событии, THE System SHALL включать строку с типом события
2. WHEN событие является семейным (isPersonal=false), THEN THE System SHALL отображать "👨‍👩‍👧‍👦 Тип: Семейное"
3. WHEN событие является персональным (isPersonal=true), THEN THE System SHALL отображать "👤 Тип: Персональное"
4. THE System SHALL размещать строку с типом события после строки с временем и перед строкой с описанием
5. THE System SHALL применять MarkdownV2 форматирование к строке с типом события

### Требование 2: Корректное экранирование текста

**User Story:** Как разработчик системы, я хочу, чтобы все текстовые данные корректно экранировались, чтобы избежать ошибок форматирования в Telegram.

#### Критерии приемки

1. WHEN THE System формирует строку с типом события, THE System SHALL экранировать специальные символы согласно правилам MarkdownV2
2. THE System SHALL использовать метод MarkdownFormatter.escape() для экранирования текста типа события
3. WHEN в тексте типа события присутствуют специальные символы MarkdownV2, THEN THE System SHALL корректно их обработать

### Требование 3: Обратная совместимость формата сообщения

**User Story:** Как пользователь бота, я хочу, чтобы остальная информация о событии отображалась как прежде, чтобы не терять привычный формат.

#### Критерии приемки

1. WHEN THE System добавляет строку с типом события, THE System SHALL сохранять все существующие строки сообщения
2. THE System SHALL сохранять порядок строк: название, дата, время, тип, описание
3. WHEN событие не имеет описания, THEN THE System SHALL отображать тип события как последнюю строку
4. THE System SHALL использовать те же эмодзи и форматирование для существующих строк

### Требование 4: Обработка граничных случаев

**User Story:** Как разработчик системы, я хочу, чтобы система корректно обрабатывала все возможные состояния поля isPersonal, чтобы избежать ошибок во время выполнения.

#### Критерии приемки

1. WHEN поле isPersonal имеет значение null, THEN THE System SHALL обрабатывать событие как семейное (по умолчанию)
2. WHEN поле isPersonal имеет значение true, THEN THE System SHALL отображать персональный тип
3. WHEN поле isPersonal имеет значение false, THEN THE System SHALL отображать семейный тип
4. THE System SHALL не выбрасывать исключения при любом значении поля isPersonal

### Требование 5: Тестовое покрытие

**User Story:** Как разработчик системы, я хочу иметь полное тестовое покрытие новой функциональности, чтобы гарантировать её корректную работу.

#### Критерии приемки

1. THE System SHALL иметь unit-тесты для метода buildEventMessage с семейными событиями
2. THE System SHALL иметь unit-тесты для метода buildEventMessage с персональными событиями
3. THE System SHALL иметь unit-тесты для обработки null значения поля isPersonal
4. THE System SHALL иметь тесты для проверки корректного экранирования текста типа события
5. THE System SHALL иметь тесты для проверки правильного порядка строк в сообщении
