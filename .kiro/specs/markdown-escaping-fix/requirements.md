# Requirements Document

## Introduction

Telegram Bot API использует формат MarkdownV2 для форматирования сообщений. В MarkdownV2 существует набор специальных символов, которые должны быть экранированы обратным слешем (`\`). В текущей реализации бота обнаружена проблема: при формировании сообщений с динамическим содержимым экранируются только переменные части, но не статический текст, что приводит к ошибкам парсинга MarkdownV2.

Ошибка проявляется в логах:
```
Bad Request (400): Ошибка парсинга MarkdownV2. 
telegramId=526536667, textPreview=✅ Дата выбрана: 12.01.2026
Теперь выберите час:, response=Bad Request: can't parse entities: 
Character '.' is reserved and must be escaped with the preceding '\'
```

## Glossary

- **MarkdownV2**: Формат разметки текста, используемый Telegram Bot API для форматирования сообщений (жирный текст, курсив, моноширинный шрифт и т.д.)
- **Специальные символы MarkdownV2**: Символы, имеющие особое значение в MarkdownV2 и требующие экранирования: `_`, `*`, `[`, `]`, `(`, `)`, `~`, `` ` ``, `>`, `#`, `+`, `-`, `=`, `|`, `{`, `}`, `.`, `!`
- **Экранирование**: Добавление обратного слеша (`\`) перед специальным символом для его отображения как обычного текста
- **TelegramMessageService**: Сервис для отправки сообщений через Telegram Bot API
- **MarkdownFormatter**: Утилитный класс для экранирования специальных символов MarkdownV2
- **UpdateProcessor**: Сервис для обработки обновлений от Telegram (сообщения, callback queries)

## Requirements

### Requirement 1

**User Story:** Как разработчик бота, я хочу, чтобы все сообщения корректно экранировались перед отправкой в Telegram, чтобы пользователи не получали ошибки парсинга MarkdownV2.

#### Acceptance Criteria

1. WHEN система формирует сообщение с динамическим содержимым THEN система SHALL экранировать все специальные символы MarkdownV2 во всем тексте сообщения
2. WHEN система отправляет сообщение через TelegramMessageService THEN система SHALL гарантировать, что текст полностью экранирован
3. WHEN пользователь выбирает дату в календаре THEN система SHALL отправить сообщение без ошибок парсинга MarkdownV2
4. WHEN система формирует сообщение со статическим текстом, содержащим специальные символы THEN система SHALL экранировать эти символы
5. WHEN система использует String.format для формирования сообщений THEN система SHALL применять экранирование ко всему результату, а не только к переменным частям

### Requirement 2

**User Story:** Как разработчик бота, я хочу иметь удобные методы для безопасного форматирования сообщений, чтобы избежать ошибок экранирования в будущем.

#### Acceptance Criteria

1. WHEN разработчик формирует сообщение с переменными THEN система SHALL предоставлять метод для безопасного форматирования с автоматическим экранированием
2. WHEN разработчик использует метод безопасного форматирования THEN система SHALL экранировать как статический текст, так и переменные части
3. WHEN разработчик передает уже экранированные части в метод форматирования THEN система SHALL не применять двойное экранирование
4. WHEN разработчик формирует сложное сообщение с несколькими переменными THEN система SHALL корректно экранировать все части сообщения

### Requirement 3

**User Story:** Как пользователь бота, я хочу получать корректно отформатированные сообщения при выборе даты, чтобы не видеть ошибки.

#### Acceptance Criteria

1. WHEN пользователь выбирает дату в inline-календаре THEN система SHALL отправить сообщение "✅ Дата выбрана: DD.MM.YYYY\n\nТеперь выберите час:" без ошибок парсинга
2. WHEN пользователь выбирает час THEN система SHALL отправить сообщение без ошибок парсинга
3. WHEN пользователь выбирает минуты THEN система SHALL отправить сообщение без ошибок парсинга
4. WHEN система отображает дату в любом формате THEN система SHALL корректно экранировать точки в дате

### Requirement 4

**User Story:** Как разработчик бота, я хочу иметь тесты для проверки корректности экранирования, чтобы предотвратить регрессии в будущем.

#### Acceptance Criteria

1. WHEN выполняются тесты MarkdownFormatter THEN система SHALL проверять экранирование всех специальных символов MarkdownV2
2. WHEN выполняются тесты форматирования сообщений THEN система SHALL проверять корректность экранирования в реальных сценариях использования
3. WHEN добавляется новый метод форматирования сообщений THEN разработчик SHALL добавить тесты для проверки экранирования
4. WHEN тесты проверяют экранирование дат THEN система SHALL тестировать различные форматы дат с точками
