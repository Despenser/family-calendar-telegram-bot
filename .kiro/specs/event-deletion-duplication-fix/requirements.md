# Требования: Исправление дублирования событий и лишних уведомлений при удалении

## Введение

При удалении первого события из списка "Мои события" второе событие дублируется (отображается дважды - один раз с шапкой, один раз без), и отправляется лишнее уведомление об удалении. Необходимо исправить эти проблемы для обеспечения корректного отображения событий и улучшения пользовательского опыта.

## Глоссарий

- **Система** - Telegram-бот семейного календаря
- **Пользователь** - авторизованный пользователь бота
- **Событие** - запись в календаре с датой, временем и описанием
- **Сообщение события** - сообщение в чате Telegram, отображающее информацию о событии
- **Шапка "Мои события"** - заголовок списка событий с количеством активных событий
- **Флаг isMyEventsHeader** - флаг, указывающий, что событие является первым в списке и должно отображаться с шапкой
- **messageId** - идентификатор сообщения в Telegram

## Требования

### Требование 1

**User Story:** Как пользователь, я хочу, чтобы при удалении первого события второе событие не дублировалось, чтобы в чате отображался чистый и понятный список событий.

#### Критерии приемки

1. WHEN пользователь удаляет первое событие из списка "Мои события" THEN Система SHALL удалить старое сообщение второго события перед его обновлением с шапкой
2. WHEN второе событие становится первым THEN Система SHALL отобразить его только один раз с шапкой "Мои события"
3. WHEN старое сообщение второго события удаляется THEN Система SHALL логировать операцию на уровне DEBUG
4. IF удаление старого сообщения завершается ошибкой THEN Система SHALL логировать ошибку на уровне WARN и продолжить обновление события

### Требование 2

**User Story:** Как пользователь, я не хочу получать лишние уведомления об удалении события, чтобы интерфейс был чище и понятнее.

#### Критерии приемки

1. WHEN пользователь удаляет событие через кнопку "Удалить" THEN Система SHALL удалить сообщение события без отправки дополнительного уведомления
2. WHEN событие успешно удалено THEN Система SHALL ответить на callback query с текстом "Событие удалено"
3. WHEN событие успешно удалено THEN Система SHALL НЕ отправлять отдельное сообщение с текстом "Событие удалено"
4. IF удаление события завершается ошибкой THEN Система SHALL отправить сообщение об ошибке пользователю

### Требование 3

**User Story:** Как разработчик, я хочу, чтобы логика удаления старого сообщения при передаче флага isMyEventsHeader была централизована, чтобы обеспечить консистентность поведения.

#### Критерии приемки

1. WHEN следующее событие получает флаг isMyEventsHeader THEN Система SHALL удалить его старое сообщение перед вызовом sendOrUpdateEventMessage
2. WHEN старое сообщение удаляется THEN Система SHALL сбросить messageId события в null
3. WHEN sendOrUpdateEventMessage вызывается с messageId равным null THEN Система SHALL отправить новое сообщение вместо обновления существующего
4. WHEN операция удаления старого сообщения выполняется THEN Система SHALL обрабатывать все исключения gracefully

### Требование 4

**User Story:** Как пользователь, я хочу, чтобы при удалении события интерфейс обновлялся корректно, чтобы я мог продолжать работу с календарем без путаницы.

#### Критерии приемки

1. WHEN пользователь удаляет событие THEN Система SHALL удалить сообщение события из чата
2. WHEN пользователь удаляет событие THEN Система SHALL ответить на callback query с подтверждением
3. WHEN пользователь удаляет событие THEN Система SHALL НЕ отправлять дополнительные сообщения в чат
4. WHEN удаление завершается успешно THEN Система SHALL обновить список событий корректно без дублирования
