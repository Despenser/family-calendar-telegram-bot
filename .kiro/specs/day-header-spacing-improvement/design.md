# Design Document

## Overview

Данный дизайн описывает простое улучшение форматирования списков событий в командах `/week` и `/upcoming_events`. Изменение заключается в добавлении дополнительной пустой строки после заголовка дня для улучшения визуального восприятия и читаемости списков событий.

## Architecture

Изменение затрагивает только один метод в утилитном классе `EventFormatter`:
- `formatDayHeader(LocalDate date, LocalDate today)` - метод форматирования заголовка дня

Архитектура остается неизменной. Изменение локализовано в одном месте, что обеспечивает единообразное применение нового форматирования во всех командах, использующих `EventFormatter`.

## Components and Interfaces

### EventFormatter

**Местоположение:** `src/main/java/ru/golubyatnikov/family/calendar/bot/util/EventFormatter.java`

**Изменяемый метод:**
```java
public static String formatDayHeader(LocalDate date, LocalDate today)
```

**Текущее поведение:**
- Метод возвращает заголовок дня с одним символом новой строки в конце (`\n`)
- Формат: `[иконка] [дата] ([описание])\n`

**Новое поведение:**
- Метод будет возвращать заголовок дня с двумя символами новой строки в конце (`\n\n`)
- Формат: `[иконка] [дата] ([описание])\n\n`
- Это создаст визуальный отступ между заголовком и первым событием

**Примеры:**

Текущий формат:
```
📍 26.01 (сегодня - понедельник)
👨‍👩‍👧‍👦 тестовое событие
```

Новый формат:
```
📍 26.01 (сегодня - понедельник)

👨‍👩‍👧‍👦 тестовое событие
```

### Затрагиваемые команды

Следующие команды используют `EventFormatter.formatDayHeader()` и автоматически получат улучшенное форматирование:

1. **WeekCommandHandler** (`/week`)
   - Отображает события на 7 дней
   - Группирует события по дням
   - Использует `formatDayHeader()` для каждого дня с событиями

2. **UpcomingEventsCommandHandler** (`/upcoming_events`)
   - Отображает события на 30 дней
   - Группирует события по дням
   - Использует `formatDayHeader()` для каждого дня с событиями

## Data Models

Изменения в моделях данных не требуются. Модификация касается только форматирования вывода.

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system-essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Заголовок дня содержит двойной перенос строки

*For any* дата и текущая дата, результат вызова `formatDayHeader(date, today)` должен заканчиваться на `\n\n` (два символа новой строки).

**Validates: Requirements 1.3**

### Property 2: Визуальный отступ присутствует во всех форматах заголовков

*For any* тип заголовка дня (сегодня, завтра, другой день), отформатированный заголовок должен содержать ровно два символа новой строки в конце.

**Validates: Requirements 1.3, 1.4**

### Property 3: Длина заголовка увеличивается на один символ

*For any* дата, длина нового отформатированного заголовка должна быть на 1 символ больше, чем длина старого заголовка (добавляется один дополнительный `\n`).

**Validates: Requirements 1.3**

## Error Handling

Изменение не вводит новых сценариев ошибок. Существующая обработка ошибок в `EventFormatter.formatDayHeader()` остается без изменений:
- Проверка на `null` для параметров `date` и `today`
- Выброс `IllegalArgumentException` при некорректных входных данных

## Testing Strategy

### Unit Tests

Необходимо обновить существующие unit-тесты для метода `formatDayHeader()`:

1. **Тест для формата "сегодня"**
   - Проверить, что заголовок для сегодняшней даты заканчивается на `\n\n`
   - Проверить, что между заголовком и следующим контентом есть пустая строка

2. **Тест для формата "завтра"**
   - Проверить, что заголовок для завтрашней даты заканчивается на `\n\n`
   - Проверить визуальный отступ

3. **Тест для формата "другой день"**
   - Проверить, что заголовок для других дат заканчивается на `\n\n`
   - Проверить визуальный отступ

### Property-Based Tests

Написать property-based тесты для проверки универсальных свойств:

1. **Property Test 1: Двойной перенос строки**
   - Генерировать случайные даты
   - Проверять, что все заголовки заканчиваются на `\n\n`
   - Минимум 100 итераций

2. **Property Test 2: Единообразие форматирования**
   - Генерировать случайные даты (сегодня, завтра, будущие)
   - Проверять, что все типы заголовков имеют одинаковое количество переносов строк в конце
   - Минимум 100 итераций

### Integration Tests

Интеграционные тесты не требуются, так как изменение локализовано в одном утилитном методе. Существующие интеграционные тесты для команд `/week` и `/upcoming_events` автоматически проверят новое форматирование.

### Manual Testing

Рекомендуется выполнить ручное тестирование:
1. Запустить команду `/week` и проверить визуальный отступ
2. Запустить команду `/upcoming_events` и проверить визуальный отступ
3. Проверить, что разделители между днями отображаются корректно
