# Implementation Plan: Day Header Spacing Improvement

## Overview

Данный план описывает простую модификацию метода `formatDayHeader()` в классе `EventFormatter` для добавления визуального отступа между заголовком дня и первым событием в списке. Изменение затрагивает только одну строку кода.

## Tasks

- [x] 1. Обновить метод formatDayHeader для добавления дополнительного переноса строки
  - Изменить возвращаемое значение метода `formatDayHeader()` в классе `EventFormatter`
  - Заменить `.append(escape("\n"))` на `.append(escape("\n\n"))` в конце каждого варианта форматирования (сегодня, завтра, другой день)
  - Обновить JavaDoc комментарии для отражения нового формата
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_

- [ ]* 1.1 Написать property-тест для проверки двойного переноса строки
  - **Property 1: Заголовок дня содержит двойной перенос строки**
  - **Validates: Requirements 1.3**
  - Генерировать случайные даты
  - Проверять, что результат `formatDayHeader()` заканчивается на `\n\n`
  - Минимум 100 итераций

- [ ]* 1.2 Написать property-тест для единообразия форматирования
  - **Property 2: Визуальный отступ присутствует во всех форматах заголовков**
  - **Validates: Requirements 1.3, 1.4**
  - Генерировать случайные даты (сегодня, завтра, будущие дни)
  - Проверять, что все типы заголовков заканчиваются на `\n\n`
  - Минимум 100 итераций

- [ ]* 1.3 Обновить существующие unit-тесты для EventFormatter
  - Обновить тесты для метода `formatDayHeader()` с учетом нового формата
  - Проверить, что заголовки для всех типов дней (сегодня, завтра, другой день) заканчиваются на `\n\n`
  - _Requirements: 1.3, 1.4_

- [x] 2. Checkpoint - Убедиться, что все тесты проходят
  - Запустить все тесты проекта
  - Убедиться, что изменение не сломало существующую функциональность
  - Спросить пользователя, если возникнут вопросы

## Notes

- Задачи, отмеченные `*`, являются опциональными и могут быть пропущены для более быстрого MVP
- Каждая задача ссылается на конкретные требования для отслеживаемости
