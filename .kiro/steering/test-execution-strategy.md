# Стратегия выполнения тестов

**ВАЖНО: Запускай тесты только на checkpoint задачах, а не после каждой правки кода.**

## Правила выполнения тестов

### Когда НЕ запускать тесты:
- После каждой правки кода в обычных задачах
- После добавления новых методов или классов
- После рефакторинга кода
- После исправления багов в обычных задачах
- В процессе реализации функциональности

### Когда ОБЯЗАТЕЛЬНО запускать тесты:
- На checkpoint задачах (задачи с текстом "Checkpoint" или "Ensure all tests pass")
- Когда пользователь явно просит запустить тесты
- После завершения всех задач в спеке
- Перед финальным коммитом изменений

## Обоснование

В проекте более 1000 тестов, и их выполнение занимает значительное время. Запуск тестов после каждой правки кода существенно замедляет разработку. Checkpoint задачи специально созданы для проверки корректности реализации на определенных этапах.

## Исключения

- Если задача явно требует написания и проверки тестов (например, "Write property test for X"), можно запустить только конкретный тест, а не весь набор
- Если пользователь явно указывает "запусти тесты" или "проверь тесты"
- При работе с критическими компонентами, где пользователь просит дополнительную проверку

## Примеры

### ❌ НЕ делай так:
```
Задача: Добавить новый метод в EventService
1. Добавляю метод
2. Запускаю все тесты (1000+ тестов, 5+ минут)
3. Перехожу к следующей задаче
```

### ✅ Делай так:
```
Задача: Добавить новый метод в EventService
1. Добавляю метод
2. Сообщаю пользователю о завершении задачи
3. Жду следующей задачи или checkpoint

Задача: Checkpoint - Ensure all tests pass
1. Запускаю все тесты
2. Исправляю найденные проблемы
3. Подтверждаю успешное прохождение
```

## Важно

- Это правило не отменяет необходимость писать качественный код
- Код должен быть корректным и следовать best practices
- Тесты всё равно будут запущены на checkpoint задачах
- Это оптимизация процесса разработки, а не снижение качества
