# Правила разработки Java Spring Boot

**ВАЖНО: Вся разработка на Java Spring Boot должна соответствовать best practices уровня senior специалиста.**

## Архитектура и структура

- Используй чистую многослойную архитектуру (Controller → Service → Repository)
- Применяй принципы SOLID и паттерны проектирования где это уместно
- Разделяй ответственность между слоями приложения
- Используй DTO для передачи данных между слоями
- Применяй MapStruct или аналоги для маппинга между entity и DTO

## Обработка ошибок и валидация

- Используй глобальный обработчик исключений (@ControllerAdvice)
- Применяй Bean Validation (JSR-303) для валидации входных данных
- Создавай кастомные исключения для бизнес-логики
- Возвращай понятные и структурированные ответы об ошибках

## Работа с базой данных

- Используй Flyway или Liquibase для миграций БД
- Оптимизируй запросы, избегай N+1 проблемы
- Применяй правильные стратегии fetch (LAZY/EAGER)
- Используй транзакции (@Transactional) корректно
- Применяй индексы для оптимизации производительности

## Безопасность

- Используй Spring Security для аутентификации и авторизации
- Применяй принцип наименьших привилегий
- Валидируй все входные данные
- Используй параметризованные запросы для защиты от SQL-инъекций
- Храни секреты в переменных окружения, не в коде

## Тестирование

- Пиши unit-тесты для бизнес-логики
- Используй integration тесты для проверки взаимодействия компонентов
- Применяй Testcontainers для тестирования с реальной БД
- Стремись к высокому покрытию кода тестами
- Используй MockMvc для тестирования контроллеров

## Конфигурация и свойства

- Используй профили Spring для разных окружений (dev, prod, test)
- Выноси конфигурацию в application.yml/properties
- Используй @ConfigurationProperties для типизированной конфигурации
- Документируй все конфигурационные параметры

## Логирование и мониторинг

- Используй SLF4J с Logback для логирования
- Применяй правильные уровни логирования (ERROR, WARN, INFO, DEBUG)
- Логируй важные бизнес-события и ошибки
- Используй структурированное логирование где возможно
- Добавляй метрики и health checks (Spring Actuator)

## REST API

- Следуй RESTful принципам проектирования API
- Используй правильные HTTP методы и статус-коды
- Версионируй API при необходимости
- Документируй API с помощью OpenAPI/Swagger
- Применяй пагинацию для списков данных

## Производительность

- Используй кэширование (@Cacheable) для часто запрашиваемых данных
- Применяй асинхронную обработку (@Async) где уместно
- Оптимизируй работу с БД (batch операции, правильные индексы)
- Используй connection pooling (HikariCP)
- Мониторь производительность приложения

## Качество кода

- Следуй Java Code Conventions
- Используй Lombok для уменьшения boilerplate кода
- Пиши понятные и информативные комментарии на русском языке
- Применяй статический анализ кода (SonarQube, Checkstyle)
- Код должен быть читаемым и поддерживаемым
