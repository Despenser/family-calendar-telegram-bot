### Added

#### Умное редактирование сообщений с вложениями

Реализован механизм редактирования существующих сообщений при работе с вложениями событий вместо создания новых сообщений. Это значительно улучшает пользовательский опыт, сохраняя чат чистым и организованным.

**Основные возможности:**

- **Редактирование вместо создания новых сообщений**: При всех операциях с вложениями (просмотр списка, добавление файла, удаление файла) бот обновляет существующее сообщение вместо отправки нового.

- **Сохранение контекста между операциями**: Система запоминает messageId сообщения с вложениями и использует его для последующих операций редактирования.

- **Автоматический fallback механизм**: Если редактирование невозможно (сообщение удалено пользователем или старше 48 часов), система автоматически переключается на отправку нового сообщения и сохраняет новый messageId.

- **Проверка истечения контекста**: Контекст сообщения автоматически считается истекшим через 47 часов (с запасом в 1 час до лимита Telegram API в 48 часов).

**Технические детали:**

- Добавлена таблица `conversation_states` для хранения контекста сообщений с вложениями
- Реализован класс `AttachmentMessageContext` для управления контекстом
- Расширен `ConversationStateService` методами:
  - `saveAttachmentMessageId()` - сохранение контекста
  - `getAttachmentMessageContext()` - получение контекста с проверкой истечения
  - `clearAttachmentMessageContext()` - очистка контекста
- Добавлен метод `editOrSendMessage()` в `AttachmentCallbackHandler` и `UpdateProcessor` для реализации fallback механизма
- Все операции с вложениями теперь используют редактирование сообщений:
  - Отображение списка вложений
  - Добавление файла
  - Удаление файла (с запросом подтверждения)
  - Отмена удаления
  - Возврат к карточке события

**Миграция базы данных:**

- `V16__Add_conversation_states_table.sql` - создание таблицы для хранения состояний диалогов с полями для контекста вложений

**Требования:**

- Требования 1.1-1.3: Сохранение и использование messageId
- Требования 2.1-2.3: Редактирование при добавлении вложения
- Требования 3.1-3.3: Редактирование при удалении вложения
- Требования 4.1-4.3: Редактирование при запросе подтверждения
- Требования 5.1-5.4: Обработка ошибок редактирования
- Требования 6.1-6.4: Управление состоянием диалога
- Требования 7.1-7.3: Редактирование при просмотре списка
- Требования 8.1-8.4: Обновление клавиатуры с учетом прав доступа
- Требования 9.1-9.3: Сохранение контекста при добавлении файла
- Требования 10.1-10.5: Логирование операций редактирования

**Примеры использования:**

```
Пользователь открывает список вложений:
1. Бот редактирует сообщение события, показывая список вложений
2. Сохраняет messageId в ConversationState

Пользователь добавляет файл:
1. Бот сохраняет messageId перед установкой состояния ожидания файла
2. После получения файла редактирует сохраненное сообщение с обновленным списком
3. При ошибке редактирования отправляет новое сообщение и сохраняет новый messageId

Пользователь удаляет файл:
1. Бот редактирует сообщение, показывая запрос подтверждения
2. После подтверждения редактирует сообщение с обновленным списком
3. При отмене редактирует сообщение обратно к списку вложений
```

**Логирование:**

Все операции редактирования подробно логируются:
- DEBUG: попытки редактирования, получение контекста
- INFO: успешное редактирование, fallback на новое сообщение
- WARN: истечение контекста, ошибки редактирования
- ERROR: критические ошибки при работе с контекстом

**Обратная совместимость:**

Изменения полностью обратно совместимы. Если messageId не сохранен или контекст истек, система автоматически работает в fallback режиме (отправка новых сообщений), как это было реализовано ранее.

**Breaking Changes:**

Нет breaking changes. Все существующие функции продолжают работать без изменений.
