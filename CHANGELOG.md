# Changelog

Все значимые изменения в проекте Family Calendar Bot будут документированы в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
и этот проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased]

### Fixed
- **Исправлены ошибки парсинга MarkdownV2 в Docker**
  - Заменено использование `String.format()` на `formatMessage()` в `MyEventsCommandHandler`
  - Исправлено экранирование текста "Удаленные события хранятся 30 дней" в `TrashCommandHandler`
  - Все специальные символы (точки, восклицательные знаки) теперь корректно экранируются
  - Устранены ошибки "Character '.' is reserved and must be escaped" в логах Docker
  - Обновлена документация `MARKDOWN_FORMATTING.md` с примерами реальных исправлений
  - Добавлены предупреждения о недопустимости использования `String.format()` для MarkdownV2

### Changed
- **Команда /help**: Исключена команда `/start` из списка доступных команд для всех пользователей (авторизованных и неавторизованных)

- **Разграничение функциональности команд /week и /upcoming_events**
  - **Команда /week**: Остается на периоде 7 дней для быстрого обзора ближайших планов семьи
    - Показывает события на текущую неделю (7 дней)
    - Использует компактный формат с группировкой по дням недели
    - Идеально подходит для быстрого просмотра ближайших планов
    - Обновлено описание: "Показать события на неделю (7 дней)"
  - **Команда /upcoming_events**: Расширена до 30 дней для долгосрочного планирования
    - Показывает все предстоящие события на ближайшие 30 дней (ранее было 7 дней)
    - Использует детальный формат с полной информацией о каждом событии
    - Включает дату, время, описание и создателя события
    - События отсортированы в хронологическом порядке
    - Обновлено описание: "Показать все предстоящие события (30 дней)"
  - **Разница между командами**:
    - `/week` - для быстрого обзора текущей недели (7 дней, компактный формат)
    - `/upcoming_events` - для детального планирования на месяц вперед (30 дней, полная информация)
  - Обе команды корректно фильтруют персональные события, показывая только доступную пользователю информацию

### Added
- **Информативные сообщения для неавторизованных пользователей**
  - Добавлен `AuthorizationService` для централизованной проверки авторизации
  - Добавлен `UnauthorizedMessageService` для формирования категоризированных сообщений
  - Добавлен enum `MessageCategory` для классификации типов команд
  - Добавлен `MessageToneValidator` для валидации дружелюбности сообщений
  - Добавлен `AuthorizationMetricsService` для сбора метрик попыток доступа
  - Реализована система конфигурируемых сообщений через `application.yml`
  - Добавлена поддержка различных категорий сообщений:
    - Создание событий (`event-creation`)
    - Просмотр событий (`event-viewing`)
    - Управление событиями (`event-management`)
    - Поиск и фильтрация (`search-filter`)
    - Управление корзиной (`trash-management`)
    - Статистика (`statistics`)
    - Общие сообщения (`general`)

- **Логирование попыток доступа**
  - Структурированное логирование всех попыток доступа неавторизованных пользователей
  - Логи включают: telegram_id, username, команду и timestamp
  - Уровень логирования: INFO для удобного мониторинга

- **Обновленная команда /help**
  - Отображение пометок 🔒 для команд, требующих авторизации
  - Информация о процессе регистрации для неавторизованных пользователей
  - Адаптивное отображение в зависимости от статуса авторизации

- **Метрики и мониторинг**
  - Счетчик попыток доступа неавторизованных пользователей
  - Счетчик отправленных сообщений об ограничении по категориям
  - Метрика времени обработки проверки авторизации
  - Счетчик ошибок при отправке сообщений

### Changed
- **UpdateProcessor**
  - Обновлен для использования `AuthorizationService` вместо прямой проверки
  - Добавлен метод `determineMessageCategory()` для определения категории команды
  - Улучшено логирование отклоненных команд с указанием причины

- **StartCommandHandler**
  - Обновлено приветственное сообщение с объяснением назначения бота
  - Добавлена информация о том, как получить доступ к функционалу

- **Конфигурация**
  - Добавлены параметры `bot.messages.unauthorized.*` в `application.yml`
  - Настройка префикса, текстов сообщений и инструкций по получению доступа

### Fixed
- Исправлено молчаливое игнорирование команд от неавторизованных пользователей
- Улучшен пользовательский опыт при попытке использовать команды без регистрации

### Security
- Улучшена система авторизации с информативной обратной связью
- Добавлено логирование для мониторинга подозрительной активности
- Реализована защита от раскрытия информации о структуре системы

### Documentation
- Обновлен README.md с информацией об обработке неавторизованных пользователей
- Обновлен SETUP.md с описанием конфигурации сообщений
- Добавлены JavaDoc комментарии для новых классов и методов
- Добавлены примеры сообщений и использования в документации

- Поиск и фильтрация событий
- Статистика использования
